## A. 이 세션에서 새로 확정한 최상위 업무 규칙 (P0)

사용자 원문 의사결정:
- **“원승인번호가 일치하면 후보가 아니라 확정연결을 해야지.”**
- **“유일하게 일치할 필요도 없어. 하나의 원승인번호에 여러 취소환불이 있을 수 있오.”**

이를 구현 계약으로 정확하게 해석한다.

1. **한 원결제(purchase) → 여러 취소/부분환불(cancellation/refund)은 정상적인 1:N 연결**이다. 모든 취소의 `original_approval_number`가 해당 원결제의 `approval_number`와 일치하고, 동일 카드사(`issuer`), 동일 카드(`card_tail`) 및 원본 정합성 조건을 충족한다면, **각 취소를 동일 원결제에 모두 확정 연결**한다. 동일한 원승인번호의 취소 건수가 2건, 3건 이상이라는 이유로 후보/충돌 취급하거나 1건만 남겨선 안 된다. 금액이 서로 다르고 가맹점 표기가 달라도 마찬가지다.
2. **“원승인번호의 유일성”과 “원결제 행의 식별 모호성”은 다르다.** 원결제의 후보가 서로 다른 유효 구매 행 여러 건으로 모호하면 임의의 하나를 골라 확정하지 않는다. 하지만 취소/환불 행이 여러 건인 것은 정상이며 **원결제 유일성을 판단할 때 세면 안 된다.** 원결제 중복·source conflict·parse 오류·다른 카드·원승인번호 공백은 기존 안전 보호를 따른다.
3. **가맹점명 일치·14일 진단 창을 확정 연결의 필수 조건으로 사용하지 않는다.** 카카오T 가승인/카카오T 일반택시/유페이 등 표기가 바뀌더라도 카드 원승인번호 근거가 있으면 정확한 1:N 관계를 확정한다. 반면 원승인번호가 없고 별칭·날짜·금액만 유사한 항목은 기존과 같이 ‘검토 후보’일 뿐이다.
4. **연결 확정 ≠ 금융 후속 행위 확정.** 1:N 관계가 증명되면 UI에 **원결제 확정 연결 / 연결 취소·환불 N건 / 원결제 금액 / 누적 취소·환불 / 순액**을 정확하게 보여준다. 이 사실만으로 미매입 가승인 해제·현금 환급 완료, 장부 자동 기장, 여행 배정, 수동 보류 해제, OTA 결제 완료를 선언하거나 수정하지 않는다. 원결제 총액보다 누적 환불이 큰 경우 등 기존 `excess`/충돌 경고를 유지한다.
5. **동일 원승인번호의 모든 취소·환불을 고려해 누적 합계·순액을 계산**한다. 화면에 ‘첫 취소만 연결됨’, ‘원승인번호는 하나의 환불에서만 사용 가능’ 같은 제약을 넣지 않는다. 환불 합계가 시간에 따라 변동되므로 스냅샷/원본 갱신 후 최신 숫자로 다시 계산한다.

**이미 있는 코드 정본:** `app/partial_refund.py::_number_links`는 `(issuer, card_tail, approval_number)`를 기준으로 원결제 1건에 대한 **복수 취소 전체**를 묶어 `refund_count`, `refunds_total_krw`, `net_krw`, `status(full/partial/excess)`를 계산한다. `refund_group`도 해당 원승인번호의 복수 취소를 열람할 수 있게 한다. **기존 엔진을 처음부터 다시 만들지 말 것.** `len(originals) == 1`은 원결제 행의 식별 조건이지 취소 수의 상한이 아니다. `webapp/card_flow.py::_render_refund_evidence` 및 `_render_refund_merchant_candidates`의 **UI가 확정 번호 연결까지 ‘후보’라고 오인 표시하지 않게** 보완하는 것이 실질적인 남은 작업이다.
