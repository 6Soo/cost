# P2 규칙 입력의 실제 병목과 축소 시제품 — 2026-11-19

## 결론

**규칙 ID 767→689 감소만으로 P2 문맥 문제가 해결되지 않는다.** 기존 `app/p2_case.py::policy_context`는 `CORE` 전체 + `process`, `trip`, `item`, `date` 전체를 매 실행에 포함하고 예약/온라인 또는 포털 증거가 있으면 `link`, 취소/환불 사건이거나 미파싱 증거가 의심되면 `refund` 전체를 더한다. 이 규칙은 금융 원본과 무관한 개발·UI·특정 공급자 전용 조항까지 매번 모델 입력에 재전송할 수 있다.

**이번 구현은 docs 정책을 줄이거나 ID를 더 삭제하지 않는다.** `app/p2_policy_pack.py`가 검증된 규칙 정본의 **원문 조항을 그대로 선택**하는 선택형 P2 정책 패킷을 작성한다. `app/p2_case.py`의 `compact_policy=False`가 현재 기본값이다. 실제 AI 워커에 새 패킷을 활성화한 것이 **아니다**.

## 읽는 데이터의 세 층

1. **항상 입력:** `DECISION_POLICY.md`의 기존 §2·§3(모든 상위 보호 포함)·§5 전체. 기존 사용자 예외·우선순위·금융 원본·수동 교정·Google 자동 무쓰기·OTA 전건 카드 매칭·M:N·숙박/항공 이용일·P2 실패 원인 구분의 상위 계약을 바꾸지 않는다.
2. **사건 공통 최소 정본 조항:** `process`/ `trip`/ `item`/ `date`에서 직접 판정에 필요한 지정된 정본 ID를 추려 전문을 보낸다. 해당 영역의 모든 `*사용자 예외*` 조항은 사건과 무관해 보여도 자동 포함한다. P2의 `process` 보호 조항은 명시적으로 선택된 경우 원문을 포함한다(기존 기본 로더는 PROC 보호 유형을 필터링했음).
3. **조건부 도메인:** 기존 `assemble`의 `is_booking_or_online`/포털 증거 판단으로 `link`, 실제/잠재 환불 증거 판단으로 `refund`를 포함하며 동일한 ID 선택/사용자 예외 원칙을 적용한다. `LINK-002`, `LINK-003`, `LINK-044`, `ITEM-080`, `DATE-023`, `DATE-109`, `PROC-010`, `RFND-018` 등 핵심 신원·금융 보호·증거 보고 규칙을 반드시 포함한다.

P2가 선택된 규칙 이외의 새로운 요건을 추정하여 생성하면 안 된다. **특수 거래나 새로운 사용 사례에 대해 최소 패킷의 충분성이 검증되지 않았으면 기존 전체 규칙 패킷으로 되돌려야 한다.** 제공한 근거의 조회 범위·조회 실패와 실제 사실 미확인을 구별해야 한다.

## 정적 입력 크기 측정 (실제 모델 호출/토큰 수 아님)

이 수치는 `policy_context`의 정본 섹션을 JSON에 넣기 전 합산한 **UTF-8 규칙 텍스트 길이**다. 결제 건·고객 자료·증빙 본문·출력 schema·도구 round는 포함하지 않는다. 일반 = CORE + process/trip/item/date, 최대 OTA+환불 = 여기에 link/refund 추가. 선택된 조항은 본문·조건·예외를 요약하지 않고 그대로 유지한다.

| 기준 | 일반 전체 → 선택형 | 절감률 | OTA+환불 전체 → 선택형 | 절감률 |
| --- | ---: | ---: | ---: | ---: |
| 현재 `main` (767 활성 ID) | 153,295 → 67,478 B | **55.98%** | 234,065 → 103,869 B | **55.62%** |
| PR #1011 압축 브랜치 (689 활성 ID) | 149,461 → 75,989 B | **49.16%** | 227,703 → 112,653 B | **50.53%** |

측정 방법: GitHub에서 두 revision의 `DECISION_POLICY.md`, 여섯 영역 규칙을 실제 읽고 기존 `policy_context`의 섹션 분리/문맥 정규화와 시제품에 지정한 ID+해당 도메인의 `사용자 예외` 전문 선택을 모사했다. 정확한 Python `assemble` 실행, JSON 봉투/원문·증거 포함한 실제 API 토큰·응답 지연·정확도 벤치마크는 **미측정**. 결과 보장이나 성능 수치로 제시하지 않는다.

## 버전·되돌림·보호 게이트

- 두 개의 알려진 ID/유형 카탈로그(현재 main 767, PR #1011의 689)를 영역별 서명으로 판별한다. **새·삭제·유형 변경 규칙이 있으면** 선택형을 거절하고 현재 전체 패킷으로 복귀한다. 규칙 본문의 변경만 있는 경우 서명은 변하지 않아 선택형 누락 가능성을 검수해야 한다.
- 선택형 파서가 원본 조항을 요약하지 않으며 `source_hash`·`revision`·`request_digest`·`policy_digest`·증거 파일·P2 모델 실행 스키마를 바꾸지 않는다. 기존 `max_bytes` 초과에서 원문·정책을 잘라내지 않는 원칙도 유지한다.
- `assemble(..., compact_policy=False)`가 기본이다. 기능의 병합·실제 운영 활성화는 **P2 선택 규칙 의미 검증, 필요한 보호 조항/예외의 누락 점검, P2 정답 기준 테스트, OTA M:N/환불/취소/이용일/P2 미매칭 상세 보고 검증** 완료 후 별도로 결정한다.
- PR #1008의 P2 미매칭 상세 보고 규칙은 본 시제품에서 바꾸지 않는다. `LINK-044` 전문을 포함하므로 나중에 그 규칙 내용이 승인·변경되면 선택형에서도 최신 전문을 읽을 수 있지만, 새로운 규칙 ID를 추가할 경우 먼저 선택 목록의 적합성을 검수해야 한다.
- 해시 서명은 **선택형을 중단시키는 보수적 버전 감지장치**이지, 임의의 동작이 안전하다는 증명은 아니다. 운영 결과의 정확성은 본문 검증과 별도 회귀가 필요하다.
