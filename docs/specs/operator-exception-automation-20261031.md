# COST 반복 업무 최소화: 4개 경량 자동화 개발명세

작성: 2026-10-31
상태: SPEC_ONLY. 코드 구현·테스트·병합·배포는 별개.
목표: 이미 구현된 카드·OTA·영수증·Google 정본 기능 위에서 **운영자가 반복적으로 확인하고 복사하는 시간**을 줄인다. 별도 워크플로 엔진·DB·에이전트·자동 회계 쓰기는 만들지 않는다.

## 최신 현황과 공통 원칙

- 기존 카드/OTA/환불 대사, M:N Google 여행+금액 대조, 영수증 OCR, Google 메인·보관 읽기, 여행 마감 표시, 참가자 후보 기능은 구현되어 있다. **중복 구현 금지**.
- 현재 Google 원본 감사의 과거 기록은 62개 여행 중 47개 비교 가능, 15개 불가(비표준 레이아웃 12, 합계·수식 범위 문제 2, 원본 누락 1). 이는 해당 시점의 증거이며 새 실행 때 재측정해야 한다.
- 카드 원천 수집·업로드는 사용자 지시로 보류. Google 정본은 읽기 전용. 수동 결정/원본 ID/중복된 실제 결제/취소·환불/여행·분기 귀속/권한 보호.
- 구현 전 **현재 main의 동일 기능 존재 여부**부터 확인하고, 기존 기능이 이미 충족하면 코드 추가 없이 테스트·수락만 기록한다. Python 유지. 새 테이블/스케줄러/외부 LLM 호출 금지.
- 상태/건수는 동일한 권한·최신성 검사를 통과한 **기존 읽기 전용 projection**에서 계산한다. 미확인과 0건, 후보와 확정, 여행 배정과 Google 반영은 혼동하지 않는다.

## AUTO-01. 운영자용 '확인할 거래' 목록 (P0)

**사용자 업무:** 카드 전체 내역, OTA, 여행별 Google 대조를 오가며 미처리 거래를 찾는다.

**구현:**
1. 기존 페이지 상단 또는 현재 여행 검토 영역에 **간결한 한 줄 요약**과 3개 기존 화면 진입 링크를 제공한다. 새로운 대시보드/중첩 카드 화면 금지.
2. 기존 데이터에서 다음을 **읽기 전용 집계**: (a) 여행 미배정/유효 분기 목적지 없음, (b) Google 미기록·부분 일치 그룹, (c) OTA 원결제·환불·충돌·증거 부족 보류.
3. 건수를 누르면 **기존 해당 목록의 필터링된 화면**으로 이동한다. 가능하면 기존 필터 파라미터 재사용. 새로운 수동 상태값 저장 금지.
4. Google 원본 불가/구형/매핑 누락이면 '확인 불가'와 원인만 표시하고 미기록 0건으로 계산하지 않는다. 동일 원천 거래가 카드/OTA 증빙으로 중복 집계되지 않게 기존 원본 키 사용.
5. 카드 자동 수집/재분류/금융 링크 변경/Google 쓰기 없음.

**수락:** 0건/여러 건/권한 없는 여행/Google 오류/동일 거래 중복 증빙/분기 기타비용/환불 보류에서 기존 화면과 정확히 동일한 집계. 모바일 1줄 요약 또는 줄바꿈, 불필요한 박스 증가 없음.

## AUTO-02. 여행별 '다음 행동' 제안 (P1)

**사용자 업무:** 해당 여행에서 무엇을 먼저 해야 하는지 직접 판단한다.

**구현:**
1. **기존 여행 상세의 접힌 검토 영역**에 현재 읽기 전용 상태로 계산한 **최대 1~3개 행동 링크**만 노출. 새로운 마감/워크플로 상태 저장 금지.
2. 판정 우선순위: (a) 원본/Google 읽기 불가 → 원본 확인 안내, (b) 실제 여행 미배정·증거 부족 → 검토 링크, (c) Google 부분/미기록 → '수기 복사할 지출 검토' 링크, (d) 이상 없음 → 행동 없음.
3. 문구는 실제 증거에 맞춰 '확인 필요', '복사 후보' 등으로 표현. Google 붙여넣기, 결제, 입금, 보험 가입, 여행 마감이 완료되었다고 자동 확정하지 않는다.
4. 기존 M:N 대조의 **건수 차이**는 후보 그룹 차이이지 개별 거래 신원 확정이 아님. 같은 여행·금액의 유효 반복 결제를 삭제/1:1 자동 할당하지 않는다.
5. 현재 기존 검토 영역에서 이미 충족한다면 중복 UI 없이 링크/문구만 보완한다.

**수락:** 정상/미기록/부분/Google 원본 오류/보관 여행/수동 배정/복수 원인에서 우선순위 일관성, 권한·원본 불변.

## AUTO-03. Google 장부 원본 양식 사전검사 (P0)

**사용자 업무:** Google 비교가 안 될 때 시트 수식/레이아웃을 수동으로 추적한다.

**구현:**
1. **기존 Google read-only parser/validator 경로**에서 여행별 구조 오류를 유형별로 산출. 별도 수집 서비스나 새로운 동기화 스케줄러 금지.
2. 검사: 여행 시트 존재 여부/메인·보관 중복·비표준 레이아웃/지출 범위·수식 합계 범위 누락/파싱 불가·권한·오래된 snapshot.
3. 사용자가 수정할 수 있도록 **시트명(권한 범위 내), 문제 셀/범위, 실제로 누락된 마지막 지출 행, 오류 유형**을 읽기 전용 안내. 단, 검증된 실제 원본 좌표가 없으면 임의 셀 주소를 만들어 내지 않는다.
4. **실제 사례 회귀:** 수식 `H47:H75`가 마지막 지출 `76행`을 누락한 경우를 정확히 탐지. Google API 오류와 원본 양식 오류를 구분.
5. 현재 '47/62' 등 과거 수치는 실시간 수치로 하드코딩하지 않는다. Google 원본 변경은 사용자가 직접 수행하며, 정상 reader refresh 후 다시 검사.
6. 개인정보·원본 지출 세부값을 로그/운영 지표에 기록하지 않는다.

**수락:** 정상 시트/비표준 레이아웃/합계 범위 누락/메인·보관 이동/원본 부재/권한 실패/오래된 캐시에서 정확한 진단; 원본 Google 쓰기 0, 오류를 정상 대조로 우회하지 않음.

## AUTO-04. 반복 수동 교정에서 규칙 후보 제안 (P2, 조건부)

**사용자 업무:** 동일 공급자/가맹점의 여행 귀속을 반복 수동 교정한다.

**구현:**
1. 우선 현재 수동 교정 기록이 **출처·시점·대상 여행·원본 키를 신뢰 가능하게 보존하는지** 읽기 전용 확인. 부족하면 기능 개발 대신 '근거 부족'으로 종료.
2. 같은 정규화 공급자/카드 식별 범위 내에서 **서로 다른 원본 거래 최소 3건**의 일관된 수동 결정을 찾으면 **후보만** 표시. 동일 거래 재수정·동일 영수증 중복 증빙은 표본으로 중복 집계하지 않는다.
3. 후보에 근거 건수·원본 출처·충돌/예외 수·적용 범위·최근 교정 시점을 제시. 서로 다른 여행에 걸친 같은 가맹점은 자동 여행 고정 규칙을 제안하지 않는다. 날짜·여행 기간·공급자 예약 근거가 필요한 분류는 기존 우선순위 준수.
4. 후보 승인도 기존 수동 규칙 편집/검토 UI가 **이미 있을 때만** 연결한다. 없으면 단순 읽기 전용 제안에 그치고 규칙 자동 생성·일괄 재분류·기존 거래 소급 변경 금지.
5. LLM 학습·외부 모델 API·새 ML 파이프라인·자동 규칙 적용·새 테이블 금지. **사용자 승인 없는 자동 변경 0**.

**수락:** 3건 일관/2건 미달/다른 여행 충돌/동일 원본 중복/수동 우선순위/환불·취소/개인 카드·OTA 근거 보호; 후보 표시만으로 DB·분류 결과 불변.

## 구현 순서와 완료 기준

1. **현행 감사:** 기존 화면/API/Google parser/수동 교정 이력 중복 기능 여부와 실제 호출 경로 확인. 해당되는 기존 테스트를 먼저 실행.
2. **AUTO-03 → AUTO-01 → AUTO-02** 순으로 기존 코드에 최소 변경. AUTO-04는 실제 수동 교정 증거가 충분할 때만 개발한다.
3. 작업별 별도 소형 PR 또는 서로 긴밀한 UI 변경만 한 PR로 묶는다. 파일만 쪼개는 리팩토링, 무근거 캐시/스키마 추가 금지.
4. 단위·통합 회귀: 같은 원천·여행·금액에서 기존 GEMN 판정 동일, 환불/취소/중복 실제 거래 보존, Google reader 실패 보호, 기존 카드/OTA 화면·수기 Google B:H 복사 불변.
5. 운영 수락: 실제 권한 사용자 read-only 확인, 모바일·PC 렌더링, Google 오류 유형 실제 근거, 테스트/병합/배포/운영 수락을 각각 분리 보고.
6. **최종 성공 지표:** 운영자가 찾아다니는 화면 수, 미처리 거래 확인 클릭 수, Google 양식 오류 원인 파악 시간 감소. 새 코드 줄 수·DB 테이블·운영 상태는 최소화.

**명시적 비범위:** Google 자동 쓰기, 카드 수집 재개, 보험 가입 자동 확정, 별도 ERP 마감 엔진, 새로운 Rust 서비스, 무승인 일괄 분류, 근거 없는 AI 추론.
