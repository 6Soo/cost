## 실행 계약

- `/cards/all?panel=coverage`는 파일·카드사별 최초~최종 거래일을 하나의 연속 기본 조회기간으로 만든다. 같은 카드사의 모든 카드 파일 범위를 합집합한 뒤 서로 떨어진 범위 사이만 공백으로 계산한다. 한 파일 내부의 거래 없는 날짜는 공백으로 세지 않는다.
- 날짜는 기존 거래의 `approval_date`(파서의 이용/승인/거래일 매핑)를 사용하고 비어 있으면 `posting_date`를 사용한다. 잘못된 날짜는 계산에서 제외한다.
- 예: 파일A의1일·10일은1~10일, 파일B의15일·20일은15~20일로 간주한다. 공백은11~14일 한곳이다. 같은 카드사의 다른 카드 파일이10~15일을 덮으면 공백은0이다. 전체 양끝 바깥을 누락으로 추정하지 않으며 파일 사이 공백만으로 실제 자료 누락을 확정하지 않는다.
- 겹치거나 바로 이어지는 파일 범위는 병합한다. 카드사가 다르면 합치지 않고 카드사가 없는 자료는 파일별로 분리한다. 원행 중복·금융 집계와 원본/조회기간 증빙은 변경하지 않는다.
- 카드 그룹/파일/공백/거래일자 없는 파일을 표시한다. 공백에서 해당 날짜를 유지해 같은 화면의 업로드를 열고 파일 입력으로 포커스를 옮긴다.
- 조회기간 확인·관리 시작일 폼을 제거한다. 구 거래 상세 업로드 화면은 새 공백 화면으로 연결한다. 긴 구간 목록은 접어서 펼치고, 파일 상세 및 처리 결과는 유지한다.
- 기존 조회기간 증빙 테이블·보호된 API는 호환/보존한다. 조회기간을 새로 확정하거나 운영 DB/원본/분류/환불/Google 장부를 쓰지 않는다. 스키마 변경 없음.
