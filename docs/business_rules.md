# 업무 규칙

## 2026-10-16 승인번호 없는 해외 취소의 짝

해외 카드 원본에는 승인번호가 없어서 취소가 어느 구매를 취소했는지 번호로 알 수 없다. 승인번호 없는 취소는 카드·가맹점명·외화 통화·외화 금액이 같은 구매와만 짝짓는다. 구매는 취소보다 앞서고 이 기간 안에 있어야 한다(`config/refund-pairing.json`, 최대 365일). 같은 조건의 구매와 취소가 여러 건이면 날짜 순서대로 구매 하나에 취소 하나씩 짝짓는다. 같은 금액끼리라 순서를 바꿔도 합계는 같다. 쓸 구매가 없는 취소는 짝 없이 둔다. 같은 조건의 구매가 있는데 짝을 정하지 못한 남는 취소는 개별로 기록하지 않고 묶음으로 보류하며(`refund_count_group`), 개수를 명세와 맞춘 뒤 기록한다. 번호를 붙이지 않는다. 원화 청구액 차이는 환율·수수료로 보고 잔액에 남긴다. 짝 계산은 쓰기가 없고, 기록된 행은 이 규칙으로 바꾸지 않는다. 같은 가맹점 이름을 가진 다른 취소를 묶던 승인번호 빈 칸 비교는 2026-10-16에 고쳤다.

## 2026-10-13 분류 후 자동 기록과 다음 행동

비용 항목과 여행 또는 분기 비용 목적지가 정해지고 원본·중복·권위 일정·회사 경비 제외·사용자 보류·OTA 연결·환불 묶음 검사를 통과한 거래는 별도 기록 버튼 없이 COST 내부 장부에 자동 기록한다. 카드 화면의 소유자 요청과 답변 저장에서만 쓰며 조회 API 자체는 기록하지 않는다. Google 최종 장부 자동 쓰기는 계속 하지 않는다.

자동 기록은 기존 원자적 미리보기·기록 경로와 거래 ID의 중복 방지를 사용한다. 자동 기록으로 사용자 확정 여부를 바꾸거나 추론을 사용자 확정으로 표시하지 않는다. 원문 ID·금액·날짜·분류 근거를 보존하고 이력에는 자동 처리를 표시한다. 문제 있는 환불 묶음은 보류하되 같은 파일의 관련 없는 정상 거래까지 막지 않는다. 새로 기록할 환불은 여전히 전체 구성원을 함께 검증하고 기록하며 일부만 기록하는 것은 금지한다. 기존 수동 기록 경로의 보호 기준은 유지한다.

화면에는 원본 상태명 대신 실제 다음 행동과 이유를 표시한다. 원본 충돌·환불 상태·예약 연결 보류를 단순 여행 미지정보다 먼저 안내한다. 파일 전체 처리 오류를 각 거래의 보류 사유로 덮지 않는다. 거래 링크는 원행 ID를 포함하며 여행 지정은 해당 수정창, 환불 확인은 해당 거래와 연결된 환불, 예약 연결 확인은 기존 결제 연결 영역으로 이동한다.

## 2026-10-13 환불 탭과 과거 내역 표시

원결제와 연결된 모든 환불 원행의 합계가 정확히 0일 때만 환불 탭에 모은다. 여러 번 나눈 환불도 전체 합계로 판정한다. 잔액이 남는 부분 환불은 원결제의 여행에 함께 표시하고 잔액을 해당 여행 비용으로 유지한다. 원결제 금액을 잔액으로 덮거나 환불 원행을 합쳐 삭제하지 않는다. 원거래가 모호하거나 충돌한 자료는 자동으로 묶지 않는다. 여행 귀속·확정·보류·기존 기록은 유지하며 환불 탭은 읽기 전용 표시 분류다.

이미 장부에 기록된 전액 환불 쌍은 모든 구성원이 기록돼 있고 같은 여행에 속하며 저장 금액 합계도 0일 때만 기존 여행의 표시 목록에서 옮긴다. 한쪽만 기록됐거나 서로 다른 여행에 속하면 기존 기록을 숨기지 않는다. 미기록 전액 환불은 환불 탭에 미기록 상태로 보이며 조회를 장부 기록이나 확정으로 해석하지 않는다.

2025년과 2026년 1분기 자료는 이전 합의대로 원본을 보존하고 신규 카드·OTA 검토 목록과 미배정 집계에서 제외한다. 카드 목록은 원본 거래일, OTA 목록은 실제 이용기간으로 판정하며 날짜에 붙은 시간도 파싱한다. 기준일을 넘기는 기간·충돌한 기간·날짜 미확인 자료는 과거 완료 자료로 단정하지 않는다. 미래 이용 예약을 과거 결제일만으로 제외하지 않는다.

## 2026-10-12 카드 3820 싱가포르 여행 예외

사용자 지정에 따라 2026-09-19~2026-09-24의 카드 끝자리 3820 사용내역은 같은 기간의 싱가포르 여행에 배정한다. 이 기간에는 분기 기타비용보다 여행 배정을 우선한다. 등록된 일정과 보존된 사용자 지시가 일치하는 여행이 하나일 때만 적용한다. 기존 비용 항목을 유지하고 항목이 없는 일반 사용내역은 기존 여행 기본 항목인 현지경비로 분류한다. 비용 항목 규칙이 충돌하면 배정과 별개로 검토 상태를 유지한다.

원본 금액·날짜·ID, 기존 사용자 확정·장부 기록·회사 경비 제외·보류·취소·환불·중복 보호를 유지한다. 자동 확정·장부 기록·Google 쓰기는 하지 않는다. 다른 연도·카드·기간으로 확대하지 않는다.

## 2026-10-12 카드 3820 잔여 거래의 분기 기타비용

카드 끝자리 3820 거래 중 기존 대사·확정 규칙·여행 배정으로 처리되지 않고 남은 매입 거래는 `분기 기타비용`으로 분류한다. 거래일의 연도와 분기를 설명에 표시하고, 거래일이 없으면 매입일을 사용한다. 날짜를 읽지 못하면 보류한다. 다른 여행이나 Google 시트를 추측해서 연결하지 않는다.

기존 사용자 확정·장부 기록·회사 경비 제외·보존 기간·구체적 규칙·여행 배정을 덮지 않는다. 취소·환불·중복·충돌·원문 오류는 이 규칙으로 새 비용을 만들지 않는다. 원본 금액·날짜·ID를 보존하며, 분류만 수행하고 사용자 확정·장부 기록·Google 쓰기는 자동으로 수행하지 않는다. 분기 설명은 회계 비용의 구분이며 여행 일정의 근거가 아니다.

## OTA 자료 확인 순서

기존 메일 조사와 포털 전수조사 자료, 예약 후보 문서를 먼저 함께 조회한다. 자료가 존재한다는 사실과 정확 카드 결제 연결을 구분한다. 등록 자료 읽기 실패는 근거 부재로 표시하지 않는다. 예약 확정·실제 결제는 실제 이용 완료의 증명이 아니다. 같은 사용자 보류를 자동 해제하거나 이미 답한 내용을 다시 질문하지 않는다. 구현과 현재 검증은 [OTA 문서](ota_mail.md)를 따른다.

## 2026-10-10 대장·가이드 항공권의 업무 여행 귀속 규칙

노선·목적지·OTA 업체와 관계없이 **서명·출처가 검증된 예약/결제 메일 또는 그 첨부 전자항공권에서 실제 탑승자 이름이 확인되고, 그 사람이 운영에 저장된 여행 담당자 또는 사용자가 이미 확정한 회사의 대장·가이드 신원과 일치할 때** 해당 항공권을 일반 고객 항공권과 달리 **업무 이동 항공권 후보**로 본다.

여행 귀속은 단순히 “직전 여행”이나 “다음 여행”으로 고정하지 않는다. 해당 대장·가이드가 담당하는 authoritative 여행들을 놓고 항공권의 전체 여정(출발·도착 공항, 각 구간 날짜, 왕복/편도, 연결편), 여행 목적지와 일정, 담당자 정보를 함께 대조한다. 다음 유형을 모두 허용한다.

- 여행 시작 전에 현지로 먼저 들어가는 **사전 출국/사전 답사·준비 이동**
- 여행 종료 직후 또는 고객 일정 종료 뒤의 **귀국 이동**
- 연속된 두 여행 사이의 **현지 이동·포지셔닝**
- 여행 도중 합류하거나 먼저 이탈하는 등 원문 근거가 있는 **부분 기간 업무 이동**

귀속 조건은 “그 여행을 위한 업무 이동”이라는 설명이 원문과 일정에서 유일하게 성립해야 한다. 항공편이 여행기간 바깥에 있다는 이유만으로 배제하지 않으며, 반대로 날짜가 가깝다는 이유만으로 자동 귀속하지 않는다. 사전 출국이면 이후 authoritative 여행, 귀국이면 직전 authoritative 여행, 연속 일정 사이 이동이면 관련 양쪽 여행의 담당·노선·시간관계를 함께 검토해 실제 비용 목적이 가장 명확한 한 여행에 귀속한다. 두 여행에 걸친 공통 이동으로 한 여행만 고를 근거가 없으면 HOLD한다.

후보가 둘 이상 합리적으로 남거나, 담당 대장·가이드 신원을 확정할 수 없거나, 항공 구간과 여행 목적지가 모순되거나, 해당 여행이 authoritative하지 않으면 자동 귀속하지 않고 HOLD한다. 이 규칙은 여행의 시작·종료일을 늘리거나 새 여행 authority를 만드는 규칙이 아니며 **기존 authoritative 여행에 항공료 비용을 귀속하는 규칙**이다.

한 예약에 여러 탑승객이 있고 대장·가이드가 아닌 탑승객이 섞여 있으면, 대장·가이드 몫의 운임이 원문에서 분리돼 확인되지 않는 한 예약 전체 금액을 이 규칙으로 자동 귀속하지 않는다. 취소·부분환불·전액환불은 기존 환불 규칙에 따라 원거래와 별도로 보존한다. 항공료가 아닌 OTA 상품이나 단순 가맹점명·결제일·목적지만으로는 이 규칙을 적용하지 않는다.

현재 `a77c71ff`(1,081,000원, 삿포로 6/15–6/21)은 이 일반 규칙의 한 적용 사례다. 메일/전자항공권의 실제 탑승자가 대장·가이드로 확인되면 `0613_북해도`를 포함해 해당 대장이 담당한 전후 authoritative 여행과 항공 구간을 함께 대조해서 귀속 여행을 결정한다. `0613_북해도`에 무조건 붙이지 않으며, 사전 출국·귀국·다음 여행 준비 이동 가능성까지 검토한 뒤 하나로 확정할 근거가 있을 때만 기록한다. 확인 전에는 HOLD를 유지한다.

### 구현 (2026-10-10)

- **탑승자·구간 근거**: 서명 검증된 Trip.com 항공 메일 본문에서 `성 (성) 이름 (이름)` 탑승자와 `가는편/오는편` 구간(날짜·공항·편명)을 예약번호별로 모은다(`app/flight_evidence.py`). 인사말의 이름은 예약자이며 탑승자로 쓰지 않는다. 연도가 없는 결제 완료 안내만 있으면 연도를 추정하지 않고 일정 불완전으로 둔다.
- **대장 신원**: 대장·가이드 신원과 담당 여행의 authority는 reservation(`6Soo/reservation`)이다. COST는 reservation 내부 API(`/api/internal/guides`, `/api/internal/tours?include_past=1`)를 읽기 전용으로 소비한다(`app/reservation_authority.py`). active 대장의 항공권 영문명(`flight_name_en`)과 실명이 메일 탑승자와 정확히 일치할 때만 대장이다. 영문명이 없는 대장이 있으면 영문 탑승자는 UNKNOWN이며 한글 이름에서 철자를 추정하지 않는다. COST의 `trip_tabs.prepared_by_name`, `owner_profile.assignee_name`, `guide-identities.json`은 신원 authority가 아니다(코드는 deprecated). 성만 같거나 일부만 같거나 띄어쓰기만 다른 이름은 일치로 보지 않는다.
- **귀속 판단**: 공항·지역 대응표(`config/guide-airfare-airports.json`)에 있는 공항만 여행지와 대조한다. 관문 공항처럼 근거가 약한 공항은 의도적으로 넣지 않았고, 표에 없으면 HOLD다. 구간별로 사전 출국·귀국·여행 사이 이동·중도 합류·조기 이탈을 판정하고, 모든 구간이 같은 여행 하나로 설명될 때만 귀속한다(`app/guide_airfare.py`). 일정 간격 한도(`max_gap_days`)는 설정이다.
- **연결**: 판정은 OTA 스냅샷 워커에서 계산되고 스냅샷 결과에는 이름 없이 판정·여행·근거 해시만 남는다. 카드 분류는 신선한 스냅샷의 `ATTRIBUTED` 판정만 `guide_airfare_evidence` 소스의 추론 규칙으로 읽는다. 사용자 확정 거래와 환불은 건드리지 않는다. reservation의 대장·여행 자료(영문명·상태·담당 대장·날짜), COST 여행 일정 권위, 메일 근거, 파서, 공항 대응표가 바뀌면 스냅샷 입력 지문이 바뀌어 기존 미리보기는 STALE로 거부된다.

| 트립닷컴·클룩·결제대행 | 예약 자료를 먼저 대조하고, 남은 거래만 질문한다. 공급자 이름만으로 항공·숙박·교통을 정하지 않는다. |
| 아성다이소 | 사용자 답변에 따라 일반 사무용품비로 재사용하고 공통 경비로 처리한다. 여행에 자동 배정하지 않는다. |
| 어드벤처코리아 | 질문한 결제 네 건과 취소·환불 두 건만 여행상품비로 분류한다. 원본 거래 hash에 묶고 여행은 예약 자료로 별도 확인한다. |
| 2025년과 2026년 1분기 | 정리 완료 자료로 내부 보존한다. 검토 화면, 미리보기, 신규 전기에서 제외한다. |

예약 메일은 사용자가 지정한 계정에서 읽었다. 발신 도메인 인증, 예약번호, 실제 원화 결제액, 결제일과 원본 카드 행의 유일한 일치를 확인한다. 같은 금액으로 여러 예약이 남으면 상품 종류만 제안할 수 있으며 특정 예약이나 여행을 임의로 연결하지 않는다. 취소·환불은 구매 거래와 별도로 보존한다.

클룩의 유료 기차표에 함께 제공된 티켓 수령 안내는 해당 상품명이 명시되고 금액이 0원임이 확인된 경우에만 별도 구매에서 제외한다. 두 번째 예약번호가 있다는 이유로 유료 예약의 대조를 누락하지 않는다. 안내에도 결제액이 있거나 다른 상품이 섞이면 자동 연결을 보류한다. 결제일과 이용일이 다르면 이용일을 결제일로 바꾸지 않는다.

예약·온라인·결제대행 거래는 과거에 현지경비로 분류한 가맹점 규칙이 있더라도 사용 국가와 결제일만으로 여행에 배정하지 않는다. 원본 거래에 묶인 구매 목적 규칙과 검증된 예약 이용기간은 별도로 적용할 수 있다.

클룩 2026-05-28의 37,300원은 볼로냐 마찌니에서 프라토를 거쳐 피렌체로 이동하는 두 명의 기차표다. 메일 본문과 첨부 바우처 네 페이지에서 이용일 2026-06-29를 확인했다. 기차표 33,900원과 발급 수수료 3,400원을 교통비로 분류했다. 이후 사용자가 추론 배정을 허용해 과거 같은 원행의 유럽 배정과 이탈리아 이동 구간을 참고하여 유럽 여행에 배정했다. 이용일과 여행기간이 다르므로 확신이 낮은 추론으로 표시하며 6월 29일 원문을 보존한다. 실제 탑승 또는 취소를 확정하지 않는다.

유럽 일정은 사용자 지시에 따라 취소되지 않은 숙박 예약 12건의 명시 기간에서 2026-05-20~2026-06-10으로 정했다. 확인된 국가는 오스트리아, 이탈리아, 프랑스다. 취소된 숙박 두 건은 일정 계산에서 제외했고 체크아웃 날짜는 하루를 빼지 않았다. 관련 메일 원문과 digest는 운영 자료 폴더에 보존한다.

과거에 업종 미상 해외 거래를 식비로 일괄 처리한 결정과 비용제외 결정은 자동 복원하지 않는다. 과거 완료 여부만으로 현재 원본 거래를 자동 승인하지 않는다.

## 2026-10-03 추가로 허용한 추론 배정

사용자가 최대한 추론해 배정하고 나중에 수정하는 방식을 허용했다. 기존 사용자 확정과 검증된 예약 여행을 우선 보호한다. 추론 규칙은 현재 원행 hash에 묶으며 다른 금액·날짜·원행과 미래 거래로 확대하지 않는다. 분류를 다시 실행해도 동일 배정과 사용자의 수정 답변을 유지한다.

같은 카드 원행과 일치하는 과거 장부의 여행, 원래 결제의 여행 후보, 실제 예약 이용기간, 가맹점 지역과 가까운 명시 여행을 차례로 참고한다. 실제 예약 이용일을 아는 경우 다른 달의 결제일로 여행을 골라 넣지 않는다. 구매 상세가 부족한 혼합 예약 상품은 여행상품비로 제안하고 세부 상품 미확인을 표시한다. 구독·통신·사무용품과 일반 업무 경비는 공통 경비로, 취소·환불은 부호를 보존해 분류한다. 국내 현장 구매는 해외 여행에 넣지 않는다.

추론한 거래는 사용자 확정으로 바꾸지 않는다. 화면에 추론 배정과 근거, 높음·중간·낮음 표시를 제공한다. 확신이 낮은 거래는 확인을 권장하지만 기록을 막지 않는다. 원문 오류·중복·충돌과 유효하지 않은 여행은 기존 기록 차단을 유지한다. 현재 없는 여행의 명칭은 참고 자료로 보존하며 일정이나 이용일을 만들어 내지 않는다.

추가 사용자 답변에 따라 이번 조지아·카자흐스탄 거래 18건은 유럽에 배정하는 예외다. 기존 유럽의 명시 숙박 일정과 원문 결제일을 변경하지 않고 사용자 예외임을 표시한다. 미래의 다른 연도나 다른 여행에 무조건 적용하지 않는다.

## 2026-10-03 댓글 기준 출발 예정 여행 등록

reserve에서 확보한 여행 목록과 해당 모집글의 전체 댓글 수를 읽는다. 답글·후기·완료 공지를 모집글로 사용하지 않는다. 댓글이 5개 이상이고 명시 출발일이 한국 날짜로 오늘 이후인 여행을 출발 예정으로 분류해 장부의 여행 목록에 등록한다. 댓글 수는 신청 인원이나 입금액으로 해석하지 않는다.

출발일·종료일·연도와 원문 제목의 기간을 대조한다. reserve에서 사람이 확정한 일정은 그 값을 보존한다. 날짜가 맞지 않거나 댓글을 조회하지 못한 여행은 보류하며, 조회 실패를 댓글 0개로 바꾸지 않는다. 같은 게시판과 같은 연도의 여행은 한 번만 등록한다. 기존 여행의 일정·담당자·사용자 수정은 덮지 않는다.

등록 후 댓글이 5개 미만으로 줄거나 일정이 바뀌면 확인 필요 표시를 남기고 여행과 비용을 삭제하지 않는다. 여행 등록은 비용 항목의 확정이나 비용 전기와 별개다. 실제 카드 원문과 비용 기록은 기존 미리보기·중복 방지 절차를 따른다.

여행글은 한국 시간 매일 0시에 하루 한 번 조회한다. 당일 조회가 실패하거나 서버가 재시작되어도 같은 날짜에 추가 조회하지 않는다. 서버가 해당 시각에 꺼져 있었으면 재시작 후 놓친 당일 조회를 한 번 수행한다. 여행 등록 수와 카드 자료 수, 수입·지출 기록 수는 화면에서 구분한다.
