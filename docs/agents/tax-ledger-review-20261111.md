# Google 지출표 7열 검토 의견 (2026-11-11, 1쪽)

**권고: 현재 양식은 유지한다.** 분기 검수가 끝난 Google 지출표를 세무법인에 그대로 넘기는 업무에 맞는 요약표다. 다만 7열만으로 개별 거래의 증빙 원본·부가세 처리까지 재현할 수 있는지는 별개다. 아래는 검토 의견이며 양식 변경이나 추가 산출물의 구현 승인이 아니다. Q1·Q2 전달 완료는 사용자 설명이며 실제 신고·증빙 완비 여부를 검증한 것은 아니다.

검토 기준은 [보관된 공식 양식 실측](../history/specs-20261110/google-ledger.md#src-docs-google-workbook-layout-md--공식-기준-매출자료-양식_rev의-bh-연속-7열-구조)의 B:H다. **거래일자 / 항목(결제처) / 내용(비용 분류) / 기간 / 예약·증빙 식별자 / 증빙유형 / 원화 금액**의 의미·순서와 합계 수식은 유지한다. 실제 헤더 F는 `예약번호`다. 이번 검토에서 Google 원본이나 고객 증빙을 새로 열지 않았다.

| 검토점 | 현 7열에서 부족할 수 있는 점 | 양식을 바꾸기 전 검토할 보완 |
| --- | --- | --- |
| 증빙 구분 | `카드`·`영수증` 같은 표기는 결제수단과 실제 증빙 종류를 함께 표현할 수 있다 | 원본에서 카드매출전표·현금영수증·세금계산서·일반 영수증을 구별할 수 있는지 세무법인이 확인. 이름만 보고 적격 여부를 자동 확정하지 않음 |
| 부가세 | 원화 총액만으로 공급가액·세액·공제 여부를 읽을 수 없다 | 홈택스·전표 등 기존 원본으로 세무법인이 필요한 구분을 얻는지 확인. 총액을 일률적으로 나눠 세액을 만들지 않음 |
| 거래 식별 | 예약번호가 없는 직접 결제, 동명이액, 부분환불은 시트 행만으로 구별하기 어렵다 | COST 내부에서 원행 ID·발급사·승인번호·취소 원거래 관계를 보존하고, 시트 행에서 원본으로 되짚을 방법이 있는지 점검. 승인번호를 새 필수 열로 정하지 않음 |
| 원본 추적·업무 목적 | 예약 확인서는 실제 결제 전표와 다르며, 여행명·분류만으로 업무 목적의 상세 사정이 남지 않을 수 있다 | 여행 탭·기간·근거 문장에서 실제 결제 자료·영수증·관련 예약으로 연결되는지 점검. 공개 링크나 원문을 시트에 무차별 추가하지 않음 |
| 해외·환불·검수 이력 | 원화 합계만으로 외화 원액·환율·수수료·원결제와 환불·사후 교정을 재현하기 어렵다 | 원본 및 기존 교정 이력 보존. 세무법인에 넘긴 분기본의 시점·건수·합계와 이후 수정 내역을 대조할 수 있는지 검토 |

국세청은 사업용 카드 자료에도 매입세액의 공제·불공제 확인이 필요하다고 안내한다([사업용 신용카드 개요](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7799&mi=2475), 2026-11-11 확인). 따라서 **시트의 비용 분류를 세법상 공제 판정과 동일하게 취급하지 않는 것**이 적절하다. 개별 국내·해외 거래의 증빙 인정·부가세·보존기간과 여행업 특례는 이번 검토로 확정하지 않았다.

우선 Fable이 위 다섯 항목을 세무법인의 기존 기장 방식과 대조하도록 제안한다. 현재 자료만으로 새 열이 필요하다고 결론 내릴 근거는 부족하다. 완료 기준은 사용자 결정대로 **분기 검수 뒤 Google 지출표가 빠짐없이 채워져 세무법인에 넘길 수 있는 상태**다.
