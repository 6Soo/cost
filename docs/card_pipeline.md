# 카드 처리

## 현재 OTA 자료 연결

메일·포털·과거 조사 자료는 운영 `ota-sources.json`에 등록해 함께 조회한다. 자료 내용 변경을 감지하고 미연결 사유를 구분하는 수정까지 적용했다. 현재 연결 수와 남은 항목, 실제 검증 범위는 [OTA 문서](ota_mail.md)의 최신 항목을 따른다.

새 카드 업로드는 서버에서 분류하고, 원본·중복·환불·OTA 근거·소유자 보류를 통과한 거래를 COST 내부 장부에 자동 기록한다. 사용자는 ‘지출 정리’에서 실제 예외 거래만 수정한다. 미리보기 및 수동 기록 API는 회계 검증·호환 목적으로 보존하지만 일상 UI에 수동 기록 승인을 요구하지 않는다. 조회 GET은 기록을 실행하지 않는다.

기업, 국민 국내와 해외, 하나 국내와 해외의 실제 양식을 읽는다. 금액과 승인일, 원번호, 취소 관계를 보존한다. 취소 금액은 음수로 정규화하고 하나의 분할 거래는 검증된 기존 정규화기를 사용한다. 승인일이 없으면 매입일을 처리 날짜로 사용하되 원본 승인일을 채워 만들지 않는다.

파일 원문은 DB에 보존한다. 같은 파일 재업로드는 기존 처리 결과를 반환한다. 다른 파일에 같은 거래가 있으면 원본 거래를 덮지 않고 파일과 거래의 관계만 추가한다. 승인번호 충돌과 번호 없는 거래의 의심스러운 반복은 보류한다.

확정된 답변은 재분류가 덮지 않는다. 답변 저장과 규칙 수정은 즉시 적용된다. 동일 가맹점 규칙이 미래 여행까지 복제하지 않는다. 여행은 검증된 명시 일정이 있을 때만 선택한다. 저장된 자유 형식 요청을 AI가 처리 중이라고 표시하지 않는다.

완료된 이전 기간의 원본·결정·기록 이력은 보존한다. 검토 기간과 미기록 거래 대상은 현재 권한·보존·차단 규칙을 따른다. 2026-10-15 이후 `app/auto_record_policy.py`는 존재하는 배치의 분류 가능한 거래를 허용하므로 이전 `received_at` 자동 기록 시각 제한을 현행 정책으로 오해하지 않는다. 보존·중복·회사 제외·보류·검증 실패는 여전히 차단한다.

예약 자료로 확인한 규칙은 원본 거래 hash와 이용기간 조건을 유지한다. 화면에서 비용 항목을 수정해도 해당 조건을 지우지 않는다. 현지경비 기본 규칙은 원본 사용 국가, 실제 승인일과 검증된 여행이 모두 맞을 때만 적용하며 예약·온라인 공급자의 결제일을 이용일로 해석하지 않는다.

확인 질문은 한 페이지에 스무 건씩 표시한다. 자동분류 결과도 개별 수정할 수 있다. 규칙은 가맹점이나 항목으로 검색하고 수정한다. 입력 중에는 다른 기기의 갱신으로 답변을 지우지 않는다.

사용자가 허용한 원행별 추론도 미리보기에 반영한다. 추론 배정과 사용자 예외를 구분해 표시하고 배정 근거를 펼쳐 볼 수 있다. 확신이 낮은 추론은 질문 영역에 확인 권장으로 표시하며 수정하지 않아도 기록할 수 있다. 한 번의 조회에서는 여행별 검증 결과를 미리보기와 선택지가 함께 사용해 반복 원본 읽기를 줄인다. 다음 조회와 장부 기록에서는 명시 일정 근거를 다시 검사한다.

자동 분류와 사용자 예외 수정의 결과는 미리보기로 확인할 수 있으며, 유효한 거래는 쓰기 경로에서 자동 전기한다. 원본 오류·충돌·무효 여행·환불/OTA 보류는 기록 대상에서 제외한다. 장부 반영 실패는 거래/장부/감사 이력을 원자적으로 되돌리고, 동일 요청 재시도 시 중복 비용을 만들지 않는다.

홈은 카드, 정리할 지출, 장부 건수만 표시한다. 정상 분류됐지만 아직 장부에 기록되지 않은 카드 거래에는 별도 상태명을 표시하지 않는다. 실제 장부 기록 여부는 `ledger_entries` 근거로 판정한다.

카드 검토의 OTA 예약번호와 이용기간은 기존 대조 report에서 가져온다. `CardFlow.preview_metadata()`가 한 미리보기 요청에서 같은 report를 재사용하며, `entry_metadata`로 미리보기 행에 연결한다. `ledger-preview-v2` digest는 `booking_ref`, `service_period`, `ota_evidence`까지 보호한다. 기록 요청은 새 resolver로 미리보기를 다시 계산하고 digest를 비교한 뒤 그 행을 그대로 projection한다. 예약번호는 `board_rows` payload의 `reservation_no`에, 이용기간은 `service_period`에 저장하고 근거 digest는 기존 `classification_basis`에 OTA 출처로 보존한다. `ledger_entries` 스키마는 확장하지 않는다. 자세한 확정·모호성 조건은 [OTA 문서](ota_mail.md)를 따른다.

## API

모든 카드 경로는 기존 로그인과 소유자 권한을 요구한다. 저장 요청에는 CSRF 토큰을 요구한다.

로그인하지 않은 /import 요청은 로그인 안내와 함께 401을 반환하고, API도 401을 반환한다. 기존 /review 진입은 소유자 권한 확인 후 같은 카드 처리 화면으로 이동한다.

카드 처리 경로가 활성화된 운영 환경에서 기본 로그인 완료 경로는 시작 화면이다. 소유자는 카드 처리 화면으로, 조회 사용자에게는 권한을 확인한 장부 화면으로 연결한다. 명시적으로 지정한 장부 이동 경로는 유지한다. 서버 연결 중단은 사용자가 이해할 수 있는 안내로 표시하고 입력 내용을 지우지 않는다.

- GET /import: 카드 처리 화면을 연다.
- POST /api/imports: 파일을 수신·분류한 뒤 적격 거래를 자동 기록한다.
- GET /api/imports: 기존 파일 목록을 조회한다.
- GET /api/imports/{batch}: 질문과 미리보기를 조회한다.
- POST /api/imports/{batch}/decision: 사용자의 예외 답변을 저장·재분류하고 적격 거래를 자동 기록한다.
- GET 또는 POST /api/imports/rules: 규칙을 조회하거나 수정한다.
- POST /api/imports/{batch}/commit: 외부/레거시 호출용 보호된 수동 기록 API(기본 화면에서 직접 호출하지 않음).

답변과 규칙은 revision을 검사하고, 기록은 최신 미리보기를 검사한다. 다른 기기의 수정은 카드 화면에서 이 초마다 확인한다. 입력 중인 답변은 자동 갱신으로 지우지 않고 변경 사실을 알린다.

## 2026-10-08 확인한 기록 계약

CSV, XLSX와 바이너리 XLS(국민카드 매입 원본)를 웹 파서가 읽는다. XLS는 `xlrd`로 첫 시트의 셀 값을 그대로 읽고 이후 정규화 규칙은 CSV·XLSX와 같다. 같은 기간을 CSV로 이미 가져왔어도 XLS를 올리면 새 거래가 생기지 않고(정규화한 값이 같은 거래는 기존 거래로 인식) 사용자가 확정한 값은 그대로다. 승인내역 XLS(`승인방식` 열이 있고 `매입일` 열이 없는 파일)는 매입 확정 전 자료라 중복을 만들 수 있어 `APPROVAL_FILE_NOT_ACQUIRED`로 거절하며, 거절 사실만 이력에 남는다. 원본 분석과 운영 가져오기 완료는 계속 구분한다.

`recordable_rows()`의 blocked·already_booked 제외와 고유 거래 기준을 API ready와 홈에 함께 적용한다. 기록 후 ready에는 이미 기록한 행이 남지 않는다. 장부 projection은 `source_event_id`로 같은 거래를 먼저 찾는다. 거래 ID가 없는 과거 장부 행은 카드사·카드 끝자리·승인번호·일자·부호 있는 금액·거래 종류가 모두 같을 때만 중복으로 차단한다. 서로 다른 실제 거래 ID와 승인·취소·환불을 보존한다.

운영에 반영한 건수와 남은 일정·보류 문제는 [운영 문서](operations.md)에 기록한다. 사용자 합의에 따라 현재 일반 업로드·결정 저장 쓰기 경로에는 자동 기록 기능이 적용돼 있다. 이전의 수동 일괄 기록 보고는 당시의 역사적 사실이다.


## 2026-10-10 검토 → 규칙 → 출력 흐름

- 장부 행을 열면 `예외 처리 (이 건만)`과 `규칙 변경 (반복되는 경우)`을 고를 수 있다. 이 건만 저장하면 그 행만 바뀌고 규칙은 만들어지지 않는다.
- `규칙 변경`으로 저장하면 규칙 대화 화면에서 `내 수정 내용으로 규칙 초안 만들기`를 쓴다. 초안은 저장된 수정(항목·여행)과 카드 원천 가맹점으로 서버가 결정적으로 만들며 모델을 쓰지 않는다. 초안은 어떤 행도 바꾸지 않는다.
- 규칙 조건은 가맹점뿐이다(카드 장부 행에는 규칙이 맞출 수 있는 거래 방향·카드 구분이 없다). 화면은 적용 범위를 "모든 여행·모든 카드의 같은 가맹점 거래"로 문장으로 보여 준다.
- 영향 미리보기에서 `기존 행 적용`과 `미래 입력 적용`을 따로 고르고 `이 범위로 적용`을 눌러야 켜진다. 둘 다 끄면 규칙은 초안으로 남는다. 직접 수정해 잠긴 필드는 영향 대상에서 제외된다.
- `미래 입력 적용`을 켜면 카드 업로드 분류에 이 규칙이 들어간다(사용자가 확정한 거래는 덮지 않는다). 같은 가맹점의 일반 카드 규칙이 있으면 명시 적용한 이 규칙이 그 항목을 대체하고, 원천 거래·예약에 묶인 규칙은 건드리지 않는다. 적용 직후 미기록 카드 거래를 다시 분류한다.
- 분류대기(여행 미정) 행도 항목만 고쳐 저장할 수 있다.
- 출력은 선택한 여행 탭의 저장된 장부 상태 그대로 만든다. 검토필요 행도 화면대로 들어가며 분류대기는 들어가지 않는다는 안내가 화면에 있다.
