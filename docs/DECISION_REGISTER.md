# 현행 결정과 사용자 판단이 필요한 항목

이 문서는 원천 규칙의 요약과 연결 목록이다. 과거 에이전트의 보고를 새로운 사용자 승인으로 승격하지 않는다. 아래 출처의 적용 범위를 유지하고, 모호한 경우 원문과 함께 질문한다. 파일 수정 시각이 가장 늦다는 이유만으로 지시의 우선순위를 정하지 않는다.

## 상태

- `CONFIRMED`: 기존 사용자 지시 또는 명시된 정정 근거가 있다.
- `ENGINEERING_CONTRACT`: 현재 작업에서 정리한 구현·검증 절차다. 새로운 비용 귀속 결정이나 외부 전기 권한이 아니다.
- `NEEDS_USER`: 양립하지 않는 업무 규칙의 적용 범위를 사용자에게 질문한 상태다. 답변 전에는 영향을 받는 결과를 확정하지 않는다.
- `SUPERSEDED`: 명시된 정정으로 대체된 과거 설명이다. 원문은 감사 이력으로 보존한다.

정책의 `CONFIRMED`와 코드의 구현·검증 완료는 별개다. 확정된 정책이더라도 해당 소비 경로가
아직 구현되지 않았거나 테스트되지 않았다면 실행 완료로 기록하지 않는다.

## Q-SCHEDULE-001 — 일정이 겹칠 때 자동 선택할 범위

상태: **CONFIRMED**, 사용자 답변 확정 2026-09-19. 일반 자동선택 승인.

- 충돌하는 근거: `AGENTS.md`의 복수 일정 충돌 보류와 같은 파일의 8월 29일 tie-break 설명. 후자는 레분토·유럽 확인 사례를 언급하면서 일반화 규칙이 아니라고도 명시한다.
- 실제 차이: 서비스 기간 `2026-04-08`부터 `2026-04-10`까지가 에히메와 교토에 모두 포함되는 테스트에서, 현재 코드는 교토를 고르고 기존 테스트는 두 후보가 남기를 요구한다.
- 추천안: 이미 확인한 레분토·유럽 사례는 근거와 범위를 명시한 예외로 보존한다. 다른 겹침은 검토 대기로 남긴다. 예외에는 여행·연도·원천 또는 이벤트 범위·선택 결과·결정 근거를 기록하고 적용 밖으로 확대하지 않는다.
- 대안: 모든 겹침에 시작일 일치 → 최근 시작일 → 늦은 종료일 순으로 자동 선택한다. 끝까지 동률이면 보류한다. 이는 일반 적용을 허용하는 새 업무 결정이다.
- 답변 전 처리: `match_service_period()`의 일반 선택 규칙과 해당 실패 테스트의 기대값을 바꾸지 않는다. 영향을 받는 여행 배정·워크북 확정·전기는 보류하고 독립적인 멱등 검증과 문서 정리는 계속한다.
- 확정 내용 2026-09-19: 사용자가 일반 자동선택을 선택했다. 시작일 일치, 최근 시작일, 늦은 종료일 순으로 자동 선택한다. 끝까지 동률이면 보류한다. 에히메 교토 사례는 0408 교토 선택으로 기대값을 맞춘다. 레분토 유럽 예외를 별도로 두지 않고 일반 규칙으로 포함한다.
- 확정 후 필요한 작업: 실제 답변과 적용 범위를 이 항목에 기록하고, Reserve Max 구현에서 규칙과 테스트를 함께 맞춘다. 기존 예외의 범위가 원천으로 특정되지 않으면 해당 예외를 임의 등록하지 않는다.
