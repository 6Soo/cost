# M5·M6 착수 상세 설계 (2026-11-17)

통합 명세 §11 "착수할 때 이 절을 상세 설계로 확장한다"에 따른 착수 설계다. 정본은 [SPEC](../SPEC.md)·[판정 규칙집](../DECISION_POLICY.md)이고, 이 문서는 M5(클라우드 서버·보조 노드)와 M6(Rust 추출기·Python 폐기)의 실행 단위·수락·게이트를 구체화한다. 선행 근거: [M3 코어 설계](m3-core.md)(§3.4 기준 출력·§5 M5 이월), 원안 작업 큐·P2 실행기는 `m3-core.md` `b8520f48` 판 §5.

운영 현재(착수 시점): `fddbb8c6`/backend8751·gateway8790, 소유권 자유·보류 없음. origin/main `6aceb693`. Rust 도구체인 `rustc 1.100.0` 설치됨.

## 0. 순서와 게이트

- 로드맵 순서는 M5→M6("순서대로 하나씩")다. 다만 **M5 완료는 제공자 선택 게이트**에 묶이고, **M6는 게이트 없이** 고정 기준 수락으로 진행한다.
- **M5 제공자 게이트(사용자 결정):** SPEC §14#10 "고객 개인정보 국외 이전·처리 위탁 고지 의무 — 사용자(제공자 선택 전)", D11 "제공자는 나중에 고른다". 제공자 비종속 설계·구현은 게이트 없이 진행하고, **실제 클라우드 이전(제공자 확정·과금·원문 국외 저장)은 사용자 결정 전에는 실행하지 않는다.**
- 진행 방식: M6 구현(게이트 없음)과 M5 설계·요청량 측정·§14 조사를 병행한다. M5 제공자 선택지는 측정·조사 근거를 갖춘 뒤 쉬운 한국어로 사용자에게 제시해 결정받는다. 무응답은 승인이 아니며 제공자·파괴적 게이트는 유지한다.
- 보호 경계(SPEC §13)는 어느 단계에서도 풀지 않는다. 고객 원문은 보호 경로에만 두고 Git·PR·보고서·무료 모델에 넣지 않는다(PR985 기준 생산과 동일).

## 1. M6 — Rust 추출기·Python 폐기

### 1.1 목표·범위

- 목표: 추출기를 Rust로 교체하고 Python을 폐기해 구성요소를 줄인다. 단일 실행 파일 + SQLite 하나로 수렴한다.
- 범위: **OTA 결제 사건 생성**(메일·포털·예약 자료 파싱과 사건 병합, `app/ota_payments.py:915` `build_ota_payment_events` 등 2,466행과 `app/ota_mail.py`·포털 파서)이 M6 대상이다(m3-core.md:37 "추출이다"). M3에서 Rust는 사건↔카드 대사만 했고 사건 생성은 Python 어댑터가 맡았다.
- 드문 양식은 Rust 파서를 새로 쓰지 않고 **P2 + 데이터 규칙**으로 흡수한다(SPEC §11.1).

### 1.2 수락 기준 — 고정(M3 기준 출력)

- **병합 조건: Rust 추출기 출력이 M3 기준 출력과 일치.** 기준값(고정): **events 7,965건**, **sha256 `a26d446510faabe4cbdfd5d8cf114b0903e6b87b8453fdb3380d529e605cbaf6`**, 28,637,104바이트.
- 기준 工件(보호 경로, 고객 원문): `D:/WebLedgerHost/data/backups/extractor-baseline-main-20261117/events.json`(+ request/response/stderr). Git에는 생산 명령·Python SHA·건수·해시만 남긴다.
- 생산 명령: `python -I tools/core_bridge/cli.py extract-baseline`(Python SHA `750e4a65`, PR980). canonical 직렬화: `canonical({'events': events})` = `json.loads(json.dumps(value, ensure_ascii=False, sort_keys=True, default=집합→sorted/기타→str))`(`tools/core_bridge/commands.py:278`). **Rust 쪽 직렬화도 이 canonical 규칙(키 정렬·ensure_ascii=False·집합 정렬·비JSON str)과 바이트 동일해야 한다.**
- 대조는 보호 경로에서 해시·건수로 한다. 고객 원문을 컨텍스트·Git·보고서에 싣지 않는다.

### 1.3 전환·이관

- 전환기: Rust 코어가 Python 추출기를 하위 프로세스로 부르는 것을 허용한다(`bridge` 모듈). **기준을 통과한 것부터 교체**한다.
- 데이터 이관: 테이블 변환이 아니라 **보존 원본을 새 파이프라인에 다시 넣는 방식**(SPEC §11.1). 기존 수동 교정은 `overrides`로 옮긴다(수동 교정은 자동 판정보다 항상 우선, §13).
- 단일 파일 통합: `board.sqlite`+`core.sqlite` 통합은 Python이 퇴역하는 M6에서 한다(m3-core.md:183). 그 전까지 daily 대조(A↔C, B↔C 그림자)는 Python 판정·연결 코드 퇴역 때까지 계속한다.
- 환불 묶음·초과 환불·원본 충돌 보호와 `supersede`(P1이 P2 교정을 덮지 않음)를 유지한다.

### 1.4 단위·게이트

- 단위는 추출기 소스/기능 묶음(메일 사건·포털 사건·사건 병합·참조 문서 등)으로 나누고, **각 단위는 자기 슬라이스에서 기준 출력과 일치**해야 병합한다. 합성 자료로 개발하고 실데이터 기준 대조는 원문 접근 허용 실행자가 하며 PR에는 집계만 남긴다.
- 게이트(m3-core.md §6.3): `cargo fmt --all --check`·`cargo clippy --workspace --all-targets -- -D warnings`·`cargo test --workspace` + 교정 사례 재실행 + 기준 해시 일치. `.py` 변경 시 `python tools/run_quality_checks.py --base origin/main --run`.
- 작업자가 테스트·골든 기대값을 고쳐 통과시키지 않는다. 독립 검수(`gpt-6.1-sol` medium 이상, Codex 한도 시 Claude opus 대체) 최종 SHA PASS → 병합 → 공식 배포.

## 2. M5 — 클라우드 서버·보조 노드

### 2.1 역할·실행 방식

- 서버: 화면·API·DB·원문 저장·P1·작업 큐. 보조 노드(로컬 PC): P2 실행·로그인 세션이 필요한 수집. **같은 실행 파일의 두 실행 방식**(SPEC §11.3).
- 보조 노드는 서버로 **나가는 요청만** 한다. PC로 들어오는 터널을 두지 않는다.
- PC가 꺼져 있으면 화면·P1·웹 업로드는 계속 동작하고 P2와 브라우저 수집만 쌓인다.

### 2.2 작업 큐·임대·P2 실행기(M3 이월, D-11)

- `core.sqlite`의 `jobs`·`budgets`·`agent_runs`·`p2_proposals`는 M3 U3에서 만들어 두고 비워 뒀다. M5에서 채운다.
- 작업 큐(`jobs`): `queued|leased|succeeded|failed|dead`, `dedupe_key` 중복 방지, `lease_owner`·`lease_until` 임대, `not_before` 재시도 지연, `budget_key`. **임대 만료**가 현 파일 잠금("죽은 PID·2시간 초과 자동 인수", `tools/p2_batch/run_incremental.py:73-115`)을 대체한다. 보조 노드는 같은 테이블을 **HTTPS로 임대**한다.
- 예산(`budgets`): 호출 상한(기본 최대 30묶음·모델 1회)·일일 예산. 실패 호출도 상한 포함. 구독 한도 공유 → 한도 오류는 `not_before`를 미뤄 다음 회차로.
- **P1 먼저:** P2가 밀려도 P1 판정은 먼저 게시.
- P2 실행기: `P2Runner` 트레이트 + `CodexExec`(운영, 현 `tools/p2_batch/layer1.py:190-192`와 같은 인자·빈 임시 cwd·stdin 자료·Windows 작업 개체 시간 제한) + `Replay`(테스트, 실제 모델 호출 0). 검증은 실행기 밖 한 함수(현 `layer1.validate`와 같은 오류 코드·digest 결속·도구 이벤트 거부). 재시도 분류(용량·형식 최대 3회 30/60초, 인증·도구 오류 즉시 `dead`). 대상 선정은 `tools/p2_batch/scope.py:81-148` 순서·사유 코드 그대로 옮겨 골든 비교.
- 반영 경로: 전환 전에는 현 Python 교정 경로(인증 API·미리보기 digest·요청당 50행)를 그대로 쓴다. 새 쓰기 경로를 만들지 않는다.

### 2.3 제공자 비종속 포장·백업

- **실행 파일 하나 + SQLite 파일 하나 + 원문 폴더(또는 S3 호환 저장소)**. 제공자 전용 런타임에 맞춘 코드를 쓰지 않는다(SPEC §11.3, D11).
- 매일 클라우드 DB와 원문을 로컬 PC로 내려받아 보관한다.
- Linux 이식성: 현 Board는 `http.server` 기반 Python이다. M6 Python 폐기 후 단일 Rust 실행 파일로 수렴하면 이식성이 높아진다. M5 packaging은 M6 진행과 맞물린다.

### 2.4 제공자 선택 게이트 — 측정·§14 조사(사용자 결정 전)

- **요청량 측정:** SPEC §11.3 "제공자는 이전 시점에 실제 요청량을 재고 고른다". 현재 Board는 요청 수 접근 로그가 없다(`ledger_board.py:2270` `log_message` 침묵, `app/request_metrics.py`는 내용 없는 성능 측정만). **제공자 규모 산정 전에 경량 요청 수 계측(내용 없는 카운터)을 넣어 실제 요청량을 읽기 전용으로 측정**한다. 운영 포트·보호 경계는 건드리지 않는다.
- **§14 조사:** 고객 개인정보 **국외 이전**(개인정보 보호법 §28-8 등)·**처리 위탁** 고지 의무를 조사한다. 국내 리전 제공자는 국외 이전 쟁점이 줄고, 국외 리전은 고지·동의 요건이 생긴다. 조사 결과를 쉬운 한국어로 정리해 제공자 선택지와 함께 사용자에게 제시한다.
- **게이트:** 제공자 확정·과금·원문 국외 저장은 사용자 결정 전 실행하지 않는다. 선택지에는 비용·리전·개인정보(국외 이전·위탁 고지)·이식성 트레이드오프를 붙인다.

## 3. 착수 작업 순서

1. M6 추출기 단위 구현(게이트 없음) — 기준 해시 일치 수락, 독립 검수·병합·배포.
2. M5 작업 큐·임대·P2 실행기 구현(제공자 비종속, 게이트 없음) — 합성 검사, 독립 검수·병합.
3. M5 요청량 계측·측정 + §14 국외 이전·위탁 조사(읽기 전용).
4. 측정·조사 근거로 제공자 선택지 제시 → **사용자 결정**(§14#10).
5. 결정 후 실제 클라우드 이전·보조 노드 연결·일일 백업 — 신선 백업·복원 확인, 보호 게이트, 공식 배포.

## 4. 보호·경계(요약)

- 카드 원문·금액·부호·ID·메일 원문·영수증 원본 변경·삭제 금지. 수동 교정 우선. 중복·환불 짝·초과 환불·원본 충돌 보호 유지. Google 최종 장부 자동 쓰기 금지. 인증 우회 금지.
- 미리보기·테스트에 운영 포트 8751·8752·8790 사용 금지. 시작하지 않은 프로세스 종료 금지. 같은 파일·DB·배포 작성자 하나.
- 고객 원문은 보호 경로에만. Git·PR·보고서·무료 모델 금지(구독 프론티어 P2·Qwen4 Max 작업자 예외, PROC-012).
- 대량 반영·삭제·스키마 변경·금융 원본 변경은 신선 백업·복원 확인 뒤. 문서만 바꾼 변경은 링크·인용 사실만 확인(재배포 없음).
