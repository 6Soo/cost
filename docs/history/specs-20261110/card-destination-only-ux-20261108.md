## 사용자에게 보이는 최종 동작

1. 카드에 미배정·확인필요·처리필요·미분류 및 동의어 상태/필터/카운터/배지/작업 CTA를 제공하지 않는다. `직접 답할 작업`과 `내 확인 필요` 메뉴·홈 버튼·카드 P3 질문/답변 기능을 폐지한다. 이를 새 이름의 대기열로 대체하지 않는다.
2. P1 코드와 P2 AI로 실제 여행을 우선한다. 해소되지 않아 P3가 필요했던 일반 비용은 원문 결제일(없으면 유효한 매입일)의 해당 분기 기타비용으로 종결한다. 실제 여행을 만들거나 날짜 오류를 오늘 날짜로 바꾸지 않는다. 실패/AI 미설정도 사람 질문으로 전가하지 않는다.
3. 카드의 사용자 귀속은 실제 여행 또는 기타비용이다. 기존 자료의 읽기 투영도 이 기준을 따른다. 기존 원본 오류·날짜 미상·금액 오류는 내부 안전 차단과 사실 기반 원본 오류 설명을 남기며 가짜 분기·성공·금융 기록을 만들지 않는다. 작업함으로 보내지 않는다.
4. 기존 수동 교정, 취소/부분환불 연결, 중복/초과환불, 기장/실제 환급/Google 반영의 구별과 owner/CSRF/revision·원자성을 유지한다. 금융 보호는 분류 대기 업무와 별개의 내부 제약이다. 기존 보호 테이블·감사 이력·원본은 삭제하지 않는다.

## UI 우선 구현·검증

홈은 자료 조회/업로드 중심이며 질문 카운터와 빈 작업 버튼이 없다. 좌측·모바일 메뉴에도 작업함이 없다. 카드 내역은 업로드·수집 현황·검색·카드/기간 필터·거래 귀속·금액 중심이다. 거래 상세의 수정은 완료 귀속의 자율 교정이며 필수 질문이 아니다. 보호 사유는 거래 상세의 읽기 정보로 제공한다.

`/my-actions` 기존 GET은 인증 후 `/cards/all`로 이동하며 질문 화면을 렌더링하지 않는다. 기존 작업 답변 POST/API는 기존 인증·CSRF 보호 이후 410으로 종료하고 데이터를 쓰지 않는다. 기존 task 이력은 감사 자료로 보존한다. P3 신규 등록과 답변 소비 worker는 중단한다.

기존 디자인 토큰·타이포·테마·공통 컴포넌트를 재사용한다. 실제 better-* 및 interface-review와 ui-ux-pro-max를 적용한다. 320/390/1440 동일 뷰포트 전후, 밝음/어두움, 키보드·긴 값·0건·업로드 성공/실패·네트워크 오류·금융 보호/환불 상태까지 검사한다. 실제 DOM/렌더링에 금지된 작업·상태가 남으면 불합격이다.
