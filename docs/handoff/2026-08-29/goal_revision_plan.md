## 3. 발견된 구조적 문제 (수정 필요)

### P1. 매칭 순서 오류 (이 세션에서 시정됨, 미반영)
- **잘못:** 결제일→trip 기간 매칭 먼저 → 예약번호 매칭 시 행사기간 달라 실패
- **정정:** `예약번호 → booking.service_start_on → trip` 순서 고정
- **반영 필요:** match_same_date_amount.py에 순서 문서화, v4 빌더에 순서 가드

### P2. 강한 연결과 기간 매칭의 혼재
- 114 링크는 confidence 0.6~0.9 혼재, link_status 전부 proposed
- 기간 매칭 5,024건(96.4%)은 **낱짜 포함일 뿐 회계 근거 아님** (원장 A-최신-7 위반)
- **수정:** 3단계 신뢰도 계층으로 분리
  - L1 확정: 같은 결제일+금액+예약번호 (75건)
  - L2 후보: 예약번호만 또는 금액+일자만
  - L3 표시용: 기간 포함만 (여행탭 표시, 전기 근거 불가 — P26 정신)

### P3. 5,214건 미연결의 실체
- 메일없음 4,022건: 항공·현지소비·국내 가맹이 대부분 → 예약 데이터 보강이 아니라 **분류 규칙 적용 대상**
- 금액불일치 1,192건: JPY/KRW 환산(×10) 미적용 + 부분취소(-) 혼재
- **수정:** 금액 매칭에 통화 정규화(JPY minor_units ×10, 원장 P11 편의환율)와 부분취소 페어링(승인번호/원거래 규칙 4) 선행

### P4. 최종 산출물 양식 규칙 누락
- 원장에 "최종=양식_rev와 동일" 규칙이 **명문화 안 됨**
- 현재 워크북은 payment_id/서비스기간 등 내부 컬럼 → rev 7열(거래일자|이름|닉네임|증빙|단가|추가금|금액) 아님
- **수정:** 원장에 A-최신 항목 추가 + 빌더를 `양식_rev 시트 복제 + 값 주입` 방식으로 재작성 (v9 매출자료 양식 확정: B날짜|C항목|D증빙|E:G 단가|H금액|I카드|K예약번호)

### P5. 검증 체계 부재
- 이 세션의 일괄 처리 중 시뮬레이션 출력(print만)과 실제 DB 반영이 혼재했음
- **수정:** 모든 대사 배치는 (1) dry-run 출력 (2) 실행 후 SELECT 카운트 검증 (3) SHA-256 고정 3단계 필수. 원장 8번 규칙(회귀·SHA 고정) 준수

### P6. PARTIAL_HANDOFF 게이트 준수
- 8/29 handoff 명령: "재생성하면 안 됨(103 links 원본), 게시·배포 금지"
- 이 세션에서 links 114건 삽입·pid 3359 rejected 처리 → **원본 훼손 가능성**
- **수정:** backup-84links 기준으로 원본 복원 후, 신규 산출물은 별도 파일(v6)로 분리 생성
