# 기록된 자동 배정의 예약 이용기간 교정

사용자 요청: “이용일 제대로 체크했는데 왜 엉뚱한곳에 배정됐지? 문제찾고수정”.

## 원인과 변경

예약 확인 전에 카드 날짜로 추론해 기장한 여행은 기존 장부 배정으로 보존됐다. 이후 명시 재검토에서 새 예약 이용기간을 확인해도 기록된 자동 배정은 교정되지 않았고 거래·장부·화면의 기존 여행이 남았다.

명시 카드 재분류에서 최신 중앙 대사의 원본 해시·유효한 결제·이용기간·실제 여행을 확인하고, 기록된 자동 추론만 예약 이용기간으로 교정한다. 거래·장부·화면 행과 교정 이력을 한 트랜잭션에서 저장한다. 단순 조회·재시작·무관한 가져오기는 과거 거래를 이동하지 않는다.

수동 결정·수동 필드 교정·owner 기장·검토 보류·환불 및 원결제·원본 불일치·오래되거나 충돌하는 예약 근거는 보호한다. 금액·카드 원본·카드 날짜·ID·금융 링크를 바꾸지 않는다. Google 최종 장부에는 쓰지 않는다.

## 실제 교정과 수락

- 문제 거래 1건은 기존 승인 범위에서 `1002_영남`에서 `1010_도쿠시마`로 교정했다. 예약 이용기간은 2026-10-13~2026-10-14다.
- 변경 전 대상 행 사본, 메모리 리허설, 원자 저장 및 교정 이력으로 복구를 보장한다. 다른 업무 행·원본·금융 보호와 반복 대상 0을 검증했다. 전체 재처리나 Google 쓰기는 하지 않았다.
- 재개 후 운영 읽기에서 거래·장부·화면의 세 여행 값 일치, 원본·금액·날짜·ID 보존, 교정 이력 1건을 확인했다. 기존 Ego15 여행 화면에서도 해당 지출을 확인했다.
- 개인정보를 포함한 원본은 Git에 넣지 않는다. 로컬 근거는 `C:/AX/cost/.local-archive/stay-trip-fix-20261103/`, 대상 행 복구 사본·실행 근거는 `D:/WebLedgerHost/data/backups/stay-period-single-20261103/`에 보존한다.
