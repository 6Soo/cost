# 직원·가이드 지출 정산 — 대상과 결과 형식 제안

> **상태:** 사용자가 고를 안을 제시하는 제안서다(2026-11-13). 구현하지 않는다.
> [통합 명세](../SPEC.md) §1.3이 정한 산출물 3종 중 "직원·가이드 지출 정산"만 정의가 비어 있다. §9와 결정 D23은 "M2 이후 대상과 결과 형식의 안을 제안한다"고 정했고, 이 문서가 그 안이다. 사용자가 고르면 명세 §9와 규칙집에 반영한 뒤 구현한다.
> 예시 표의 사람·여행·금액은 **모두 지어낸 값**이다. 실제 고객·직원 이름과 금액은 넣지 않았다.

## 1. 정산이 답해야 할 질문 후보

여행사는 가이드가 여행 중 현장에서 돈을 쓰고, 직원이 사무 비용을 쓴다. 정산은 아래 질문에 답해야 한다.

| # | 질문 | 뜻 |
| --- | --- | --- |
| Q1 | 가이드에게 돌려줄 돈이 얼마인가 | 가이드가 사비(현금·개인카드)로 낸 여행 경비를 회사가 갚는다 |
| Q2 | 가이드가 미리 받은 경비를 어떻게 썼는가 | 선급금(가이드에게 미리 준 돈)의 사용 내역과 남은 돈 반환·추가 청구 |
| Q3 | 직원 개인 결제를 얼마 돌려줘야 하는가 | 사무·준비 비용을 개인카드로 낸 직원 환급 |
| Q4 | 누가 어느 여행에 얼마를 썼는가 | 사람별·여행별 지출 합계. 여행별 손익과 이어진다 |
| Q5 | 증빙이 빠짐없이 모였는가 | 세무·증빙 자료로 넘길 때 영수증 누락·중복 확인 |

## 2. 지금 있는 것과 없는 것

### 재사용할 수 있는 기능

| 기능 | 지금 하는 일 | 정산에 쓰이는 부분 |
| --- | --- | --- |
| 영수증 등록·검토 ([코드](../../webapp/receipt_review.py), [규칙](../policy/receipt.md)) | 사진·PDF 업로드, 결제수단(현금·개인카드·법인카드)·지급처·여행 선택, Google 7열 복사 | 현금·개인카드 지출의 입력과 증빙 |
| 카드 판정 | 카드 거래를 여행·항목에 배정(P1 규칙·P2 AI) | 여행별 지출은 이미 판정돼 있다 |
| 지정 카드 규칙 (TRIP-069~071, ITEM-037·038) | 소유자가 지정한 카드 2장에 여행·분기 예외 적용 | 카드별 사용자 구분의 출발점 |
| 캐시·포인트 처리 (ITEM-019) | 아고다캐시·클룩 포인트 등도 카드와 같은 과정으로 판정 | 비카드 지출 포함 |
| 참가자 명단 ([규칙](../policy/income.md), INC-032) | 대장·가이드·직원·일반 참가 역할 구분 | 여행에 누가 가이드로 갔는지 |
| 계정·열람 권한 ([코드](../../webapp/access_control.py)) | owner/viewer 역할, 여행별 열람 허용 | 가이드 계정·업로드 권한의 바탕 |
| Google 지출표 읽기 ([코드](../../app/google_authority.py), [규칙](../policy/google.md)) | 여행 탭의 수입·지출을 읽기 전용 동기화 | 정산 결과의 대사 대상 |

### 없는 것 (이번 제안이 채울 부분)

- **등록자 구분:** 영수증에 "누가 올렸고 누가 썼는지" 필드가 없다. 업로드는 owner만 할 수 있다.
- **카드→사람 연결:** 지정 카드 규칙은 카드→여행만 정한다. 어떤 카드를 누가 쓰는지 표가 없다.
- **선급금 기록:** 회사가 가이드에게 미리 준 돈의 기록이 어디에도 없다.
- **정산 집계·내보내기:** 사람별·여행별 합계와 정산표가 없다.
- **지급처 칸:** Google 지출표 7열(거래일자·항목·내용·기간·예약번호·증빙유형·금액)에 낸 사람 칸이 없다. 양식은 바꾸지 않는다(D22). 정산은 별도 표로 내보낸다.

### 운영 건수 (2026-11-13, 읽기 전용 조회)

| 항목 | 건수 |
| --- | --- |
| 영수증 등록 | **0건** (기능은 켜져 있으나 저장소가 만들어지지 않음 = 미사용) |
| 영수증 등록자 | **0명** |
| 여행별 영수증 분포 | 없음(0건). 참고: 내부 장부 캐시·포인트 4행이 4개 여행에 1건씩 |
| 현금·개인카드로 보이는 지출 | 내부 장부 캐시·포인트 **4건**(아고다캐시 3·클룩 포인트 1). Google 지출표 "영수증" 증빙 **96행**은 현금·개인카드 표기가 없어 따로 못 셈. 카드 가져오기에 개인카드 거래 구분 없음 |
| 지정 카드 | **2장**(거래 518건·14건) |
| 참고 | 카드 거래 7,336건, 장부 행 3,548, 여행 탭 77, 계정 owner 1·viewer 0 |

뜻: 정산은 데이터가 0에서 시작한다. 다만 카드→여행 판정과 영수증·권한 기능은 이미 있어 재사용할 수 있다.

## 3. 안 A·B·C (작게 → 크게)

### 안 A — 영수증 환급 목록 (작음)

- **대상:** 회사 경비로 인정한 현금·개인카드 영수증. Q1·Q3만 답한다.
- **입력:** owner가 지금처럼 영수증을 올리고 여행·결제수단을 고른다. 여기에 **"낸 사람" 선택**만 추가한다.
- **결과물:** 사람별 환급 집계와 TSV/CSV 내보내기. 예시(지어낸 값):

  | 낸 사람 | 여행 | 현금 | 개인카드 | 환급 합계 | 영수증 수 |
  | --- | --- | --- | --- | --- | --- |
  | 가이드 A | 0000_여행1 | 35,000 | 120,000 | 155,000 | 7 |
  | 직원 B | 분기 기타비용 | 0 | 48,000 | 48,000 | 3 |

- **분기 검수와의 관계:** owner가 분기 검수 때 "낸 사람"과 경비 인정을 확인하고 내보낸다. 새 확인 단계는 없다.
- **재사용:** 영수증 등록·검토, 결제수단·지급처·여행 필드, TSV 내보내기. **새로 만드는 것:** 낸 사람 필드, 집계, 내보내기.
- **한계:** 가이드의 법인카드·지정 카드 지출이 빠진다. 선급금(Q2)은 답하지 못한다.

### 안 B — 사람별·여행별 정산 (중간)

- **대상:** A + 법인카드·지정 카드·캐시·포인트까지 사람별로 모은다. Q1·Q3·Q4·Q5를 답한다.
- **입력:** A의 입력 + **카드→사람 연결을 owner가 한 번 등록**(예: "지정 카드 ①은 가이드 A"). 같은 카드를 여러 사람이 쓰면 여행별로 분기 검수에서 사람을 고른다.
- **결과물:** 사람별·여행별 정산표와 여행별 합계, 환급 목록. 예시(지어낸 값):

  | 사람 | 여행 | 법인카드 | 현금 | 개인카드 | 포인트 | 합계 | 이 중 환급 대상 |
  | --- | --- | --- | --- | --- | --- | --- | --- |
  | 가이드 A | 0000_여행1 | 820,000 | 35,000 | 120,000 | 15,000 | 990,000 | 155,000 |
  | 직원 B | 0000_여행2 | 210,000 | 0 | 48,000 | 0 | 258,000 | 48,000 |

- **분기 검수와의 관계:** 사람 배정 교정은 기존 판정 교정과 같은 경로로 처리한다. 교정은 규칙·데이터로 쌓여 같은 교정을 두 번 받지 않는다(명세 §8).
- **재사용:** 카드 귀속 판정(P1/P2), 지정 카드 규칙, 캐시·포인트 파이프라인, 참가자 역할, 교정 이력 + A의 전부. **새로 만드는 것:** 카드→사람 연결 표, 사람 축 집계, 정산 내보내기.
- **한계:** 선급금 사용·반환(Q2)은 기록이 없어 답하지 못한다.

### 안 C — 선급금 포함 전체 정산 (큼)

- **대상:** B + 선급금 장부. Q1~Q5 전부 답한다.
- **입력:** B의 입력 + **선급금 기록**(owner가 준 금액·날짜·받은 사람을 입력) + **가이드 직접 업로드**(가이드 계정과 여행별 업로드 권한을 새로 만든다).
- **결과물:** 가이드별 선급금 정산서 + B의 표들. 예시(지어낸 값):

  | 가이드 | 여행 | 선급금 | 사용액 | 잔액 |
  | --- | --- | --- | --- | --- |
  | 가이드 A | 0000_여행1 | 500,000 | 430,000 | +70,000(반환) |
  | 가이드 C | 0000_여행3 | 300,000 | 342,000 | -42,000(추가 청구) |

- **분기 검수와의 관계:** owner가 분기 검수 때 잔액을 검수한다. 실제 이체·환급은 사용자가 직접 하고, COST는 이체 완료를 추론하지 않는다(명세 §1.5).
- **재사용:** B의 전부 + viewer 계정·열람 권한(업로드 허용으로 확장 설계 필요), 수입·이체 읽기 경로(의미 확인 필요). **새로 만드는 것:** 선급금 장부, 가이드 업로드 권한, 정산서, 잔액 계산.
- **위험:** 권한 확장은 보호 경계(명세 §13)를 약화하지 않는 설계가 필요하다. 선급금 입력 부담이 새로 생긴다. M3 이후 새 화면·코어와 함께 하는 편이 나을 수 있다.

## 4. 권장안 — B

이유:

1. **A는 정산이라 부르기 좁다.** 가이드 지출의 대부분은 법인카드·지정 카드인데 A는 이를 빼고 영수증 환급만 센다.
2. **C는 데이터를 새로 만들어야 한다.** 선급금 기록이 지금 없고, 가이드 계정·업로드 권한 확장도 필요하다. 입력 부담과 보호 설계가 커서 B 뒤에 붙이는 편이 안전하다.
3. **B는 이미 있는 판정을 재사용한다.** 카드→여행 판정은 끝나 있으므로 카드→사람 연결과 집계만 더하면 된다. 핵심 질문 3개 중 2개(환급·사람별 지출)를 답하고, 나머지(선급금)는 C로 확장할 수 있다.
4. **분기 검수 구조에 맞는다.** 거래마다 묻지 않고, 사람 배정 교정이 규칙으로 쌓인다.

단, 선급금 관리가 급하면 C의 선급금 입력 부분만 앞으로 당길 수 있다. 아래 질문 2의 답에 달렸다.

## 5. 사용자가 정해야 할 질문

1. **정산 대상 범위** — 여행 가이드만인가, 직원 사무 비용도 포함인가?
   예: "해외 여행 가이드만" vs "직원 개인카드 사무용품 구매도 환급 대상에 포함".
2. **선급금 관리 방법** — 가이드에게 미리 준 경비를 COST에서 관리하나, 밖(엑셀·뱅킹 앱)에서 관리하나?
   예: "가이드 A가 여행 전 500,000원을 받아 430,000원을 쓰고 70,000원을 반환" — 이 내역을 COST에 입력할 사람이 있는가? 있다면 누가 입력하나?
3. **영수증 업로드 주체** — 가이드가 직접 올리나, owner가 모아서 올리나?
   예: "가이드가 여행 중 휴대폰으로 직접 업로드" vs "귀국 후 owner가 일괄 업로드". 직접 업로드는 가이드 계정·권한 생성이 필요하다(안 C).
4. **카드의 사람 구분 방법** — 카드→사람을 한 번 등록하면 충분한가?
   예: "지정 카드 ①은 항상 가이드 A" vs "같은 카드를 여행마다 다른 사람이 씀". 후자는 여행별 사람 선택이 필요하다.
5. **정산 시점과 결과 형식** — 언제, 어떤 표로 받나?
   예: "여행 종료 직후 여행별 정산서" vs "분기 검수 때 사람별 집계 한 번". 내보내기는 TSV/CSV 중 무엇으로 할 것인가?

## 6. 바뀌지 않는 것 (보호)

- Google 최종 장부에 자동으로 쓰지 않는다. 지출표 양식은 바꾸지 않는다(D22). 정산은 별도 표·내보내기다.
- 카드 원문·금액·영수증 원본을 바꾸거나 지우지 않는다. 수동 교정이 자동 판정보다 우선한다.
- 실제 환급·이체 완료 사실을 추론으로 만들지 않는다.
- 계정·열람 권한 검사를 약화하지 않는다. 고객 원문은 Git·PR·보고서에 넣지 않는다.
- 확인함·보류·분류 대기 같은 상태는 만들지 않는다(P3 폐지).
