## 구현 우선순위 및 충돌 처리

1. 기존 RF-101/102/103/201/202 대량 리팩토링 중 **단독 파일 소유권을 위반하지 않는다**. 진행 중인 PR/브랜치·최신 main을 확인하고 신규 작업이 충돌하지 않도록 순서화.
2. 제품 우선순위는 [PIR-01~06 참가자와 수입 통합](participant-income-authority-and-drag-link-20261028.md), [PA-01~06 낮은 근거의 잠정 배정](provisional-assignment-review-first-20261028.md). P0로 작업지시 준비.
3. 여행별 항공권 UI([TF-001~08](trip-flight-booking-overview-20261028.md))와 보험/수입 통합 UI는 같은 여행 탭을 수정하므로 공통 레이아웃 RF-202/203을 먼저 합치고 **동일 파일 충돌 없이** 이어서 반영한다.
4. 신규 제안 범위는 **명세**다. 기존 실사용 데이터 전환·금융 거래 수정·보험 명단 전송·Google 자동 쓰기는 이 결정만으로 승인되지 않는다.
5. 완료 보고는 `SPEC_ONLY / CODE_WRITTEN / TEST_PASSED / MERGED / DEPLOYED / REAL_DATA_ACCEPTED`를 구분. 명세 병합만으로 실제 화면이 동작한다고 보고 금지.

## 후속 결정이 있을 때만 확장할 사항

- 1인별 여행비 완납 조건, 공동입금의 금액 배분, 환불/추가입금 정산은 **현재 명세 범위에 포함되지 않는다**. 참가자-입금 관계를 연결하는 것은 입금·완납의 재무적 확정이나 원본 수정이 아니다.
- 소유자 이외 직원의 보험 명단 열람은 미승인.
- Travel INS 서버 간 HTTP API 전송은 미승인.
- 오래된 미해결 OTA 자동 보관·강제 완료는 **명시적 거부**.
