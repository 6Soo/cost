# COST UI 품질 개선 실행 명세 (2026-11-05)

상태: **개발 절차 승인 / UI 코드 미변경 / 실제 적용·검증 미완료**. 이 문서는 새 UI 개선 요청이 있을 때 적용하는 작업 방법이며, 오래된 UI TODO를 자동 재개하거나 전면 재설계를 지시하지 않는다.

## 1. 우선 규칙과 목적
- 최상위: [AGENTS.md](../../AGENTS.md), [현행 상태](../session_handoff.md), [UI 계약](ui.md), 금융·Google·OTA 보호 명세 및 배포 단일 작성자 규칙.
- 목적: 거래·여행·항공권·OTA 관리 화면의 **정보 밀도, 가독성, 검색·필터 조작성, 접근성, 반응형, 상태 표시**를 기존 디자인 시스템 안에서 개선.
- UI 작업이더라도 금융 분류, 금액, ID, 사용자 교정, API·DB 계약, Google 원본·보호 13표를 변경하지 않는다. 테마 아이콘은 기존 우상단 단일 토글을 유지한다. 이 문서는 운영 배포·고객 데이터 쓰기 승인이 아니다.
- 기존 미커밋 변경과 다른 에이전트 작업을 보존하며 UI와 무관한 대규모 리팩토링을 하지 않는다.

## 2. 스킬 설치·인식
원본: https://github.com/jakubkrehel/skills . 설치는 사용자 로컬 Windows에서 저장소 루트에 `npx skills add jakubkrehel/skills` 실행, Codex 또는 실제 사용하는 OpenCode 에이전트의 **프로젝트 로컬** 범위를 우선한다. 명령/설치 옵션은 실행 시 원본 README를 재확인한다. 레포에 아직 설치되지 않은 스킬이 있으면 설치 사실을 꾸미지 말고 사용 가능 여부를 확인한다. 에이전트 스킬의 SKILL.md를 실제로 읽고 사용하며 이름만 언급하는 것으로 사용 완료 처리하지 않는다. 외부 설치·다운로드가 제한되면 BLOCKED로 기록하고 기존 UI 검사로 가능한 일을 계속한다.

## 3. 요청별 실행 절차
1. **DISCOVER:** 최신 사용자 요청과 해당 화면 계약을 확인. 현재 화면·컴포넌트·CSS·반응형·테스트의 기준 SHA/스크린샷을 확보. 실고객 정보는 익명화된 fixture만 사용.
2. **AUDIT:** `better-interface`로 문제를 **위치 / 재현 조건 / 사용자 영향 / 심각도 / 기존 디자인과의 충돌 / 제안 수정 / 검증 방법** 표로 작성. 실제 실행이 불가능하면 수동 진단이라고 표시.
3. **PLAN:** `better-layout`, `better-typography`, `better-accessibility`, `better-writing` 중 **문제에 해당하는 것만** 선택. 전체 스타일·컴포넌트 교체 금지. 주요 화면은 기존 금융/여행 표기 의미와 API 필드 보존을 명세에 기록.
4. **IMPLEMENT:** 가장 영향이 큰 작은 변경 단위로 구현. 테이블 열 폭·긴 거래처명·금액 정렬·필터·모바일 스크롤·키보드 포커스·오류 안내·다크모드를 우선하되 실제 문제가 확인된 항목만 고친다.
5. **STATE:** 필요할 때 `state-machine`으로 로딩, 데이터 없음, 오류, 네트워크 지연, 분류 진행, 확인 필요를 fixture로 표시. `break`로 긴 이름, 긴 금액, 대량 행, 좁은 뷰포트, 확대 및 빠른 연속 클릭을 시험. 두 스킬의 실제 환경 요구를 먼저 확인하고 임시 화면/파일을 정리한다.
6. **VERIFY:** UI 변경 관련 `interface-review`로 diff를 점검하고 해당 테스트·브라우저 확인을 수행. 반응형 데스크톱/모바일, 키보드 탐색, 텍스트 대비, 누락/중복/잘못된 금융 표시, 기존 주요 동선을 확인. 시각적 변화가 있으면 동일 뷰포트 변경 전/후 화면 증거를 기록. 테스트 실행 없는 PASS 금지.
7. **DELIVER:** 별도 PR에 변화 파일, 스킬별 실제 사용/미사용, Before/After, 테스트·CI·브라우저 증거, 미검증/회귀 위험, SHA를 기록. 배포는 AGENTS.md의 기존 권한·QA/안전 게이트만 따른다.

## 4. 완료 수락 기준
- UI 요구사항별 **COMPLETE / PARTIAL / BLOCKED / FAILED**와 근거가 있다.
- 금융·여행·Google/OTA 원본·DB·API 변경 0건 또는 별도 명시적 승인 및 보호 검증.
- 기존 주요 화면 기능·테마·상태 표현 보존, 모바일/데스크톱 시각 및 키보드 접근성 검증.
- 대상 화면별 재현 가능한 수정과 UI 영향 테스트. 실제 검사 결과와 미실행 항목을 분리.
- 스킬 설치, 진단, PR 생성, 코드 병합, 운영 배포를 **각각 다른 완료 상태**로 보고한다.

## 5. 에이전트 시작 지시문
> COST의 현재 사용자 요청에 해당하는 UI만 개선한다. 먼저 AGENTS.md·현재 상태·이 명세·해당 UI 계약을 확인하라. Jakub Krehel 스킬 사용 가능 여부를 검사하고 better-interface로 기준 화면을 진단하라. 문제에 맞는 better-layout/typography/accessibility/writing만 선택해 최소 구현하고 필요 시 state-machine·break로 예외를 테스트한 뒤 interface-review와 실제 브라우저·영향 테스트를 수행하라. 금융 데이터/운영 DB/API·수동 교정은 보호한다. 실제 diff·테스트·SHA 없이는 완료라고 하지 말고 별도 PR로 제출하라.
