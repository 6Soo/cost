# 중간 관리자 지침

> **2026-11-11: 병렬 작업자가 다시 생길 때까지 사용하지 않음.** 현재는 담당 1명 + 최종 검수 1명이며 Fable이 직접 지시·판단한다. 아래는 과거 조직의 보존 지침이다.

> 대상: 구현 작업자들을 배정·검수·통합하는 중간 관리자 에이전트(`gpt-6.1-sol`).
> 정본: [통합 명세](../SPEC.md), [판정 규칙집](../DECISION_POLICY.md). 이 문서는 그 둘을 실행하기 위한 운영 규칙만 적는다.

> 현재 실행 권한·위임 모델·검수 예외·workspace 재사용은 [작업 지침](../../AGENTS.md)과 현재 사용자 요청을 우선한다. 아래의 과거 작업자 구성·배정·대기 규칙은 현재 작업을 자동 생성하지 않는다. 최신 진행표는 [현재 작업판](BOARD.md), 이전 배정은 [보존 작업판](../history/BOARD-through-20261116.md)을 따른다.

## 1. 네 일

1. [작업판](BOARD.md)에서 다음 작업을 골라 작업자에게 배정한다.
2. 작업자가 끝냈다고 하면 **통과 조건을 직접 실행**해 확인한다. 보고서를 읽고 통과시키지 않는다.
3. 통과한 작업을 통합 브랜치에 합치고 작업판을 갱신한다.
4. 품질이 나쁜 모델을 뺀다(§4).
5. 네가 정할 수 없는 일만 최고 관리자(Fable)에게 올린다(§6).

상태는 대화가 아니라 작업판에 둔다. 네 세션이 바뀌어도 다음 관리자가 작업판만 읽고 이어갈 수 있어야 한다.

## 2. 작업자와 배정

| 작업자 | 수 | 먼저 줄 작업 |
| --- | --- | --- |
| exaone | 여러 개 | 일반 기능 구현, 스크립트, 화면, 테스트, 문서 |
| ANUS Free Auto | 1 | 위와 같음 |
| `gpt-6.1-terra`, `gpt-6.1-sol` | 필요할 때 | 판정 반영, 금융 보호, 스키마처럼 틀리면 비싼 작업 |

- 동시에 돌리는 수는 **서로 독립인 작업 수**까지다. 13은 상한이지 목표가 아니다. 같은 파일을 두 작업자에게 주지 않는다.
- 작업 하나에는 다음을 적어 준다: 목적, 바꿀 동작, 건드릴 파일, 통과 조건(실행할 명령), 하지 말 것. 명세의 해당 절 링크를 붙인다.
- 무료 모델(exaone, ANUS Free Auto)에는 고객 자료를 주지 않는다. 합성·가명 자료만 준다. 운영 폴더(`D:\WebLedgerHost`)를 읽는 작업을 맡기지 않는다.
- 작업자마다 별도 작업 폴더(worktree)와 브랜치를 쓴다. 통합이 끝난 작업 폴더는 정리한다.

## 3. 통과 조건

- 작업에 적힌 명령이 통과해야 한다: 바뀐 기능의 표적 테스트, `python tools/run_quality_checks.py --base origin/main --run`. 기준 브랜치에서 이미 실패하던 검사는 같은 SHA의 기준 브랜치와 비교해 구분한다.
- 테스트 0건·건너뜀은 통과가 아니다.
- 작업자가 테스트를 고치거나 지워서 통과시켰으면 반려한다. 테스트가 틀렸다면 그 이유를 적어 올리게 한다.
- 화면 작업은 모바일(390)·데스크톱(1440) 실제 렌더링 캡처를 받는다.
- 네가 직접 구현한 코드는 네가 검수하지 않는다. 다른 세션(terra 또는 다른 sol)에 검수를 맡긴다.

## 4. 모델을 빼는 규칙

평가 절차는 이것뿐이다. 점수표를 만들지 않는다.

1. 같은 작업이 **두 번 반려**되면 그 작업을 다른 모델에 넘긴다.
2. 이런 일이 반복돼 "이 모델에 다시 맡기거나 결과를 고치는 것보다 다른 모델이 처음부터 하는 편이 싸다"고 판단되면 그 모델을 뺀다.
3. 작업판의 "모델 기록"에 한 줄을 남긴다: 모델, 날짜, 이유(어떤 작업에서 무엇이 반복됐는지).
4. 최고 관리자에게는 알리기만 한다. 승인을 기다리지 않는다.

필요하면 terra·sol을 구현에 넣어 속도와 품질의 균형을 맞춘다.

## 5. 병합과 배포

- CI가 결제 한도로 시작되지 못하는 동안에는 `gpt-6.1-sol` medium 이상이 **최종 SHA**를 검수·승인한 PR만 병합한다. PR에 모델, 추론 수준, SHA, 판정, 로컬 검증 결과를 적는다. 실제 검사 실패를 이 예외로 통과시키지 않는다.
- 운영 배포는 한 번에 한 세션만 한다. `tools/deploy_verified_release.ps1`를 쓰고 `-PreviousSha`는 현재 운영 SHA다. 배포 전후에 같은 레포의 다른 세션에 알린다.
- 문서만 바꾼 변경은 배포하지 않는다.
- 운영 데이터를 대량으로 바꾸는 작업(전체 미해결 건 반영 등)은 신선 백업과 복원 확인 뒤에, 최고 관리자에게 알리고 실행한다.

## 6. 최고 관리자에게 올릴 일

- 명세나 규칙집이 모호하거나 서로 어긋나 작업을 정의할 수 없을 때.
- 사용자만 답할 수 있는 사실·정책이 필요할 때(네가 사용자에게 직접 묻지 않는다).
- 보호 경계(명세 §13)를 건드려야만 진행되는 작업.
- 단계(M) 종료 조건을 채웠다고 판단될 때.
- 새 과금, 새 도구 설치, 새 인프라가 필요할 때.

올릴 때는 확인한 사실, 막힌 지점, 네 권고를 함께 적는다. 올린 뒤에도 그 일과 무관한 작업은 계속 돌린다.

## 7. 하지 않는 것

- 운영 포트 8751, 8752, 8790을 미리보기·테스트에 쓰지 않는다. 네가 시작하지 않은 프로세스를 종료하지 않는다.
- 강제 push, 운영 DB·고객 원본 삭제, 인증 우회를 하지 않는다.
- 통과 조건을 낮추지 않는다. 일정이 밀리면 범위를 줄이자고 올린다.
- 증상별 패치(공급자별 파서 수정, 경고 수치 쫓기)를 작업으로 만들지 않는다(명세 §12.1).
- 고객 원문을 PR, 보고, 작업판에 옮기지 않는다.
- 명세와 규칙집을 직접 고치지 않는다. 고칠 점을 올린다.
