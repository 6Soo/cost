# 이메일(Gmail) 연동 설계 — `kkokkohero6@gmail.com`

이미 hanmail → Gmail(`kkokkohero6@gmail.com`) 수집이 구성돼 있고 결제 메일이 다수 쌓여 있다.
이를 되살려 **로드맵 P2(OTA 실사용일)·P3(페이 내역)** 를 지금 붙인다.

## 핵심: Gmail도 Apps Script로 (샌드박스 아님)

- 이 자동화 환경은 구글 접근이 차단됨 → **GmailApp/SpreadsheetApp(Apps Script)** 로만 접근.
- GmailApp은 **스크립트를 실행하는 계정의 메일함**을 읽는다.
  → 결제 메일이 있는 `kkokkohero6@gmail.com` 에서 실행해야 그 메일함을 읽을 수 있음.

### 계정 배치 (확정)
**`kkokkohero6@gmail.com` 단일 계정에서 전체 자동화 실행.** 공유 0회.
- 이 계정이 **결제 메일함**과 **시트 5개를 모두 소유** → 이상적 구성.
- GmailApp: 결제 메일 파싱 (같은 계정 메일함).
- SpreadsheetApp.openById: 5개 시트 접근 (소유자라 추가 공유 불필요).

```
kkokkohero6@gmail.com
 ├─ 메일함  → GmailApp 파싱 (OTA·페이·카드 결제/예약 메일)
 └─ 시트 5개 소유 → openById 로 읽기/기록/색칠
```

> 남은 과제는 **`kkokko-hero@hanmail.net`(3820 전용) 메일을 이 계정으로 끌어오는 것** 하나뿐. 아래 참고.

## 되살리기 체크리스트
1. `kkokko-hero@hanmail.net` → `kkokkohero6@gmail.com` 유입 구성 (아래 "hanmail 연동" 참조).
2. Gmail 필터로 결제/예약 메일에 라벨 **`결제데이터`** 자동 부여
   (3820 유입분은 `to:kkokko-hero@hanmail.net` 조건으로 하위 라벨 `3820` 추가).
3. Apps Script를 `kkokkohero6` 계정에 배치 + **시간 기반 트리거**(예: 6시간마다) 등록.

## hanmail(`kkokko-hero@hanmail.net`) 연동 — 상세

Gmail은 스크립트 실행 계정의 메일함만 읽으므로, hanmail 메일을
`kkokkohero6@gmail.com` 으로 **유입**시켜야 한다. 두 경로를 함께 쓴다.

### A. 앞으로 오는 메일 — Daum 자동전달 (실시간, 권장)
1. PC 브라우저로 Daum 메일(`kkokko-hero@hanmail.net`) 로그인.
2. 우측 상단 **⚙ 환경설정 → 자동전달**.
3. 전달 주소에 `kkokkohero6@gmail.com` 입력, **전달 사용** 체크, **원본 보관** 체크, 저장.
4. (확인메일이 오면) Gmail에서 확인 링크 클릭.
5. Gmail → 검색창에 `to:kkokko-hero@hanmail.net` → **필터 만들기** →
   라벨 `결제데이터` + `3820` 적용.
> 장점: 즉시 전달·단일 메일함. 단점: **활성화 이후 신규 메일만** 전달됨(과거분 X).

### B. 이미 쌓인 backlog — Gmail POP3 가져오기 (일회성)
1. Daum에서 POP3 켜기: Daum 메일 **⚙ 환경설정 → IMAP/POP3 → "POP3/SMTP 사용" ON**.
   (2단계 인증 사용 중이면 **앱 비밀번호** 발급받아 사용)
2. Gmail → **⚙ 모든 설정 보기 → "계정 및 가져오기" 탭 → "다른 계정에서 메일 확인" → 메일 계정 추가**.
3. `kkokko-hero@hanmail.net` 입력 → **"다른 계정에서 메일 가져오기(POP3)"** 선택.
4. 서버 정보:
   - POP 서버: `pop.daum.net` · 포트 `995` · **SSL 사용 체크**
   - 사용자명: `kkokko-hero@hanmail.net` · 비밀번호: Daum 비번(또는 앱 비번)
   - **"가져온 메일에 라벨 지정" → `3820`** 선택
5. 추가하면 Gmail이 POP3로 서버의 기존 메일을 끌어옴(오래된 것부터 수 회에 걸쳐).
> 참고: POP3는 서버 보관분만 가져오며 전량 보장은 아님. 대량이면 며칠 나눠 수집될 수 있음.

**결론:** A(자동전달)로 앞으로를, B(POP3)로 과거분을 커버 → 3820 메일이 모두
`kkokkohero6` 로 모이고 `3820` 라벨로 식별됨. 이후 파서가 동일하게 처리.

## 여러 한메일 계정 유입 (대표가이드 등)

`kkokkohero6` **한 계정**이 여러 한메일을 모두 읽어올 수 있다.
- **POP3 가져오기**는 Gmail당 **최대 5개 외부 계정** 추가 가능(위 B를 계정마다 반복).
- **자동전달**은 개수 제한 없음(위 A를 계정마다 반복).

계정을 **라벨로 구분**하면 정산 시 카드 주인/성향 매칭에 쓸 수 있다.

| 유입 계정 | 사용자 | 라벨 | 성향 |
|---|---|---|---|
| `kkokko-hero@hanmail.net` | 본인(김주형) | `3820` | 기타비용 위주, 큰 금액=항공료(`CARD_PROFILES['3820']`) |
| (대표가이드 한메일) | 대표가이드 | 계정별 라벨 | 숙박비 등 여행성(`DEFAULT_CARD_PROFILE`) |

> 분류 엔진은 **카드 RAW의 뒷4자리**로 주인 성향을 적용한다(라벨은 메일 매칭·식별 보조).
> 현재는 `3820`만 본인이고 **그 외 모든 카드는 대표가이드**로 자동 처리된다(`DEFAULT_CARD_PROFILE`, 여행성).
> 추후 가이드별로 카드가 하나씩 생기면 뒷4자리를 `CONFIG.CARD_PROFILES`에 등록한다.

## 수집 파이프라인
```
Gmail(label:결제데이터 -label:처리완료)
  → 발신자별 파서로 구조화
  → '메일수집' 스테이징 시트에 append
  → 메시지에 '처리완료' 라벨 부여 (멱등/증분)
```

### 구조화 레코드 (스테이징 시트 열)
| 열 | 내용 |
|---|---|
| source | naverpay / kakaopay / agoda / booking / tripcom / card ... |
| paidDate | 결제일 |
| useDate | **실사용일**(OTA 체크인/탑승). 없으면 공란 |
| merchant | 시설/항공사/가맹점명 |
| item | 항목 요약(항공권/숙박 등) |
| amount | 금액(원) |
| messageId | Gmail 메시지 ID(중복 방지 키) |

## 장부와의 매칭 (보류 건 해소)
- **OTA 보류건**(RAW의 트립/아고다/부킹): 스테이징의 `amount`(+가맹점)로 매칭 →
  `useDate`(실사용일)를 찾아 **그 날짜로 장부 전기** → "결제≠사용" 문제 해결.
- **3820 페이 보류건**: 스테이징의 `amount`(+결제일 근접)로 매칭 →
  `item`으로 계정과목/여행 귀속 확정.

### 남은 파서용으로 받을 것
- **부킹닷컴 / 네이버페이 / 카카오페이** 예시 메일 각 1통 (발신자+제목+본문).

### 유의점(설계 반영)
- **트립 예약번호**엔 zero-width 문자가 섞여 있어 숫자만 추출(`digits()`).
- **트립 항공권**은 본문에 금액이 없음(전자영수증 PDF) → 카드내역 금액과 매칭.
- **아고다는 JPY** → 카드(원화)와는 날짜+가맹점 위주 매칭.
- **취소/환불 메일**은 `type=refund`, 금액 음수 → 장부 매출취소/반대분개로 연결.
- **체크인 임박 알림** 등 비결제 메일은 파서에서 `null` 반환해 스킵.
