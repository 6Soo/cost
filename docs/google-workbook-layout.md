## 2. 실제로 확인한 여행 시트 구조

**사용자 확정(2026-10-11): 메인 장부의 `매출자료 양식_rev`가 신규 여행 시트의 유일한 기준 템플릿이다.** 신규 기능 구현·복사 출력·검증은 이 양식 하나를 기준으로 한다. 과거에 관측된 상이한 레이아웃은 구형 양식의 잔재이며 사용자가 추후 직접 정비한다. **레거시 레이아웃을 위해 호환 파서/자동 변환기/별도 복사 경로를 만들지 않는다.**

기준 템플릿은 위쪽 **수입 내용**, 아래쪽 **지출 내용**, 맨 아래 **합계 및 회사수익인식**이다. 신설 시트에서는 데이터 행 추가/수식 범위 변경이 있을 수 있으므로 기준 **열 계약을 유지하되 절대 행 번호를 하드코딩하지 않는다**. 비표준 구형 시트가 그대로 남으면 임의로 매핑하지 않고 '구형 양식/확인 필요'로 표시하여 최종 장부 조회가 완전하다고 주장하지 않는다.

### 공식 기준: `매출자료 양식_rev`의 B:H 연속 7열 구조

확인된 예:
- 메인 **0630_오제**: 수입 제목 B6/헤더 B7:H7, 지출 제목 B45/헤더 B46:H46.
- 메인 **1005_경주**: 수입 제목 B4/헤더 B5:H5, 지출 제목 B30/헤더 B31:H31.
- 보관 **0404_에히메의 사본**: 수입 제목 B6/헤더 B7:H7, 지출 제목 B25/헤더 B26:H26.
- **유일한 신규 여행 기준 템플릿 `매출자료 양식_rev`**: 수입 제목 B4/헤더 B5:H5, 지출 제목 B20/헤더 B21:H21 (템플릿이며 실거래 장부가 아님). 템플릿 실측 수식: 수입 합계 C18 `=sum(H6:H17)`, 지출 합계 C33 `=SUM(H22:H32)`, 회사수익 C35 `=C18-C33`. 이 행 번호는 원본 양식의 현재 위치이지 앞으로 모든 여행 탭의 고정 위치가 아니다.

지출 헤더/열: **B 거래일자 | C 항목 | D 내용 | E 기간 | F 예약번호 | G 증빙유형 | H 금액(원)**.

수입 헤더/열: **B 거래일자 | C 이름 | D 닉네임 | E 예약금 | F 잔금 | G 추가금 | H 금액(원)**.

수입 H열에는 실제로 SUM(E:G) 같은 행별 수식이 있다. COST가 읽는 것은 허용하지만 지출 복사 과정에서 수입/수식 영역을 덮어쓰지 않는다.

### 구형 양식 관측 기록: B:I 비연속 5열 구조 (신규 구현 대상 아님)

- 메인 **0909_제주**: 수입 제목 B6/헤더 B7·D7·F7·I7, 지출 제목 B24/헤더 B25·D25·F25·H25·I25.
- 보관 **0107_대만**: 수입 제목 B6/헤더 B7·D7·F7·I7, 지출 제목 B26/헤더 B27·D27·F27·H27·I27.

지출 헤더/열: **B 거래일자 | D 항목 | F 내용 | H 증빙유형 | I 금액(원)**.

중간 C/E/G 등은 빈칸·서식/병합 영역일 수 있다. **이 구형 시트에는 공식 템플릿의 7열 복사 결과를 붙여넣으면 안 된다.** 사용자가 직접 `양식_rev` 기준으로 수정할 예정이므로, COST가 별도의 레거시 호환 복사 또는 자동 변환을 구현하지 않는다.

수입은 B 거래일자, D 이름, F 내용(예약금/잔금), I 금액. A형의 수입 세부 구조와도 다르다.

### 의미와 탐지 규칙

- 사용자가 구어로 말한 “증빙내용”의 **실측 헤더는 “증빙유형”**이다.
- 실제 값은 **카드, 이체, 영수증, 세금계산서** 등이 관측됐다. 증빙값을 카드/이체/영수증 세 종류로 제한하지 않는다.
- **사용자 확정(2026-10-11): 지출 C열 `항목` = 결제처·가맹점명·지급처(예: 아고다·트립닷컴·현지 식당), D열 `내용` = 비용 분류(예: 숙박비·항공료·식비·차량비)**다. COST 내부 필드명이 같아도 이 의미에 맞춰 명시적으로 매핑하며, 원본 카드의 가맹점 문자열을 규칙 없이 덮어쓰지 않는다.
- 기간·예약번호는 A형에 있지만 B형에는 없다. 없는 열을 임의로 만들어 구글 표를 밀지 않는다.
- 신설 여행 탭은 `양식_rev` 기준의 동일한 열 계약을 전제로 하되 행이 늘어나면 수입·지출 시작과 끝은 달라질 수 있다. Google이 제공하는 rowCount(약 900~1,200)는 실제 장부 거래 행수가 아니다.
- **기준 양식의 ‘수입 내용’·‘지출 내용’·실제 헤더·총액/수익 계산 경계**로 읽을 범위와 붙여넣기 영역을 결정한다. 구형 레이아웃을 자동 호환시키지 않는다. 형식이 기준 양식과 다르거나 수식/병합 셀을 침범할 위험이 있으면 **HOLD/비표준 표시**한다.
- 붙여넣기는 사용자가 직접 한다. COST는 합계·수식 셀을 직접 갱신하지 않는다.

## 3. 수식의 권위와 관측 오류

- 메인 0630_오제: 수입 H의 SUM(E:G), 지출합계에 SUM(H47:H75), 회사수익에 수입-지출 수식이 관측됐다.
- 메인 0909_제주: 지출합계가 I열 대상(예: SUM(I26:I28))으로 계산된다.
- **메인 3분기_기타비용 C50에는 실제 “=#REF!-C48” 수식이 있으며 결과가 #REF!**이다. C48의 지출합계는 SUM(H6:H47)이다. 이 부분을 원본 변경 없이 발견했다. COST는 이 결과를 정상 회사수익 또는 0원으로 위장하면 안 된다. 실제로 오류인지 불필요한 템플릿 잔재인지는 사용자 판단 필요.
- Google의 집계 오류나 마감 후 수정은 COST가 무단으로 고치지 않고 원본 오류·최신 확인 시각을 그대로 드러낸다.

## 4. 정본 라우팅 / 분기 마감 이동

- 기본 정보: 어떤 여행 시트가 **어느 파일에 실제 존재하는지** 양쪽 탭 목록에서 확인한다. 월/분기만 보고 파일을 결정하지 않는다.
- **사용자 확정(2026-10-11): 여행 마감 완료의 유일한 업무 트리거는 해당 여행 시트가 활성 메인 Google 장부에서 과거/보관 Google 장부로 이동되는 시점**이다. COST는 **보관 장부에 실제 여행 시트가 확인되는 경우 마감 완료로 취급**하며, **여행 종료일·월·분기·수익 수식 존재·메인 장부에서 자체 결산 완료만으로는 마감 처리하지 않는다**. 따라서 메인에만 남은 여행은 출발일이 과거라도 미마감이다.
- **중복 공존과 마감은 별도 속성:** 동일한 실제 여행 시트가 **양쪽에 존재해도 보관본의 존재로 마감 완료 상태**이며, 정본 금액은 기존 확정대로 **메인 우선 + `확인 대상`**, 사용자가 정본을 변경할 수 있다. '마감 완료'가 '보관본 금액을 우선 집계'한다는 뜻은 아니다. Google 조회·데모 순위에서 한 여행은 항상 한 번만 반영한다.
- **실제 이동 시각과 관측 시각 구분:** 동기화로 보관본이 최초 확인된 KST 시각은 `마감 감지 시각`으로 기록할 수 있지만, Google에서 실제 이동한 정확한 시간이라고 주장하지 않는다. 보관 장부에 이미 있던 과거 여행도 적법한 여행 탭임이 확인되면 마감 완료로 볼 수 있다.
- 템플릿·총괄표·기타비용·프리랜서 대장이나 다른 여행과 우연히 이름이 비슷한 `의 사본`을 실여행의 보관 이동으로 오인하지 않는다. 여행 식별이 모호하거나 Google 보관본 조회가 실패하면 새로 마감 완료로 확정하지 않고 `확인 대상`으로 둔다. 원본 시트 이동·복사·삭제는 사용자만 수행하고 COST는 읽기 전용이다.
- **사용자 확정(2026-10-11): 동일 회계 여행이 두 파일에 동시에 존재하면 활성 메인의 여행 시트를 기본 정본으로 우선 선택한다.** 동시에 `확인 대상`으로 표시하고, 사용자가 COST에서 양쪽 내용을 비교·확인하여 정본 선택을 수동 조정할 수 있게 한다. 두 사본의 내용이 같더라도 중복 존재 자체를 확인 대상으로 표시한다. 금액이 다르다고 자동으로 보관본을 선택하거나 전체 조회를 중단하지 않는다.
- 두 사본의 파일 ID/탭 ID/읽기 시각/행수 및 합계 차이를 비교 가능하게 유지한다. **집계·확정 조회에는 선택된 사본의 수입·지출만 한 번 반영한다.** 정본 수동 선택은 기록·이력을 보존하고 이후 동기화에도 유지한다. 어느 쪽을 선택해도 Google 원본을 COST가 쓰거나 수정하지 않는다.
- 메인에서 해당 여행이 실제로 사라지고 보관본만 남으면 보관본을 읽되, 정본 원본 변경을 표시·기록한다. 다른 여행을 이름 유사성만으로 동일 여행이라 단정하지 않는다.
- “의 사본” 문구와 파일 수정시간은 단독으로 권위를 증명하지 않는다.
- Google 파일·sheetId는 복사/이동 과정에서 달라질 수 있으므로 **실제 회계 여행의 안정 식별 키**와 파일별 현재 sheetId를 따로 관리해야 한다. 제목만으로 유사 여행을 합치지 않는다.
- 같은 여행의 장부가 두 파일에 있다면 **메인 우선·확인 대상 표시·사용자 선택 조정 가능·수입/지출 두 번 합산 금지**. 내용이 달라도 선택 전에는 '양쪽 일치 검증 완료'로 표시하지 않는다. 누락된 시트를 분기 이동으로 추측해 자동 0원 처리하지 않는다.
- 파일이 읽히지 않거나 탭이 사라지면 마지막 정상 스냅샷의 날짜·오류 상태를 표시하고, 최근 확정 장부라고 주장하지 않는다.
- 분기 마감 후에도 보관 파일은 수정될 수 있어 변경 감지 후 해당 시트만 업데이트한다.
- 메인에서 사라진 시트가 보관에 들어와도 기존 카드 원본·사용자 확정·환불·OTA 연결을 삭제/덮어쓰지 않는다.

## 5. 다음 구현 전에 사용자 확인이 필요한 질문

1. **연도 판정 — 두 여행은 확정:** `0206_하쿠산`, `0302_야쿠시마`는 **2027년 출발**이다. 나머지 탭의 2027년 여부는 명시 근거로 식별한다. 상단 템플릿 문구만으로 연도를 정하지 않는다.
2. **열 의미 — 확정:** 공식 `양식_rev` 지출 C열 **항목=결제처·가맹점명·지급처**, D열 **내용=비용 분류**. 예: `아고다/숙박비`, `트립닷컴/항공료`, `현지 식당명/식비`, `렌터카 업체명/차량비`.
3. **출력 단위 — 사용자 확정(2026-10-11): 카드와 영수증 지출은 실제 거래 한 건당 Google 지출표 한 행으로 출력한다.** 같은 날짜·가맹점·항목·금액이라도 서로 다른 실제 결제이면 각각 독립 행이다. 가맹점/항목/기간 기준 집계·병합·묶음 출력은 제공하지 않는다. 영수증 한 장은 기본 한 건이며, 법인카드 영수증이 이미 존재하는 카드 매입과 동일 거래로 확인된 경우에 한해 카드 지출 행 하나만 출력하고 영수증은 증빙으로 연결한다. 취소·환불도 원거래와 임의 합산·상쇄해 거래 행을 숨기지 않는다. 동일 원본 파일 재수신으로 발생한 중복은 기존 거래 ID·중복 방지 규칙대로 처리한다.
4. **양쪽 파일 중복 탭 — 사용자 확정:** **활성 메인 우선**, 보관본도 보존하고 `확인 대상`으로 표시한다. 사용자는 두 장부 차이를 비교하고 **정본 선택을 수동 조정**할 수 있다. 선택된 한 쪽만 조회·집계하며 Google 원본은 자동 수정하지 않는다. 우선순위 질문은 해결됐다.
5. **별도 관리 시트:** 분기 기타비용, 프리랜서 지급대장, 행사경비총괄표는 웹 제3자 조회에서 어떤 수준까지 공개해야 하는가?
6. **증빙의 레거시값:** 신규 법인카드 지출 복사값은 “카드”, 개인/현금 영수증은 “영수증”으로 하되, 과거 “영수증” 레거시 항목은 그대로 둘 것인가?
7. **수식 오류:** 메인 3분기_기타비용 C50의 #REF!는 별도 수정해야 할 오류인가, 사용하지 않는 템플릿 칸인가?

## 6. 완료 범위

- **실측/사용자 확인 완료:** 두 Google 원본의 제목/MIME/타임존/탭 목록(각 26/43), 기준 `매출자료 양식_rev`의 헤더·수입/지출·합계 수식 구조, 대표 과거 양식과 차이, 실제 증빙값, 기타비용 C50의 계산 오류, `0206_하쿠산`·`0302_야쿠시마`의 2027년 귀속. 공식 기준은 `양식_rev` 하나이며 구형 양식 호환 구현은 범위 밖.
