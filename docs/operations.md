## 2026-10-04 취소 정산과 사용자 보류의 기록 차단

OTA 여행 미배정 16건을 취소·환불 관리 13건, 실제 환불 확인 대기 1건, 사용자 보류 1건, 예약·결제 연결 확인 대기 1건으로 분리했다. 상태는 같은 SQLite의 `transaction_review_holds`에 원행 ID와 원문 hash로 저장한다. 기존 거래·분류·사용자 결정·원본 파일은 바꾸지 않았다. 확인되지 않은 거래를 새 금액이나 환불 전표로 만들지 않았다.

카드 검토 화면에 취소·환불과 보류 항목을 별도로 표시한다. 이 행들은 일반 질문 건수와 일반 비용 기록 가능 목록에서 제외하며, 기록 직전에도 동일 보류를 다시 검사한다. 답변 저장만으로 보류를 해제하지 않는다. 사용자가 자료 확인을 마쳤다는 별도 선택을 한 경우에만 같은 답변 저장 트랜잭션에서 해제한다. 원문 hash가 달라진 보류는 자동 해제하지 않는다.

운영 복구 사본에서 기존 모든 테이블 불변과 반복 저장 결과를 확인했고, 실제 로그인 웹 API에서 보류 16건 모두 `review_hold`로 기록 차단되는 것을 확인했다. 모바일 폭 390에서 보류 표시와 해제 선택을 확인했고 가로 넘침은 없었다. 카드 파이프라인 검사 116개와 화면 검사 8개가 통과했다. 적용 증거는 `.local-archive/ota-rematch-20261004/review-holds-result.json`이다.

현재 카드 원행의 마지막 승인일은 국민 7월 15일, 기업 7월 14일, 하나 7월 20일이다. 8월 1일 항공권 실제 환불 원행은 현재 입력 자료에 없다. 사용자에게 8월 이후 카드 사용·취소 자료의 저장 위치를 질문했다. 이 사실을 실제 환불이 없다는 뜻으로 해석하지 않는다.

## 운영 데이터

실제 카드 파일 다섯 개에서 비용 이벤트 5,328건을 읽었다. 검증된 양식과 기존 카드 정규화 결과를 거래별 날짜, 가맹점, 카드, 부호 있는 금액으로 대조했다. 차이는 없었다. 분할 거래를 포함한 이벤트 수이므로 과거 수기 검토 행 수와 같지 않다.

과거 최대 자동 처리 결과의 5,328건을 현재 원본 거래와 전부 대조했다. 현재 검토 대상은 2026-04-01 이후 1,676건이며 비용 항목은 전부 분류했다. 여행 배정은 기존 631건에서 1,391건으로 760건 늘었다. 나머지 285건은 공통 경비 또는 여행 미배정이다. 사용자 지시에 따라 정리 완료된 2025년과 2026년 1분기 3,652건은 내부에 보존하고 화면과 신규 전기에서 제외했다. 새 카드 처리 경로가 활성화된 장부 화면에서는 과거 수기 원천을 별도 미리보기로 노출하지 않는다.

2026-10-03에 사용자가 추론 배정을 허용한 뒤 기존 규칙 632건, 현재 원행에만 적용되는 추론 1,026건, 사용자 국가 예외 18건으로 나뉜다. 추론 중 확신이 낮은 거래도 기록을 막지 않으며, 카드 검토 화면에서는 무엇을 확인해야 하는지 기존 근거에 따라 구체적으로 표시한다. 사용자가 수정하면 해당 답변을 우선한다. 기존 확정 답변, 검증된 예약 배정, 원본과 명시 일정은 보호한다. 추론을 미래 거래에 대한 일반 규칙이나 확인된 예약 사실로 바꾸지 않는다.

사용자의 명시 답변에 따라 조지아 11건과 카자흐스탄 7건은 모두 5월_유럽에 배정했다. 현재 거래 원행을 지정한 예외 규칙으로 저장했으며 여행 일정 자체를 늘리지는 않았다.

예약 메일 368개를 읽고 인증된 예약·결제 사실 336개를 추출했다. 원본과 유일하게 맞는 104건은 숙박 80건, 항공 12건, 렌터카 한 건, 교통 열한 건이다. 이 수치는 보존 기간을 포함한 메일 대조 결과이며 현재 검토 범위의 추가 자동분류 수와 같지 않다. 동일 금액으로 여러 예약이 남은 20건은 상품 종류만 제안하고 특정 예약 연결은 보류했다.

유럽 여행은 취소되지 않은 숙박 예약 12건의 명시 기간인 2026-05-20~2026-06-10을 반영했다. 취소된 숙박 두 건은 제외했다. 운영 여행 24개 모두 명시 일정과 원본 hash를 확인했다. 기존 저장 요청 한 건과 감사 이력 47건을 보존했다. 기존 회사와 담당자 정보도 유지했다.

신규 장부 기록은 아직 0건이다. 실제 자료는 카드 처리 화면에 들어 있으며, 사용자가 미리보기를 확인하고 기록 버튼을 누르기 전까지 실제 장부를 늘리지 않았다. 자동분류에는 비용 항목만 정해져 여행이 미배정인 결과도 포함되므로 자동 여행 배정 건수로 해석하지 않는다. 기존 자유 형식 요청의 원문은 그대로 보존했다.

추가 답변에 따라 아성다이소는 공통 사무용품비로, 질문한 어드벤처코리아의 결제 네 건과 취소·환불 두 건은 여행상품비로 분류했다. 다이소는 질문한 미확정 열 건뿐 아니라 이미 항목이 있었던 한 건에도 같은 재사용 규칙을 적용했다. 클룩 일곱 건은 유료 기차표와 무료 티켓 수령 안내를 구분해 메일로 확인했다. 세 건에는 이용일이 6월 28~29일로 적혀 있고 두 건의 환불 메일이 있다. 37,300원은 첨부 바우처 네 페이지까지 확인해 6월 29일의 두 명 기차표와 발급 수수료임을 확인했다. 추론 허용 후에는 같은 카드 원행의 과거 배정과 이탈리아 이동 내용을 근거로 5월_유럽에 낮은 확신의 추론으로 배정했다. 실제 이용일 원문은 그대로 보존하고 실제 탑승이나 취소는 확정하지 않았다. 클룩에는 렌터카도 있으므로 공급자 전체를 교통비로 분류하지 않는다.

Windows 화면 제어 도구도 초기화 단계에서 `failed to write kernel assets`와 경로 오류를 두 번 반환했다. 실제 인증서 암호 입력과 로그인은 여전히 미완료이며 외부 제품 내부 수정이 필수라고 단정하지 않는다.

2026-10-05 사용자 지시 `무인로그인 수행`에 따라 새 실행에서 현재 계정과 보관함, 회사 공동인증서를 다시 확인했다. 저장 항목의 기존 주소를 유지하면서 국민 기업 로그인 주소를 추가했고, 암호 필드는 변경하지 않았다. 실제 PC에서 Delfino 실행을 확인했으며 설치 안내를 닫은 뒤 회사 인증서가 선택됐다. 공식 자동입력은 다시 입력란 탐지 오류를 반환했다. 이어서 실제 암호 칸 클릭과 공식 키보드 입력전환 버튼 클릭으로 입력란 포커스까지 확인했지만 저장 로그인 제안이 나타나지 않았고 암호도 비어 있었다. 따라서 로그인과 새 다운로드는 실패 상태다. 이번 실행 기록은 `.local-archive/card-downloads/20261005T011500836Z-unattended-login/login-result.json`이다. 암호 원문 조회, 보안 속성 변경, 재부팅, 업데이트나 재설치는 하지 않았다.

## OTA 메일 처리 통합

메일 처리를 `app/ota_mail.py`로 통합했다. 실행과 기존 호출 호환은 `tools/match_booking_mail.py`, 분류 규칙 반영은 `tools/recover_history_rules.py`가 담당한다. 원화와 외화 숙박 대조를 같은 결과에 연결하고 규칙과 예약 근거를 원행 해시로 연결했다. 인증 도메인, 메일 중복과 본문 충돌, 이용기간 충돌, 취소 예약, 실제 복수 카드 거래와 외화 소수점을 검증한다. 상세 흐름과 실행 방법은 [OTA 메일 처리](ota_mail.md)에 정리했다.

보존 메일 631개를 재생해 기존 대조 106건을 유지했다. 상품 종류만 확인한 거래 20건과 취소 메일이 있는 연결 예약 12건을 구분했다. 검사 107개가 통과했으며 운영 복구 사본 검증과 재시작 후 준비 상태·실제 로그인 카드 조회가 정상 응답했다. 운영 DB의 업무 테이블과 기존 분류는 변경하지 않았다. 새로운 분석 결과의 취소 표시는 기존 거래의 일괄 변경이나 실제 장부 전기로 적용하지 않았다.

사용자 요청으로 미확정 OTA 원행 전체 434건을 새 메일 처리 체계로 재분류했다. 예약 대조 106건과 상품 종류 확인 20건을 반영하고 취소 메일이 있는 12건의 여행 배정을 모두 해제 상태로 확인했다. 기존에 여행이 붙어 있던 취소 거래 10건과 이용기간이 맞지 않는 숙박 1건의 배정이 해제되어 미배정은 27건에서 38건으로 바뀌었다. 신규 여행 배정은 0건이다. 원본 금액과 취소·환불 거래를 그대로 보존했다.

## 실행 데이터 루트

2026-10-06 일반 작업 계정에서 운영 설정 파일 접근이 거부되는 문제를 해결했다. 관리자 권한으로 기존 접근 권한을 백업한 뒤 `D:/WebLedgerHost/config`에는 해당 계정의 읽기·탐색 권한만, `real-review.json`과 `card-flow.json`에는 읽기 권한만 추가했다. 기존 소유자와 다른 계정의 권한을 유지했고 설정 파일의 SHA256이 변경되지 않았음을 확인했다. 기존 권한 백업은 `C:/AX/cost-access-repair-20261006/acl-before.json`이다.

일반 권한으로 두 설정 JSON을 읽고 `configured_readonly_flow()`를 실행해 운영 거래 5,328건과 장부 기록 0건을 조회했다. 운영 DB는 읽기 전용으로 열었다. 비밀값 폴더의 권한 확대, 운영 파일 내용 수정, DB 쓰기, 서비스 재시작은 수행하지 않았다. 이 기록은 접근 문제 해결이며 새 OTA 코드의 운영 반영 완료를 뜻하지 않는다.

실행 시 `WEBLEDGER_DATA_ROOT`는 지속 디스크에 마운트된 절대 경로를 지정한다. 예를 들어 Linux에서는 `/srv/web-ledger/data`를 지속 볼륨에 연결하며, 현재 Windows 운영 데이터 루트는 `D:/WebLedgerHost/data`다. 상대 경로·임시 디렉터리·소스 체크아웃 안 경로는 운영에서 거부된다. Procfile 시작 명령은 이 값을 환경 변수로 전달하며 `--data-root` 인자를 사용하지 않는다.
