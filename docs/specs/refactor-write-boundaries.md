## Source facts and limits

The paths above trace the host dispatch and the available persistence boundary. OTA backend persistence and Google provider reads cross injected/module boundaries, so those named OPEN_QUESTIONs remain; no runtime claim is made for those indirect edges. `access_control.py` defines role/session/access rules and schema constraints; `ledger_store.py` contains transactional SQL, revision/request tables, and audit/outbox helpers; `ops.py` includes health and recovery/readiness helpers.

Use the CLI to generate a machine-readable candidate inventory:

```powershell
python tools/audit_write_boundaries.py --pretty
```

The output deliberately separates `STATIC_CANDIDATE`, `STATIC_NONWRITE`, and `OPEN_QUESTION`. SQL output contains verb/table metadata only; it never includes statement text or SQL literal contents. SQL comments, CTEs, semicolon batches, and dynamic SQL return `OPEN_QUESTION`. Path/read/encoding/parse failures are returned in the JSON `errors` array and produce exit code 2. It does not claim that a decorator protects a route merely because its name resembles an auth control. Aliases, dynamic dispatch, indirect calls, framework hooks, and transaction behavior require manual confirmation. R1 runtime/DTO extraction is outside this R0 artifact.
