## A-최신. 자동화 검증 경계 (2026-08-06 사용자 확정 — 충돌 시 최우선)
- **수기장부와 과거 분류값은 학습·후보 생성용일 뿐 증거가 아니다.** 앞으로 수기장부가 없어도 동작해야 하며, 과거 답안을 재실행해 같은 값이 나오는 것은 검증으로 인정하지 않는다. 이 원칙은 아래 A1·P8·P10·P11·P15 등 수기장부에 권위를 주던 옛 규칙을 대체한다.
- 과거 2분기 방식에서는 **원천 완전성, 카드 원행·승인번호, 예약번호/PNR, 정확금액, 서비스일, 그룹 건수, 취소 원거래, 중복·충돌 검사**만 검증 절차로 계승한다. 수기 라벨·과거 확신도·가맹점+근사금액·결제일만의 여행배정은 계승하지 않는다.
- 자동 확정은 `여행 귀속(allocation_target)·계정(account)·비용 성격(cost_type)` 세 축만 다룬다. **부가세(vat_tag)는 분류·미해결·Gate 5 조건에서 제외**하며 신고 판단은 세무법인에 맡긴다.
- 일반적인 ±2% 차이는 근거가 아니다. 정확금액 또는 원천에 명시된 할인·수수료·환율 조정식이 있어야 금액 일치로 승격한다.
- 후보 생성 → 현재 원천증거 1회 고정 → 축별 독립검증 → 충돌 없는 건만 승격 → 마지막 전체집계 1회의 순서로 실행한다. 중간 단계마다 5,328건 전체검사를 반복하지 않는다.
- 카드 엑셀은 한 실행에서 한 번만 파싱하고 그 스냅샷을 적재·검증에 공유한다. 실행 종료 직전 변경 여부는 엑셀을 다시 해석하지 않고 원본 바이트 해시만 재확인한다.

- 사용자가 확인한 뒤에만 임시 여행 탭을 확정 상태로 승격한다. 카페 학습자료와 일반 과거 분류값은 계속 학습용으로만 취급한다.

## A0. 여행사 순액신고 기준 (2026-07-20 재학습 — 최우선 개념)
- 여행사 부가세 = **순액과세**. 과세표준(매출) = **여행알선수수료(마진) = 총수입 − 여행경비**. 총액(gross) 아님.
- 항공·숙박 등 여행경비는 **고객 대행(수탁) 성격 → 매입세액공제 대상 아님**. 순액 계산의 **차감항목**일 뿐.
- ⇒ 비용은 **여행(실체)별 전액 귀속**, 결제 분기 무관. 분기별 분류 범위·분기 간 중복 개념을 사용하지 않는다. 선결제·환불도 실제 여행과 전 기간 관계로 연결한다. 워크북=여행별 순액(수입−여행경비) 산출기.
- 선결제 누락 시 여행경비 과소→순액(마진) 과대→세액 과대. 완전성이 곧 정확한 절세.

## A-최신-여행분류예외-2. 현재 카드의 직접 여행분류와 임시 레지스트리 (2026-08-08 사용자 확정)

1. 여행 분류가 현재 카드 원자료만으로 직접 가능하면 자동으로 임시 대상에 제안한다. 예: `0107_대만`. 이 제안은 `needs_review`이며 사용자 확인 전에는 최종 배정·배분·전표·환불상속에 사용하지 않는다.
2. 수기장부의 **여행 탭 분류 자체**는 강한 분류 힌트로 사용할 수 있다. 단, 수기 행의 금액·가맹점·기재내용을 현재 카드의 거래증거로 승격하지 않는다. 현재 카드의 발급원천·이용일·양수금액과 수기 여행 탭이 1:1로 맞을 때만 임시 대상 제안을 만들고, 건수 불일치·대상 충돌은 `여행_미배정` 검토로 둔다.
3. 현재 카드의 새로운 임시 여행 클러스터는 같은 발급원천·카드 식별자·국가·지역에서만 만든다. 지역 토큰이 서로 다른 실제 가맹점 2곳 이상에 있고, 양수 구매 3건 이상·이용일 2일 이상·7일 이내·정규화 가맹점 2곳 이상이어야 한다. 국가만 있거나 단일 도시명만 있는 행은 클러스터를 시작할 수 없으며, 이미 생긴 클러스터에만 보조행으로 붙일 수 있다.
4. 임시 여행 레지스트리는 정식 여행 일정표와 별도로 보존한다. 레지스트리 ID에는 카드 식별자 해시·국가·지역·기간·구성 거래 fact hash·규칙 버전을 포함하고, 변조·오래된 레지스트리는 Gate5에서 거부한다.
5. `travel_unassigned_count`를 임시대상으로 숨기지 않는다. Gate5는 최종 미배정과 별도로 `travel_open_count = travel_unassigned + provisional_trip + ambiguous_travel_review`를 표시한다.
6. PG 이름만으로 비여행 또는 여행을 확정하지 않는다. 국내 비여행 전환은 명시된 최종 가맹점·업종 쌍의 allowlist가 정확히 맞을 때만 허용한다. OTA·항공 결제일은 서비스일로 사용하지 않으며, 금액 근사(±2%)·국가 단독·과거 bucket은 단독 근거로 사용하지 않는다.

## A-최신-여행분류예외-3. 여행성은 알지만 여행 대상이 모를 때 (2026-08-08)

1. 현재 카드 원자료만으로 여행성은 직접 보이지만 정식 여행 대상이 확인되지 않는 양수 구매에는 사용자 확인용 임시 대상명을 자동 제안한다. 실제 해외 현장 사용은 `임시여행활동_...`, OTA·항공·여행상품은 `임시예약_..._행사기간미상`으로 구분한다.
2. 임시활동의 이용일 묶음은 카드 사용창일 뿐 행사·서비스기간이 아니다. OTA·항공·여행상품은 결제일을 행사일로 사용하지 않고, 가맹점의 도시·국가도 목적지로 해석하지 않는다. 통화만으로 국가를 만들지 않는다.
3. PG 이름만 있고 여행 provider·상품 근거가 없으면 임시예약으로 만들지 않고 `여행_미배정` 검토에 남긴다. 명시적 국내 비여행 허용목록은 계속 `기타비용`을 우선한다.

## A-최신-게이트5-잔여건 계약 (2026-08-11)

1. Gate5의 전체 건수는 숨기지 않는다. `final`(최종확정), `auto_nonfinal`(자동 후속처리 중인 임시분류), `human_question_nonfinal`(사용자에게 실제로 물을 묶음), `untriaged_nonfinal`(어느 경로에도 들어가지 못한 건) 네 lane을 서로 겹치지 않게 보고한다. `nonfinal_count`·`travel_open_count`는 임시분류를 완료로 바꾸지 않는다.

4. 취소·환불은 확정 원거래의 비용축만 상속한다. 임시 원거래의 대상명을 근거로 취소·환불 비용축을 상속하거나 `direct_high_coverage_reversal_inheritance` 링크를 만들지 않는다.
5. 해외 이용일을 행사일로 쓰는 예외는 OTA·항공·PG가 아닌 실제 현장 가맹점 토큰이 카드 행에 양성으로 있어야 한다. `allow_generic_foreign` 같은 설정값만으로 온라인·항공·OTA 행을 현장 이용으로 승격하지 않는다.

## A-최신-Gate5 triage·release 분리 보정 (2026-08-12 사용자 확정)

1. Gate5의 통과는 모든 결제가 final이라는 뜻이 아니라, 모든 결제가 상호배타적인 final·자동후속·사용자질문 lane에 빠짐없이 들어갔고 비최종 행의 부작용이 0이라는 `TRIAGE_PASS`를 뜻한다.
2. `travel_unassigned=5`, 사용자 질문 그룹 `10`은 처리량을 관찰하는 queue SLO다. 초과 사실과 유일 key 수는 경고로 계속 보고하지만, 그것만으로 분석·triage를 실패시키지 않는다. 이 항목은 위 절 4번의 “5건 통과·6건 실패”를 대체한다.

## A-최신-구조적 실패요인별 규칙 추가 요청 (2026-08-12 사용자 확정)

1. 비최종 건의 승인 여부를 건별로 묻지 않는다. 현재 비최종 집합을 `row_finality` veto와
   기타 fail-closed 원인으로 분류하고, 사용자의 결정 단위를 공통 구조적 실패요인
   (`structural_failure_family` + `classification_path`)으로 고정한다. 한 건이 여러 요인을
   가지면 여러 그룹에 겹칠 수 있으므로 그룹 합계와 유일 영향 건수를 따로 보고한다.
2. Gate5 actual 및 `question_queue.json`의 `rule_addition_requests`는
   `structural-rule-admission-v1` 계약을 사용한다. 각 그룹은 영향 건수·멤버십 해시·분류
   경로별 집계·필요한 rule shape만 노출하며, payment ID·event key·가맹점·금액·날짜·대상명
   같은 행 단위 원문은 출력하지 않는다.
3. 사용자에게 요청하는 것은 “이 실패요인에 대해 bounded rule을 설계·추가할 것인가”이지
   해당 건들을 승인할 것인지가 아니다. 응답 단위는 `allow_rule <request_id>` 또는
   `keep_blocked <request_id>`이며, `allow_rule`은 규칙 구현·표적 검증을 시작할 권한만
   의미한다. 그것만으로 final·confirmed decision·allocation·posting을 만들지 않는다.
4. 허용 규칙은 반드시 다음 계약을 포함한다.
   - inclusion predicate: 어떤 구조적 실패를 어떤 증거로 예외 허용하는지
   - exclusion predicate: 비슷해 보이지만 계속 거부할 경우
   - evidence binding: 현재 카드 event/fact와 독립 원천의 hash·cardinality 결속
   - side-effect invariants: 비최종 행의 decision/plan/allocation/posting/reversal 상속 0
   - rollback identity: 규칙 제거·재실행 시 대상 집합을 재현할 식별자와 해시
5. 규칙 추가는 다음 순서로만 반복한다.
   1) 구조적 실패요인별 aggregate request 생성 → 2) 사용자가 family 단위로 허용/보류
   결정 → 3) 해당 family+분류경로 scope만 격리 구현 → 4) 독립 설계·회귀 검증 → 5) 최신 run 재집계로
   `nonfinal_count`, `travel_open_count`, lane 상호배타성, 비최종 side-effect 불변식을 비교한다.
   수치가 악화되거나 불변식이 깨지면 해당 규칙을 폐기하고 이전 상태를 유지한다.
6. 이 절의 방식은 이후 모든 비최종 축소 작업에 계속 적용한다. `nonfinal_count`를 queue
   SLO·임시분류 수·사용자 질문 수로 대체하지 않으며, 구조적 family가 없는 건은
   `unclassified_nonfinal`로 별도 요청하고 임의 규칙을 추정하지 않는다.
7. 이번 목표 검증의 `package-b`는 네 가지 classification path를 한 번에 선택하는
   run-scoped 규칙 묶음이다. 건별 승인으로 해석하지 않으며, 적용된 행은 terminal 분류만
   받고 allocation plan·cost allocation·posting·reversal inheritance는 만들지 않는다.
   기본 실행은 `package=none`으로 fail-closed이고, package를 적용할 때마다 최신 run의
   `nonfinal_count`, lane 불변식, 비최종 side-effect 0, Gate4·Gate6 상태를 다시 기록한다.
8. `package-c`는 package-b에 지리 문맥 exact와 수기 환불 exact/M:N invariant path를
   추가한 임시분류 축소 묶음이다. 이 묶음으로 `auto_provisional`을 5건까지 줄여도
   `human_question_nonfinal` 2건과 `nonfinal` 7건을 숨기지 않는다. package-c terminal도
   분류 종료일 뿐이며 plan·allocation·posting·reversal inheritance를 만들지 않는다.

   여행탭·여행코드·예약번호·행사기간을 만들지 않고 `travel_eligible=0`으로 둔다.
3. `2025년 비용`은 `accounting_final=1`, `allocation_eligible=1`,
   `posting_eligible=1`이다. 확정 배부계획과 결제금액 1:1 배부를 만든다. 다만
   shadow 산출 단계에서는 외부 회계 시스템의 실제 전표 발행을 실행하지 않으며,
   전기 엔진이 사용할 회계기간은 `2025`, 기준일 원천은 `payment.occurred_on`으로
   고정한다. 실제 게시 작업은 release 승인 및 전기 엔진의 별도 게이트를 거친다.
4. `reversal_inheritance_eligible=0`이며 취소·환불 행은 원거래 비용으로 상속하지
   않는다. 원거래와 취소·환불이 상계되지 않거나 부분취소인 경우에는 이 규칙의
   잔여 구매로 흡수하지 않고 취소환불/검토 레인에 남긴다.
5. 각 행은 현재 카드 증빙과 사용자 승인 정책 증빙을 함께 가지며,
   `payment-year-2025-cost-accounting-v1:<event-hash>` 멱등 키를 사용한다. 동일
   run에서 재생성·중복 삽입은 실패해야 하고, membership·provenance·정책 source
   hash가 Gate5 semantic hash에 포함되어야 한다.
6. 이 규칙으로 늘어나는 수는 여행 확정 건수가 아니라 **회계확정·배부 가능 건수**다.
   Gate5는 `accounting_final`과 `display_terminal_final`을 계속 별도로 공개하고,
   규칙 적용만으로 5,000건을 맞추기 위해 2026년 임시행·메일 없는 여행행·취소환불을
   회계확정으로 바꾸지 않는다.

## A-최신-구조적 회계 예외 요청·shadow 전표 계약 (2026-08-14, 승인 대기)

1. 건별 승인 대신 구조적으로 같은 실패 원인을 가진 family 단위로만 예외 규칙을
   요청한다. 요청 family에는 `rule_id`, 대상 path, 허용하는 실패 요인, 금지되는 여행
   승격·상속, membership·provenance·policy hash, 예상 건수와 제외 집합을 함께 적는다.
   사용자가 family를 허용하기 전에는 기본 pipeline에 적용하지 않는다.
2. 현재 요청 후보인 `unresolved-2026-purchase-clearing-v1`은 2026년 purchase이며
   `provisional_travel_target_metadata_enrichment`인 건만 대상으로 한다. 이 family는
   여행 확정이 아니며, 행사기간·여행코드·예약번호·여행 target을 만들지 않는다. 회계
   표시가 필요할 때도 `미확정여행원가` 대기계정과 `법인카드미지급금` 사이의 회계-only
   shadow로만 표현하고, 원 후속 재분류 계약이 없으면 실제 전기로 승격하지 않는다.
3. 취소·환불 family는 authority 전체를 한 transaction으로 묶는다. member 수·purchase/
   reversal 수·signed amount·net=0·source event·고아 0을 먼저 확인하고, 1:1·2:2·M:N을
   임의로 개별쌍으로 바꾸지 않는다. 부분상계·상충·비영 잔액은 family 밖에 둔다.
4. shadow 전표는 기존 `journal_entries`와 분리된 batch/member/line/manifest 구조를
   사용한다. 모든 batch는 차변합계=대변합계, 회계기간·전기일·통화 근거·멱등키·원천
   component 연결을 갖고, 전체 구성원과 라인을 하나의 transaction으로 삽입한다. 현재
   `ledger_currency=KRW`는 source card currency가 아니라 `payment_transactions.amount_krw`
   를 장부 금액으로 삼는다는 뜻이며 source currency unknown을 숨기지 않는다.
5. `shadow_balanced`는 전기 완료가 아니다. `posting_status=shadow_only`, 기존 journal
   0, 재실행 hash 동일, family 상호배타성, 비최종 side-effect 0 및 production chart
   mapping 확인 전에는 `release_ready`·실제 journal·외부 회계 전기를 만들지 않는다.
   실제 posting 승격 함수는 단순 boolean을 신뢰하지 않고, 승인된 `rule_id` 집합과
   `decision_id`를 포함한 family approval attestation hash 및 Gate5·Gate6·HAN equality가
   모두 true인 release attestation hash를 함께 요구한다. 둘 중 하나라도 없으면 posting
   row는 0건으로 남긴다.

## A-최신-Agoda 포털 금액·카드 대사 규칙 (2026-08-15)

1. Agoda 포털 조사는 `Upcoming / Completed / Cancelled` 세 탭의 동적 마지막
   페이지까지 연속 조사하고, 전체 재조사에서 예약 ID 집합과 탭별 슬롯 수가 수렴한
   private census만 사용한다. 2026년과 겹치는 예약이 최종 대상이며, 같은 금액의
   외부 경합을 닫기 위해 서비스 종료일이 2025-08-01 이후인 비대상 예약도
   `competition-only`로 상세 금액을 수집한다.
2. 상세에서는 gross, 실제 결제액, 향후 결제액, 현장 결제액, 할인·쿠폰·AgodaCash·
   포인트, 환불을 서로 다른 필드로 보존한다. 카드 정보는 카드사와 마스킹된 끝
   4자리만 private DB에 저장하고 전체 카드번호·CVV는 수집하거나 저장하지 않는다.
3. 예약과 카드 거래의 정확한 통화·금액 일치는 먼저 `결제금액일치` 후보 간선으로
   만든다. 수렴한 예약 모집단과 현재 카드 원천 모집단 양쪽에서 대체 후보가 0인
   양방향 1:1일 때만 개별 예약-결제 관계를 confirmed authority로 확정한다. 외화는
   `통화+현지금액+card4`가 모두 일치할 때 더 강한 근거로 사용한다.
4. 동일 금액 예약 N건과 카드결제 N건이 경합하되 통화·card4·provider·생애주기와
   금액 멀티셋이 닫혀 있으면, 개별쌍을 임의로 만들지 않고 순서 없는 N:N group
   authority 하나로 확정한다. 이 경우 `individual_pair_asserted=false`를 보존하고
   Cartesian `payment_booking_links`를 생성하지 않는다. 어느 한쪽 수가 다르거나
   집합 밖 후보가 있으면 전부 검토로 남긴다.
5. `pay at property`의 보증카드, gross만 있고 실제 청구 근거가 없는 예약, 미완료
   카드 원천기간, 부분환불·재청구·chargeback·통화 충돌은 개별 확정 근거가 아니다.
   포인트·AgodaCash 사용액은 비용 gross에는 보존하되 카드 청구액으로 간주하지 않는다.
6. 이 단계의 confirmed는 예약-카드결제 **관계 확정**이다. 여행 귀속·비용 세 축,
   allocation, journal/posting, reversal inheritance를 만들지 않는다. 개별 확정만
   일반 링크에 `proposed`로 노출하고, 회계·여행 확정은 별도 분류 및 release gate를
   통과해야 한다.

## A-최신-Agoda 원장행·카드·결제 claim 삼자 연결 승격 규칙 (2026-08-25 사용자 확정)

이 절은 바로 앞 「Agoda 포털 금액·카드 대사 규칙」의 3~4항을 강화한다. 두 절이
충돌하면 이 절을 우선한다.

1. `M`은 원장행, `C`는 카드 RAW business event, `B`는 Agoda 예약 자체가 아니라
   source-scoped immutable payment claim이다. `B`는 claim/payment-event ID,
   reservation ID, 금액·통화·부호·상태·source digest/locator를 갖고, 한 예약의
   split/capture/recharge는 각각 별도 `B`다. 실제 payment claim이 없는 예약은 `B`가
   아니다. `M`의 안정 identity는 sheet + stable physical row key + canonical row
   digest이며, workbook/file revision digest는 provenance와 source-set version으로
   보존한다.
2. admissible `M-C`/`C-B` edge는 component를 만들기 전에 `rule_version`과
   `node_schema_version`으로 고정된 순수 pairwise predicate로 전부 계산한다. component,
   이미 선택된 match, 행순서, 평가순서에 따라 edge가 달라져서는 안 된다. candidate
   graph의 component는 이 전체 edge 집합의 maximal connected component다.
3. closure와 유일성은 필요조건일 뿐 양성 증거가 아니다. confirmed의 각 node는 금액
   매칭에서 파생되지 않은 검증된 교차원천 anchor로 직접 상대 node 또는 동일 group
   membership에 결속돼야 한다. anchor에는 source, 대상 node/group, scope, cardinality,
   evidence digest를 저장한다. singleton anchor의 복수 node 재사용, 공통 census·일반
   명세서를 개별 anchor로 사용, 동일 business event/claim의 중복 node는 금지한다.
   individual에는 cardinality-1 pair/triple-scoped anchor, group에는 각 node의
   group-scoped membership anchor가 필요하다. 금액·card4·provider·날짜·일정만의
   조합은 anchor가 아니다.
4. 필수 비교값은 non-null이고 모든 가용 권위 표현이 일치해야 한다. `M-C`의 signed
   KRW, `B-C`의 native currency + signed amount, 양쪽에 권위 KRW가 있으면 그 KRW도
   허용오차 0으로 정확히 같아야 한다. 한 표현의 일치로 다른 표현의 충돌을 무시하는
   OR 판정은 금지한다. sign·provider·card4·time·status도 충돌하거나 사유 없이
   누락되면 보류한다.
5. closed purchase component는 scope가 명시된 `M/C/B` census가 sealed되고 source,
   census, attestation digest가 검증되며 purchase cardinality·amount·currency·sign·
   provider·card4·status가 무충돌이어야 한다. 서로 다른 권위 service period/trip
   scope는 먼저 분할하고 안전하게 분할할 수 없으면 보류한다. 일정은 충돌·분할
   신호이며 positive anchor가 아니다.
6. 3~5항을 모두 충족한 closed purchase component 안에서만 모든 유효 완전 `M-C-B`
   matching을 순서와 무관하게 계산한다. 모든 valid matching에 공통이고 cardinality-1
   pair/triple anchor가 있는 forced triple은 `confirmed_individual`로 먼저 분리하고
   residual에 대해 반복한다. 남은 동일 `N` residual에 완전 matching이 하나 이상 있고
   더 이상 `confirmed_individual` 조건의 triple이 없으며 각 node의 group membership
   anchor가 있으면 unordered `confirmed_group`으로 확정한다. 후보상 unique pairing이
   보여도 pair/triple anchor가 없으면 개별 pairing을 주장하지 않는다. group은
   `individual_pair_asserted=false`, `bijection_asserted=false`이며 Cartesian·행순서·
   금액순서 pairing을 금지한다. complete matching 없음, counts 불일치, anchor 부족,
   금액/card4 multiset만 일치한 경우는 `candidate_only` 또는
   `reconciled_candidate_group`이다. 서로 독립인 component를 합치지 않는다.
7. 평면 원장에는 `confirmed_individual`만 단일 `reservation_id`를 기록한다.
   `confirmed_group`은 `reservation_id` 공란과 `reconciliation_status=confirmed_group`,
   `reconciliation_group_id`를 모두 강제한다. 누락 또는 reservation ID 동시 기입은
   검증 실패다. 전체 reservation/payment-claim set과 join path는 group authority에만
   두고 한 셀에 다중 ID를 쓰지 않는다.
8. purchase graph와 lifecycle graph를 분리한다. `relation_kind=purchase`의 disposition은
   `candidate_only|reconciled_candidate_group|confirmed_individual|confirmed_group`,
   `relation_kind=lifecycle`의 disposition은
   `candidate_lifecycle_only|confirmed_individual_lifecycle|confirmed_group_lifecycle`이다.
9. lifecycle event도 독립 digest/locator, terminal status, 비금액 anchor가 필요하다.
   `confirmed_individual_lifecycle`은 가능한 parent가 정확히 하나의 active
   `confirmed_individual` component이고, 해당 `B`와 원 `C/M`을 직접 잇는
   cardinality-1 비금액 anchor 또는 검증된 unique source parent relation이 있으며
   외부 competing parent가 없을 때만 허용한다. `confirmed_group_lifecycle`은 가능한
   parent set이 정확히 하나의 active purchase group과 같고 그 집합 귀속이 독립 group
   anchor로 입증될 때만 허용한다. 금액·card4·날짜·provider만으로 좁힌 것은
   `candidate_lifecycle_only`이며 어떤 group에도 귀속하지 않는다. 미해결 lifecycle은
   purchase authority, booking status, net, 개별행, 배분, 전기에 영향을 주지 않는다.
   confirmed group lifecycle도 개별 booking에 취소액을 배분하지 않으며 lifecycle
   artifact의 gross/net은 관찰값이다. 0원 `M`은 purchase graph의 admissible node가
   아니고 reservation ID·`B`·purchase authority를 만들지 않으며 원천/lifecycle
   증거로만 보존한다.
10. authority는 `active|superseded`, rule/schema version, source/census/attestation/graph
    digest, anchor ID와 cardinality, reason code, `financial_effect=none`,
    `allocation_eligible=false`, `posting_eligible=false`를 갖는다. 현재
    rule/schema/source-set의 active authority만 현재 의사결정에 사용할 수 있고,
    superseded authority는 역사 감사 외에는 소비하지 않는다.
11. relation authority는 trip assignment, 비용분류, 계정, VAT, allocation,
    journal/posting, reversal inheritance를 만들지 않는다. downstream은
    `financial_effect=none`과 두 eligible 값의 false를 hard gate로 검사한다.
12. 같은 input + rule/schema version은 같은 semantic digest와 결과를 내며 재실행은
    멱등이다. 이 규칙의 수용만으로 DB·시트·링크·전표를 변경하지 않는다.
13. 현재 관찰된 다수 1:1와 9개 N:N 구조(2:2 다섯 개, 3:3 세 개, 4:4 한 개),
    모호한 cancellation은 구조 분해만 수용한다. 실제 행은 3~10항의 verifier를
    통과하기 전에는 candidate이며, 기존의 강한 후보라는 표현, 개수 또는 금액
    일치만으로 confirmed로 승격하지 않는다.

14. `group_permutation_invariant_projection`은 purchase relation disposition이
    아니라 별도의 파생 projection이다. `confirmed_group`의 unordered 집합 권위와
    개별 예약-결제 identity를 섞지 않는다. 3~10항과 아래 조건을 모두 통과한
    `confirmed_group`만 이 projection의 권위 입력이 될 수 있다. `reconciled_candidate_group`
    은 `candidate_draft`만 만들 수 있고 canonical classification, allocation, journal,
    posting 또는 release authority의 입력이 될 수 없다.

15. projection은 다음의 닫힌 계약을 `projection_schema_version`,
    `transformation_version`, `projection_field_set_sha256`, `consumer_contract_sha256`와
    함께 고정한다. 계약에는 signed KRW/native amount, currency/FX, sign,
    transaction type, merchant, source system, payment date/lane, provider,
    product type, service start/end, booking/payment/refund status, account,
    cost type, VAT, authoritative trip target/year/end semantics, recognition
    period, allocation dimension, rounding 및 null semantics를 포함한다. downstream이
    읽는 필드가 계약에 없거나 계약·변환 규칙이 바뀌면 기존 projection은 즉시
    `superseded`로 만들고 다시 계산한다.

16. `confirmed_group`의 순열불변 projection은 정확한 완전 matching 집합을 계산할
    수 있을 때만 허용한다. 예약·payment node 수가 같고 2 이상이며, closed/sealed
    census, 중복 없는 active node, 외부 competing component 없음, 실제 양수 purchase
    claim만 존재해야 한다. `N<=4`는 모든 완전 matching을 열거하고, 그보다 큰 N은
    검증된 symbolic verifier가 없으면 보류한다. 각 matching에서 reservation identity
    필드를 제외한 canonical semantic output digest가 정확히 하나로 같아야 하며,
    그 digest에 `reservation_id`, `booking_id`, `booking_number`, `claim_id`,
    pair-edge ID 또는 refund-parent ID를 포함하지 않는다.

17. projection의 payment 행은 `UNIQUE(group_id,payment_id)`로 한 번씩만 생성하고,
    active payment가 여러 active group에 속하지 않음을 검증한다. N:N 확정 그룹의
    원장 `reservation_number`는 비워 두지 않고, 그룹 member 중 하나를
    `synthetic_group_representative` 방식으로 배정한다. 이 값은 사용자가 원하는
    회계 원장 표시·검색용 대표값이며, 실제 payment와 해당 예약의 1:1 사실관계를
    뜻하지 않는다. 배정 규칙은 `synthetic_assignment_version`으로 고정하고,
    정규화한 예약번호의 사전순 최소값처럼 재실행 가능한 결정 규칙을 사용한다.
    모든 해당 행에는 `group_id`, `reservation_assignment_mode`,
    `individual_pair_asserted=false`, `bijection_asserted=false`를 함께 기록한다.
    전체 payment member를 빠짐없이 한 번씩 포함하고 중복·누락을 0으로 검증한다.
    양수 purchase 기준으로 `payment row 합계 = group aggregate = allocation aggregate`
    를 원 단위로 보존하고, journal을 만들 때 `debit 합계 = credit 합계 = 해당
    aggregate`를 검증한다. group aggregate를 각 payment 행에 반복 기록해 N배로
    만드는 것은 검증 실패다.

18. authoritative `trip_schedule`의 날짜·연도·종료 의미·source digest가 검증되고
    서비스 기간이 정확히 하나의 여행 대상에 결속될 때만 group-level projection에
    `trip_target_projection`을 넣는다. 일정이 없거나 복수이거나 연도/digest/end
    semantics가 충돌하면 `여행_미배정` draft만 허용하고 release를 금지한다. group
    projection은 예약별 배부나 환불별 배부를 만들지 않으며, allocation·journal·posting은
    relation authority와 분리된 별도 release authority가 최신 source/group/schedule를
    다시 검증한 뒤에만 허용한다.

19. synthetic 대표 예약번호는 원장과 원장 export에는 표시할 수 있지만, 이를
    개별 예약의 사실 증명값으로 재사용하지 않는다. `reservation_number`를 이용한
    외부 join·개별 예약 분류·예약별 배부는 `group_id`와
    `reservation_assignment_mode`를 함께 확인하지 않으면 거부한다. 화면에는
    대표 예약번호와 함께 `group_label`, `member_count`,
    `individual_pair_asserted=false`, `bijection_asserted=false`,
    `synthetic_group_representative`를 표시하고, 전체 예약 member는 별도
    membership 목록으로 제공한다. 원장 금액은 group aggregate가 아니라 각 payment
    row의 실제 금액으로만 기록하며, 관계 authority는 대표번호를 채우더라도
    `financial_effect=none`, `allocation_eligible=false`, `posting_eligible=false`를
    유지한다. trip_schedule이 확정된 뒤의 group-level 비용분류·전기는 허용하되,
    대표 예약번호를 근거로 특정 예약에 비용을 귀속시키는 것은 금지한다.

20. lifecycle은 purchase projection과 독립된 graph·authority로 관리한다. refund,
    cancellation, chargeback, recharge, split, future payment 또는 late-arriving
    lifecycle이 나타나면 기존 purchase projection과 release를 stale로 차단하고
    새 source/census로 supersede한다. lifecycle parent set이 정확히 하나의 purchase
    group과 독립 exact-set anchor로 일치할 때만 group lifecycle을 만들며, 그 금액을
    개별 booking에 배분하거나 개별 reservation identity로 소급하지 않는다.

21. 최소 negative test는 독립 group anchor 없음·재사용, 외부 competitor, 중복 event/claim,
    cardinality 불일치, 완전 matching 부재, projection 필드 단일 차이·NULL·raw/canonical
    충돌, VAT/FX/인식기간/반올림/allocation key 차이, 일정 없음·복수·연도/digest 충돌,
    refund/cancel/chargeback/recharge/split/pay-at-property, payment 행 증폭·누락·중복,
    candidate의 canonical/release 진입, member shuffle 및 모든 matching 순열,
    재실행 멱등성, source/rule/schema/downstream field 변경 후 stale authority 소비를
    포함한다. 하나라도 실패하면 projection은 fail-closed다.


## A-최신-매칭 순서·신뢰도 계층 (2026-08-29 사용자 확정)

1. **매칭 순서 고정:** `card → mail(같은 결제일 금액) → booking(예약번호) → booking.service_start_on → trip` 순서로 매칭한다. 결제일 기간 매칭을 먼저 사용하지 않는다(예약번호가 있으면 행사기간 불일치 가능).
2. **3계층 신뢰도 분류:**
   - L1 확정 (`bound_unique`): 같은 결제일 금액 일치 + 예약번호 직접 매칭 + reference_code/card4 정합.
   - L2 후보 (`authority_ambiguous` / `confidence<0.8`): 예약번호만 또는 금액+일자만 일치.
   - L3 표시용 (`payment_year_terminal` / 기간 포함만): 회계 전기·게이트 근거가 아닌 워크북 표시용. posting_eligible=false 유지.
3. **강한 연결 가드:** `held(no_actual_charge_claim)` + 식별자(ref code) 부재면 L3로 격리, 권위 매칭 금지.
