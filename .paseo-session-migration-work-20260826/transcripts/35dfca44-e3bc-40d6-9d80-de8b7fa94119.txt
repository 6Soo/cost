[User] 실제 live census에서 확인됐지만 현재 staging DB에 없는 Agoda 예약을 상세 수집하라. 이 배치의 정확한 대상 ID는 ["1645645740","1634034097","1609832106","1609833389","1609835358","1609836272","1634009255"] 이다. 모든 대상은 Completed 호텔 목록의 live census ID이며, 첫 ID 1755579869는 Completed 1페이지, 나머지는 Completed 3페이지에 있었다.

규칙:
- 이 workspace의 네 전용 Paseo IAB 세션/브라우저/탭 하나만 사용한다. 다른 agent의 browserId/tab을 사용하거나 새 agent·새 세션·중복 탭을 만들지 말라.
- Windows Paseo IAB만 사용하고 Edge/UIA/CDP/다른 브라우저로 폴백하지 말라.
- 파일, SQLite, artifact에는 절대 쓰지 말라. 결과는 최종 JSON 하나로만 반환한다.
- 현재 Agoda bookings 목록에서 대상 ID가 붙은 카드의 data-element-name="mmb-booking-card"와 data-bookingid를 정확히 일치시켜 먼저 증명한다. ID가 없으면 오래된 artifact를 찾느라 전체 페이지를 무한 재탐색하지 말고 TARGET_NOT_PRESENT_AFTER_CENSUS를 기록한다.
- 대상 카드가 항공이면 상세를 열지 말고 is_hotel=false 및 SKIPPED_FLIGHT를 기록한다.
- 호텔 카드의 상세 진입은 카드 내부 data-element-name="blp-booking-item-button-edit" 하나만 browser_evaluate에서 선택·클릭한다. browser_click, snapshot ref, 순번/index, 좌표, 위치 range, 일반 텍스트 partial match는 금지한다.
- 고객센터/도움말/지원 control은 존재 여부만 관찰하고 절대 클릭·호출하지 말라. 실제 chat dialog/root와 입력 placeholder "요청 사항을 선택하거나 직접 입력해 주세요"가 동시에 보이면 즉시 fail-closed하고 CUSTOMER_CENTER_PANEL_VISIBLE을 기록한다.
- 목록 로딩은 최대 5회, 상세 진입은 대상당 최대 3회 bounded retry만 허용한다. 실패하면 같은 세션에서 다음 대상에 진행하되 무한 재시도하지 않는다.
- 상세 성공 후 browser_back 또는 DOM 상태로 목록 복귀를 확인한 다음 다음 대상에 진행한다. 현재 URL과 선택 control을 기록한다.
- 각 레코드에 booking_id, is_hotel, property_name, check_in, check_out, reservation_status, payment_state_or_collection_wording, currency, amount, card_type, card_last4, current_url, selected_control, customer_center_control_present, panel_visible, started_at, ended_at, duration_ms, failure_codes를 포함한다.
- 전체 JSON에 status, batch, records, success_count, failed_count, skipped_count, aggregate_failure_codes, started_at, ended_at, duration_ms를 포함한다.
Paseo IAB 전용 세션 규칙을 적용해 대상 카드 증명 → 호텔 상세 수집 → 목록 복귀 확인 순서로 진행하겠습니다. 파일·DB·artifact에는 쓰지 않고 최종 JSON만 반환하겠습니다.
