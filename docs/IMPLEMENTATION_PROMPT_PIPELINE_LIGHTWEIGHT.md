# 구현자용 작업 프롬프트

당신은 비용 자동화 저장소의 경량화 구현자다. 한국어로 보고한다.

## 작업 격리
- 전용 worktree 또는 별도 작업공간 하나에서만 작업한다.
- 다른 작업공간, 운영 DB, 원본 자료, 기존 출력과 동시에 작업하지 않는다.
- 기존 산출물과 운영 DB를 덮어쓰지 않는다. 코디네이터가 검토 후 통합한다.

## 범위
- `run_manifest.py`를 추가해 봉인된 입력을 직접 실행당 한 번 해시하고 규칙·구조·결정 버전에 결속한다.
- 새 정규화 엔진을 만들지 말고 `direct_sources.py`, `direct_projection.py`의 결과와 식별자를 재사용한다.
- 일정 권위 로드와 관계 판정을 실행당 한 번 수행한다.
- 투영기는 공통 판정 결과만 읽는다.
- 감사는 산출물마다 원천을 다시 읽지 않고 실행 시작 때 직접 만든 manifest와 결과 계약을 확인한다.
- 상태는 `ready`, `held`, `blocked`, `external_pending`으로 둔다. `external_pending`과 오류가 있으면 `release_eligible=false`다.
- 같은 입력·의미 해시는 `verified_skip`으로 기록한다. 외부 전기 중복 방지를 주장하지 않는다.

## 업무 규칙
결제일은 여행일이 아니다. 권위 일정 필수 필드와 source_sha256를 확인한다. 옛 기간 문자열, 가짜 예약번호, 가짜 고객명, 증명되지 않은 숙박 기간을 만들지 않는다. 음수·0원은 양수 구매로 바꾸지 않는다. 현재 결정 등록부의 일정 겹침 규칙을 따른다.

## 필수 테스트
- 반복 실행은 두 번째 `verified_skip`이고 새 내부 행과 외부 효과가 없다.
- 행 순서 변경은 같은 의미 해시를 만든다.
- 금액·부호·날짜·예약 ID·여행 ID·원천 해시 변경은 의미 해시를 바꾼다.
- 중복 ID, 권위 필드 누락, 원천 해시 불일치, 음수·0원은 거부한다.
- 후보·held는 ready가 되지 않는다.
- 기존 출력과 임시 파일은 보존한다.
- 외부 단계 생략은 `external_pending`이지만 release는 차단한다.
- 기존 v2 자료를 읽는다.

## 검증
변경 대상 테스트 → `test_pipeline_audit.py`와 shadow 테스트 → 일정·OTA·webapp 테스트 → `pipeline_audit` → Python 문법 검사 → `git diff --check` 순서로 실행한다. 테스트 기대값을 낮추거나 삭제하지 않는다.

완료 보고에는 변경 파일, 실제 줄어든 읽기·검증 횟수, 테스트 결과, 남은 상태, 의미 해시와 파일 해시, 원본·운영 외부 효과 미변경을 적는다.
