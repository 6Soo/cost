## (c) 순서 의존 실패 결정화 — 환경 누수

묶음 단독에서는 통과하지만 전체 스위트에서는 실패하던 케이스들이 있다. 원인은 **앞선 파일이 프로세스 환경에 `WEBLEDGER_CARD_FLOW=1`을 남기는 누수**다. 이 값이 있으면 `/review`가 `/cards/all`로 303 리다이렉트되어(`ledger_board.py`의 card_flow 분기), 검토 화면을 기다리는 브라우저 검사들이 줄줄이 실패한다.

전체 스위트(`branch-solo.xml`)에서 이 묶음의 누수 시그니처를 집계했다(`.local-archive/suite-g1/fullsuite_delta.py`):
- `Page.wait_for_function Timeout`(`#rows .card` 대기) **32건** — 검토 브라우저 3개 파일.
- `the model was never requested` **1건**.
- bare board 리다이렉트 `303 not found in 200` **1건**.

이 중 4건은 위 (b) 표의 계약 실패와 겹치는 테스트(전체 스위트에서는 누수가 계약 단언보다 먼저 터짐)이고, 나머지 **30건이 전체 스위트 전용 순서 의존 실패**다(실 검토 브라우저 19 + initial_term 6 + guidance 4 + bare_board 1).

**결정화(수정):** `ReviewTestCase.setUp`/`_restore`(test_real_review.py)와 `ReviewBrowserFixture.setUp`/`_restore`(test_real_review_browser.py)에서 `WEBLEDGER_CARD_FLOW`를 `"0"`으로 고정하고 종료 시 원래 값으로 복원한다. `test_review_initial_term_browser.py`·`test_review_guidance_browser.py`는 `ReviewBrowserFixture`를 상속하므로 자동 적용된다(두 파일은 수정하지 않음). 이로써 누수 값이 무엇이든 검토 화면 검사는 항상 카드 흐름 비활성 상태에서 돌아간다.

누수 진원지(어떤 파일이 `CARD_FLOW=1`을 남기는지)는 이 묶음 소관이 아니다. 환경 프로브(`.local-archive/suite-g1/env_probe.py`·`run_probe.py`)가 전체 스위트 접두사(`tests`·`tools`·`webapp/tests` 중 `test_real_review.py`까지)를 순서대로 돌며 첫 영구 누수를 찾았으나, 접두사 구간에서는 진원지를 확정하지 못했다(누수는 전체 순서 의존). 진원지는 다른 묶음 파일 소관이라 확인되더라도 보고만 하고 고치지 않는다(보호 규칙). 환경 고정은 진원지와 무관하게 이 묶음을 결정화하며, 위 실증(외부 `CARD_FLOW=1`에서도 58 passed)으로 확인했다.
