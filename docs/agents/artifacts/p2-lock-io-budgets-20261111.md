# P2 잠금·I/O 장애 조사 — 미완료

기준 SHA `83d87f88416924a5ec377e988a82b778d9f956a2`; 비교 `bd4646a1`. 운영 자료·실제 모델·배포는 사용하지 않았다.

## 코드로 확인한 사실

- 두 버전 모두 `sweep_once` 전체가 `active_writer`로 감싸져 배포 route가 설정된 경우 route 잠금을 회차 반환까지 유지한다. P1 준비는 runtime 및 board 잠금 아래 실행하고, `_call_agent`는 이 내부 잠금에서 벗어나지만 바깥 route 잠금 안에 남는다.
- P2 조립과 추가 조회, 반영 직전 신선도 재조립은 runtime 및 board 잠금 안에서 실행한다. 모델 호출은 runtime 및 board 잠금 밖이지만 route 잠금 안이다. DB 쓰기 잠금의 실제 보유 시간은 측정하지 않았다.
- `bd4646a1`은 조립 중 enable/window 검사 콜백이 없고, 소스 호출은 전체 로딩이다. 따라서 조립 시작 뒤 off가 되어도 진행 중인 조립은 끝날 때까지 계속될 수 있다. `83d87f88`은 로더 전후 및 항목 반복에서 검사를 추가했지만 전체 로더 호출 내부는 중단할 수 없다. 두 버전에서 P1의 `_held_context`와 분류도 P2 게이트 이전에 수행된다. 이것이 실제 관측된 읽기량의 원인인지는 확인되지 않았다.
- 두 버전에서 호출 예약은 초기 조립 후에 이루어진다. 예약 0은 조립 미완료, 선정 결과 없음, 게이트 또는 조립 전 오류 등 여러 경로와 양립한다. 실제 당시 스택과 이번 실행에 귀속되는 충분한 단계별 기록이 없으므로 직접 원인은 미확정이다. 과거 저장 metrics는 이번 실행의 증거로 사용하지 않았다.
- 기존 소스는 전체 메일 로딩과 포털 전체 행 읽기를 사용한다. 83은 회차 스냅샷 재사용을 추가했으나 색인 조회나 실제 I/O 예산을 제공하지 않는다.
