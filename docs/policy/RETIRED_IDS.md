# 폐지·통합 규칙 ID 대응표 — 2026-11-19

**현행 적용:** `docs/policy/*.md`의 현재 `### <ID>` 규칙 정의 **689개**가 활성 규칙이다. 이 표의 **78개 ID는 새로운 78개 규칙이 아니라 폐지·통합된 과거 호환 ID**다. 767개 원래 ID의 추적 가능성을 유지하되 P1/P2가 같은 판단을 여러 번 중복 적용하지 않게 한다. 개별 구버전 코드의 자동 별칭 해석까지 완료했다는 뜻은 아니다.

**참조·감사:** 과거 기록·PR·코드 주석에 있는 폐지 ID는 이 표의 정본 ID로 해석한다. 정본 규칙의 모든 조건·예외·보호가 우선하며 단순 이름 치환만으로 수동·원본·금융 근거가 늘어나지 않는다. 옛 ID의 당시 전문과 결정 유형·출처는 [통합 전 고정 원문](https://github.com/6Soo/cost/tree/3d8e879163a17e4b510cbe8ddb6047623de46e47/docs/policy)에서 동일 ID로 확인한다. 상태 '**폐지·통합**'은 법적·금융·사용자 예외 규칙을 철회한다는 뜻이 아니라, **동일 판단의 활성 정본 ID로 합쳤다**는 뜻이다.

> **호환 한계:** 실행 코드, 테스트, 외부 문서에 폐지 ID를 하드코딩한 경로는 이번 docs-only 작업에서 전수 검증하지 않았다. 런타임 ID가 필요한 소비자는 후속 구현에서 명시적인 이 매핑을 읽거나 활성 ID로 변경해야 한다. 사전 검증 없이 기존 동작이 완전히 동일하다고 표시하지 않는다.

## 재검수

- 기존 767개 ID가 **689개 활성 정의 + 78개 폐지·통합 호환 ID**로 정확히 일대일 분리돼야 한다.
- 통합 전의 예외·범위·중복·환불·수동 교정·원본 오류·이용일 경계는 정본 조항에 남아야 한다. 종류가 다른 규칙의 단순 유사도만으로 통합하지 않는다.
- 활성 규칙·핵심 규칙집 내부의 과거 ID 참조는 정본 ID로 고친다. 과거 기록과 코드의 이력은 삭제하지 않는다.
- 실제 P1/P2 해석, M:N 금융, 환불 원자성, 보험/영수증, P2 미매칭 상세 보고, 이용일 우선, M3~M6 회귀 검증은 **별도 실행/독립 검수 전이며 이 PR에서 성공으로 주장하지 않는다**.
