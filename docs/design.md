# 프로세스 재설계 · 장부 스키마 · 분류 규칙

## 1. 프로세스 재설계

### 원칙
- **1단계(업로드)는 수동 유지.** 법인카드는 오픈 API가 없어 수집 자동화 ROI가 낮다.
  대신 "다운로드 → 붙여넣기" 이후 전부를 자동화한다.
- **2·3·4단계를 "정산 실행" 버튼 한 번으로 통합.**
- **멱등성(idempotent):** 실행 시 RAW의 **흰색(미분류) 행만** 처리한다.
  이미 색칠된 행은 건너뛴다 → 언제 몇 번을 눌러도 안전. 중복 전기 없음.
- **점점 똑똑해짐:** 완료 장부에서 `가맹점명 → 계정과목` 지식을 학습해 두고,
  사용자가 수동 분류한 건이 생길 때마다 그 지식을 갱신한다.

### 실행 흐름 (정산 실행)
1. RAW 3개 시트에서 **배경색이 흰색(미분류)** 인 행 수집.
2. 각 행을 **규칙 + 학습된 가맹점맵**으로 분류.
3. 판정 결과에 따라:
   - **확정** → 장부 시트에 전기, RAW 행을 **완료색**으로.
   - **매출취소/환불** (음수 금액 또는 취소쌍) → **매출취소색**으로 표기(장부에는 반대분개 또는 제외).
   - **보류**(트립닷컴·아고다·부킹 / 페이 큰 금액 / 미지의 가맹점) →
     **흰색 유지** + 셀 노트로 "보류 사유"를 남긴다(사용자가 왜 남았는지 즉시 파악).
4. 요약 로그(처리 n건 / 확정 n / 취소 n / 보류 n)를 토스트로 표시.

> 색 체계는 기존 3색(완료/매출취소/흰색)을 그대로 유지한다.
> 보류 사유는 색을 늘리지 않고 **셀 노트**로 비파괴적으로 표기.

## 2. 장부(원장) 스키마

### 완료 장부에서 확인된 실제 구조
| 날짜(결제일) | 거래처 | 적요 | 결제수단 | 금액 | 예약번호 |
|---|---|---|---|---|---|
| 26.04.27 | AGODA.COM APA HOTEL | 숙박_0426_0428 | 국민 | 392,913 | 1694922534 |
| 26.03.09 | 대한항공_고마츠 | 항공_이정례_0424_0429 | 국민 | 651,000 | |

핵심 관찰:
- **날짜 = 결제일**, **실사용일은 적요 접미(`_0426_0428`)에 수기 인코딩** → OTA는 메일 매칭 필수.
- **적요 = `용도_세부`**: 용도(숙박/항공/식비/교통비/입장료) + 체크인/아웃 또는 승객명.
- **결제수단**: 카드사(국민/기업/하나) · 카드4자리(4595/4971) · 이체 · 영수증 혼재
  → 실제 카드가 RAW 3개보다 많다(국민·기업·하나·4595·4971…).
- **예약번호**: 아고다 ID, 트립 예약번호, 부킹 번호 → **카드↔메일↔장부 조인 키**.

### 채택 스키마 (완료장부 계승 + 명시화)
필수(본질): **거래일자·계정과목·적요·금액·가맹점**. 부가: 결제일·예약번호·여행·결제수단·국내해외·통화·현지금액·상태.
- 적요는 완료장부 스타일(`용도_MMDD`)을 자동 생성.
- 계정과목을 별도 열로 명시(완료장부는 적요에 녹여썼지만, 집계·세무를 위해 분리).

> **확정 필요:** 기존 **진행 장부에 그대로 이어붙이려면** 그 시트의 실제 헤더/열(빈 열 포함)을
> 확인해 매핑을 고정한다. 신설을 원하면 위 채택 스키마로 새 탭에 기록.

## 3. 분류 규칙 (2단계 추론의 핵심)

동일 건 판정(RAW ↔ 장부) 키: **거래일자 + 가맹점명 + 금액**.

### A. 해외결제
- 식비 / 교통비 / (호텔명 포함)숙박비 → **해당 일자에 맞는 여행**으로 분류.
- **10만원 이하** & 가맹점명이 "식비 아님"을 명시하지 않는 한 → **식비**로 처리.
  - 교통/렌트/주유 키워드 예: `TOYOTA`, `RENT`, `ENEOS`, `HERTZ`, `TAXI`, `PARKING`,
    `SHELL`, `ESSO`, `EXPRESSWAY`, `TOLL`, 주유·렌터카·철도 등 → **교통비**.
  - 호텔/숙박 키워드: `HOTEL`, `HOSTEL`, `INN`, `RESORT`, `RYOKAN`, `민박`, `료칸` 등 → **숙박비**.
- **트립닷컴 / 아고다 / 부킹닷컴** → **보류(사용시기 확인 필요).**
  결제시기와 실사용시기가 크게 어긋나 자동 추론 불가 → 지금은 수동. (로드맵의 이메일 파싱으로 해결 예정)

### B. 국내결제 — 기타비용 vs 국내여행 2갈래
- **카드 3820 (김주형 이사) = 기타비용** → 표준(IFRS) 계정과목:
  업종 기반 매핑 — 커피/음료→**회의비**, 음식점→**복리후생비**, 슈퍼/편의점→**소모품비**, 용역→**지급수수료**.
  - PG/전자상거래/페이(KCP·네이버페이·카카오페이) 큰 금액(항공권 결제료) → **메일 매칭**
    (KICC 이지페이/페이 메일) → 성공 시 계정 확정, 실패 시 보류.
  - 미상 업종 → 보류(회의비/복리후생비/소모품비 중 확인).
- **그 외 국내카드 (아슬란 대장 등) = 국내여행** → 여행 세부 계정:
  커피·음식→**식비**, 주유·렌트·교통→**교통비**, 숙박→**숙박비**, 입장→**입장료**. 기본 **식비**.
- **항공사/여행사 직접결제**(대한항공·마이트립 등) → **여비교통비**.

### C. 학습(자기개선)
- 완료 장부에서 `정규화(가맹점명) → 계정과목`을 수집해 **가맹점맵** 구축.
- 정산 실행 시 규칙보다 **가맹점맵을 우선** 적용(과거에 사람이 확정한 판단을 재사용).
- 사용자가 보류 건을 수동 확정하면 그 매핑을 가맹점맵에 추가.
