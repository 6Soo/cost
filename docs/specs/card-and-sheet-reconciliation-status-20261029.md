# 카드 업로드 전수 검증 및 Google 수기 지출 중복 방지 현황

기준: 2026-10-29. 본 문서는 구현 완료 선언이 아닌 작업 현황과 기존 규칙의 관계를 정리한다.

## 확정된 두 제품 명세

- 카드 업로드 전수 검증: PR #349 (https://github.com/6Soo/cost/pull/349). 신규 파일 원천 거래 전체를 기존 DB와 대조, 신규 거래 자동 등록, 월별·전체 분류 검증. 이번 파일만 검증하며 보고서는 영구 보관하지 않는다. 분류 완료 조건은 거래 성격 + 유효한 특정 여행 귀속. 고신뢰 자동 여행 추론도 완료로 인정. 취소·환불 연결은 별도 금융 대사 상태로 보고한다.
- 수기 Google 지출 중복 방지: PR #350 (https://github.com/6Soo/cost/pull/350). 수기 셀은 보존하고 차이 표시. 고유 ID가 없더라도 복합 조건으로 유일하게 동일 거래가 판정되면 자동 연결하며 새 행을 추가하지 않는다. 모호하거나 핵심 값이 충돌하면 보류. 연결은 재전송 중복 방지를 위해 보존하되 시트 행 번호만으로 식별하지 않는다.

## 현재 구현과 명세의 경계

- 최신 운영 인계: docs/session_handoff.md, PR #351. 카드 6,395건 classified, 일반 지출 정리 0건, 보호 보류 4건이라는 운영 기록이 있다. 이는 신규 파일 전수 검증·Google 장부 기록 완료를 의미하지 않는다.
- 기존 finance.md의 classified는 자동·수동 비용 분류 완료를 의미하며, 과거 유효 여행이 없는 거래도 분류 완료로 남을 수 있다. 신규 업로드 검증은 더 엄격한 여행 귀속+거래 성격 기준으로 **별도 지표**를 산출한다. 기존 classified 값을 변경하거나 허위로 여행을 생성하지 않는다.
- Google 최종 장부 자동 쓰기 금지, 원본·수동 교정·환불·금융 링크 보호, P1→P2→P3 원칙은 유지한다. 자동 동일성 판정은 외부 시트 쓰기 권한을 뜻하지 않는다.
- PR #349와 #350은 조회 시점 OPEN, 미병합이며 문서만 추가했다. 두 기능의 구현·테스트·배포·실자료 수락은 확인되지 않았다.

## 후속 작업 순서와 수락

1. PR #349/#350과 main 최신 코드를 대조해 기존 카드 업로드, 분류, Google 읽기, 내부 preview/commit/project, 연결 저장 및 감사 경로를 재사용한다.
2. 카드 업로드 원천 행 전수 계수, 고유키/복합 조건 중복 대조, 신규 멱등 등록, 월별 완료·실패 원인 및 환불 별도 경고를 구현한다.
3. Google 수기 행의 읽기 전용 후보 생성, 유일한 복합 조건 자동 매칭, 수기 원본 차이 표시, 안정적 연결 기록 및 행 이동·변경 재검증을 구현한다.
4. 장부 반영 직전에 재대조한다. 동일 거래는 신규 행 0, 신규 거래는 기존 허용된 기록 경로, 불명확하면 안전 보류.
5. 합성 테스트: 재업로드 신규 0, 반복 동일금액 거래 오병합 0, 수기 행 변경 0, Google 무승인 쓰기 0, 월별 합계 일치, 환불 원결제 연결 별도 상태, 동시 실행/재시도 멱등.
6. PR 병합, 구현, 테스트, 운영 배포, 실제 시트 수락을 각각 독립적으로 보고한다.
