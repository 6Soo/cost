# 카드 내역 거래일자 공백 전환 (2026-11-08)

상태: 구현·표적 검사 완료, PR/영향 QA/독립 검토/배포 진행 중.

최신 사용자 요청: “조회기간 자체를 폐기하고 거래일자 기준으로 카드 내역 일자 공백을 찾는 방식으로 uiux 수정”. 이 결정은 과거 카드 업로드 조회기간 UX 명세의 대시보드 기준보다 우선한다.

## 실행 계약

- `/cards/all?panel=coverage`는 카드사·끝4자리의 표시용 그룹별로 실제 거래 날짜를 합친다. 파일 MIN/MAX 전체를 거래가 있는 기간으로 간주하지 않는다.
- 날짜는 기존 거래의 `approval_date`(파서의 이용/승인/거래일 매핑)를 사용하고 비어 있으면 `posting_date`를 사용한다. 잘못된 날짜는 계산에서 제외한다.
- 첫 거래일~마지막 거래일 사이 거래 없는 연속 날짜만 공백이다. 양끝 바깥을 누락으로 추정하지 않는다. 공백은 정상 미사용일일 수 있으며 자료 누락을 확정하지 않는다.
- 중복/겹치는 파일의 같은 거래일은 한 번만 반영한다. 서로 다른 카드 그룹은 합치지 않는다. 카드 정보가 불완전하면 파일별로 분리한다.
- 카드 그룹/파일/공백/거래일자 없는 파일을 표시한다. 공백에서 해당 날짜를 유지해 같은 화면의 업로드를 열고 파일 입력으로 포커스를 옮긴다.
- 조회기간 확인·관리 시작일 폼을 제거한다. 구 거래 상세 업로드 화면은 새 공백 화면으로 연결한다. 긴 구간 목록은 접어서 펼치고, 파일 상세 및 처리 결과는 유지한다.
- 기존 조회기간 증빙 테이블·보호된 API는 호환/보존한다. 조회기간을 새로 확정하거나 운영 DB/원본/분류/환불/Google 장부를 쓰지 않는다. 스키마 변경 없음.

## 수락과 검증

| 항목 | 상태/근거 |
| --- | --- |
| 조회기간 없는 거래 파일 표시 | 구현·표적 API 검사 통과 |
| 파일 내부 공백 및 겹치는 자료로 공백 해소 | 합성 API 회귀 검사 |
| 카드 분리·다중 카드 파일 1회 집계·필터 | 합성 API 회귀 검사 |
| owner/CSRF·읽기 불변·구 증빙 revision 보호 | 기존 및 표적 검사 유지 |
| 조회기간 폼 제거·업로드 오류/복구 유지 | DOM 및 기존 브라우저 회귀 검사 |
| 1440/390/320px·긴 이름·빈 상태·오류 재시도·포커스·테마 | ego-browser 합성 미리보기로 검사, 비공개 증거 별도 보관 |
| 인증 운영 화면 | 미검증. 인증 우회하지 않음 |

UI 검토에는 better-interface, better-accessibility/layout/writing/typography/colors/ui와 interface-review를 적용한다. 기존 CSS 토큰·native 버튼·details·상태 live region을 재사용한다. state-machine/break 스킬은 이 환경에 없어 실제 사용으로 주장하지 않으며 같은 예외 상태를 합성 자료로 검증한다. 별도 PR은 이번 변경만 포함하며 기존 main의 다른 로컬 커밋 8개를 포함하지 않는다.
