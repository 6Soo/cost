# Python 기능군 리팩토링 검증 결과 · 2026-11-01

승인 범위와 업무 규칙은 [실행 명세](python-refactor-20261101.md), 운영 적용 결과는 [운영 기록](../../operations.md)에 기록한다. 기준 코드는 `bc723cfa6ddcc454ffe31125c08de0ba3d1a5239`다. 고객 원문과 운영 DB는 이 보고서에 포함하지 않는다.

## 전수 조사와 우선순위

기준 Git 추적 Python 835개를 AST로 조사했다. 실행 코드 199개, 유지보수 도구 198개, 보관 코드 6개, 테스트 432개다. 보관 코드와 도구를 실행 코드와 분리해 집계했고, 함수 길이·분기·동일 함수 본문·import 의존을 조사했다. 병렬 조사 결과의 함수 이름 일치만으로 중복을 판정하지 않고 실제 AST와 diff를 검토했다.

우선순위는 여행 후보/준비기간 정책, OTA 결제 매칭, 카드·은행 CSV 입력과 원본 검증, 담당자 메타데이터, 항공권 스냅샷과 장부 합계의 공통 읽기 순으로 정했다. 이들은 현재 업무 경로에 직접 영향을 주고 기능군별 검증 경계가 있다. 권한 동기화의 큰 재작성 초안은 동등성 근거가 부족해 채택하지 않았고, 동일한 무시 응답 DTO만 공통화했다.

메일 수집기들의 `collect`, HTTP의 `dispatch`, 저장소의 변경 함수는 이름이 같아도 원본 선택·인증·원자 저장 계약이 달라 일괄 통합하지 않았다. 이 조사 후보는 새 개발 큐가 아니다. 기존 미추적 파일·사용자 변경은 보존했다.

## 변경 구조

- `app.trip_selection`: 검증된 여행 기간 계산, 국내/해외 후보 필터, 기간 내/다음 여행 준비기간 후보를 공유한다. 열린 종료일의 반복 suffix 탐색을 역방향 1회 순회로 바꿨다. 카드 후보 점수의 반복 선형 검색도 사전 조회로 바꿨다.
- 카드 분류: 선택한 거래를 SQL에서 조회하고, 환불의 원결제가 선택 범위 밖이면 해당 의존 행만 추가 조회한다. 기존 수동 결정·원본·중복·환불 보호와 기록 원자성을 유지한다.
- OTA: 후보 인덱스 준비 → 고정 그룹 검증 → 반복 결제 그룹 생성/배정 → 개별 결제 선택 → 결과/관계 조립으로 분리했다. 방향·카드 끝4 인덱스로 불필요한 전체 카드 탐색을 줄였다. 외부 함수와 M:N 관계, 수동/legacy exact·고정 그룹 보호는 유지한다.
- `webapp.import_source`: 카드/은행의 CSV 읽기·헤더/공란 검증과 원본 SHA 검증을 공유하며 기존 오류 타입·코드와 import 경로를 유지한다.
- `webapp.owner_metadata`: 같은 읽기 트랜잭션에서 회사명을 조회한다. 화면·내보내기가 같은 함수를 사용한다.
- 항공 스냅샷은 요청별 저장소를 지연 조회하고, 합계는 기존 `board._shown_amount` 훅을 동적으로 호출한다.

모든 측정은 같은 합성 입력에서 전체 출력이 같음을 확인했다. OTA는 추가로 고정 난수 200개 시나리오를 비교했다. 여행 후보 순위 성능 입력은 모든 여행이 끝난 날짜여서 준비기간의 의도된 변경과 분리했다. 이는 CPU/조회 커널 측정이며 실제 페이지·운영 DB·네트워크 응답시간 개선율이 아니다. 운영 전체 처리 성능은 측정하지 않았다.

Rust는 도입하지 않았다. 현재 병목은 반복 탐색과 전체 행 로딩으로 Python 안에서 개선됐다. 순수 매칭은 향후 변환 가능한 경계지만, 현재 부하에서 추가 네이티브 인터페이스·자료 변환·Windows 빌드/롤백 경계를 정당화하는 이득은 입증되지 않았다. Rust 구현 비교 벤치마크를 했다는 뜻은 아니다. DB·권한·웹 렌더링은 기존 Python 생태계와 결합되어 유지한다.
