# OTA 근거가 있는 여행 미배정 카드의 복구 누락

현재 요청: 단순 개별 교정에 그치지 않고 발생 경로를 추적해 원인을 수정한다.

목적은 업종만 분류된 정상 구매가 영구적으로 사용자 확인에 남는 누락을 없애는 것이다. 자동 작업자와 자동 기록 요청이 여행 없는 자동분류를 미완료로 인식하고, 현재 OTA 이용기간을 우선하여 기존 분류·기록 경로를 재개한다. 여행까지 배정된 과거 미기록 전체를 재처리하지 않는다.

## 조사 근거

- 운영 대상은 업종 규칙으로 숙박비가 분류되었으나 여행 두 필드가 공란이며 revision 1이었다. 수동 답변·명시 보류·원본 오류·중복·기기록은 없었다.
- 초기 배치의 기본 분류 기록은 2026-10-31에 존재한다. 이후 자동 작업은 별도 미분류 거래들만 처리했고 대상은 저장 작업 ID에도 없었다. 당시 최종 추론 미적용의 외부 원인(중단 여부 등)은 로그만으로 확정하지 않는다.
- 자동 작업자의 후보 SQL과 자동 기록 요청의 복구 SQL이 상태/항목만 확인하여 `classified + item + 빈 여행`을 누락했다. 작업자의 기존 여행 복구 분기 역시 명시적으로 저장된 작업 ID가 없는 이 거래에는 도달하지 않았다.
- 현재 중앙 대사는 정확 카드 연결을 보유한다. 인증된 보관 메일 5건의 이용기간은 모두 2026-10-16~17이며, 그 기간을 포함하는 유효 여행은 `1015_오제` 하나다. 카드 날짜 기반 기존 추론도 같은 여행을 고르지만 재발 방지 검사는 결제일과 이용기간의 여행이 다른 합성 자료로 검증한다.

종료 조건은 합성 회귀/보호 통과, 정상 main 병합, 검증 SHA 배포, 보호 경로와 대상 운영 결과 확인이다. 실제 데이터 적용은 코드 배포와 분리해 위험에 맞는 복구·사본 검증·원자성 게이트를 거친다. Google 최종 장부 쓰기는 하지 않는다. 고객 원문/거래 식별자는 Git에 기록하지 않는다.

로컬 증거: `.local-archive/ota-trip-gap-20261102/` (Git 제외). 최초 단건 교정 리허설은 보호 비교에서 중단됐고 실제 DB에는 적용하지 않았다.

수정은 여행 공란 자동분류의 미완료 조건을 공통화해 두 진입점에서 사용한다. 작업자는 이 조건의 행에 현재 게시된 OTA 근거 분류를 먼저 실행한다. 이미 배정된 거래는 기존 근거를 유지한 채 기록만 재개한다. 분기 비용·대장 항공권·명시 결정·보류·중복/원본 오류·환불 원결제·기기록/기존 장부행은 보호한다. 읽기와 Google 쓰기 권한은 바꾸지 않는다.

최초 인접 검사의 Windows 임시 디렉터리 정리 실패1건은 해당 검사 단독 재실행1 passed, 후속 OTA/환불/권한 전체11 passed로 확인했다. 운영 사본은 중앙 게시본과 동일한 기존 작업자 출력(results/public 일치)을 사용했으며 원문 재대사·네트워크·운영 쓰기를 하지 않았다. 현재 변경된 후보는 대상1건뿐이고 `1015_오제`에 분류·내부기록1/9,906원, 원본/수동/금융 링크/다른 행/스키마 불변, 재실행0을 확인했다. 전체 회귀/실기기 검사는 수행하지 않았다.
