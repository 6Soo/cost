[제품 오너 결정 5개](specs/owner-product-decisions-20261028.md)가 우선한다. 여행 탭은 **수입 → 보험가입내역 → 지출**, 보험 확정 명단은 참가자의 기준이며, 수입의 보험 등록 열에서 드래그·직접 선택으로 연결한다. OTA는 **90일 경과 자동 숨김을 허용하지 않으며**, 유효한 단서가 적어도 여행을 잠정 배정해 사용자가 검토·교정한다. 금융 결제·환불의 최종 확정은 별도 보호한다.

## 반드시 유지할 현재 제품 결정

- **P1 코드 자동처리 → P2 AI 추론 분류 → P3 사용자 개입.** P2/P3의 처리·교정 근거를 검증된 코드 규칙으로 축적해 P1을 늘리고 P3를 줄인다. 조회·계산·추론으로 해결 가능한 일을 사용자에게 질문하지 않는다. [실행·질문·코드 승격 기준](specs/finance.md#p1-p2-p3-20261029)을 따른다.
- **사용자 작업함은 단 하나다.** 사람만 답할 수 있는 실제 예외만 최상위 `내 확인 필요`에 모으고, 자동 진행·재시도·기술 장애는 별도 사용자 대기열로 만들지 않는다. 보류 UI·보류 해제는 금지하며 내부 금융 안전 잠금만 유지한다. [통합 작업함 정본](specs/unified-expense-action-queue-20261105.md)을 따른다.
- **개별 검토는 판단 가능한 변경을 바로 처리한다.** 단순 변경 승인을 다시 묻지 않으며, 소수 여행 이동은 변경 전 값·이력으로 되돌린다. 별도 전체 백업·서버 중지는 복구가 어려운 작업의 위험에 맞춰 적용한다. 같은날·동액 연결, 사전승인/환불 요청 구분, 일정 변경 통합과 보고 기준은 [개별 거래 검토 실행 계약](specs/finance.md#review-execution-contract-20261029)을 따른다.
- **2026-10-29: 분류가 되면 완료다.** 자동분류에 별도 확정/미확정·잠정 후 승인 상태를 두지 않는다. 자동·수동 출처와 불확실성을 표시하고 수동 교정은 보호한다. [자동분류 완료 계약](specs/finance.md#자동분류-완료-계약-2026-10-29)이 과거 잠정 분류 문구보다 우선한다.
- **카드의 금융 유효성과 OTA 식별은 독립이다.** 정상 원행은 정확한 OTA 예약번호가 없더라도 실제 여행 최선 후보에 우선 배정하고 내부 비용 준비를 허용한다. 낮은 추론·복수 여행 후보의 불확실성을 표시하며 사용자의 수동 귀속을 재분류로 뒤집지 않는다.
- **원승인번호 환불은 1:N이다.** 동일 카드·발급사의 정상 원결제가 하나로 식별되면 복수 취소/부분환불 모두 확정 연결한다. 취소 건수 유일성·가맹점명·금액 차이로 이 연결을 단순 후보로 강등하지 않는다. 원결제 자체의 중복/오류·초과환불·수동 보류는 보호한다. 연결 확정은 기장이나 은행 환급 완료가 아니다.
- **항공권 이름 검색은 근거 조회다.** 명시 예약일이 없으면 같은 공급자·예약번호의 보관 인증 메일 중 최초 수신일을 한국 날짜로 표시하고 “최초 메일 수신일 기준”임을 밝힌다. 날짜·여정 충돌·취소·stale·기존 연결의 자동 후보 차단은 유지한다. 이름/당일 카드 후보만으로 결제·참가자를 확정하지 않는다.
- **Google이 최종 장부다.** 수입·이체는 사용자가 직접 입력하고 COST는 읽는다. 카드·현지 영수증은 COST에서 검토하고 사용자가 붙여넣는다. 추정 예약번호를 확정값처럼 복사하지 않는다.
- **수동 교정과 승인 범위를 보존한다.** 실제 금액·날짜·ID를 규칙으로 바꾸지 않는다. 승인된 업무 계약 안의 규칙 코드화·검증은 P1/P2/P3 원칙에 따라 자율 수행하고, 새로운 업무 정책·권한 결정만 P3로 올린다.
- **UI의 최신 계약은 아이콘 하나의 수동 테마다.** 일반 지출 검토에서 대량 자동 정리와 보호된 owner 유지보수 쓰기를 분리한다. 상세 화면 명세의 과거 “시스템 테마만 허용” 문구보다 이 결정이 우선한다.

R0~R6와 과거 UI 큐는 이미 수행 이력이 있다. [현재 상태](session_handoff.md)에 남은 구체적인 항목과 새 사용자 요청만 작업 대상으로 삼는다.
