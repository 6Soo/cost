## 1. 단일 주 에이전트의 실행 범위 및 우선순위

**동일한 주 에이전트가 운영/기술 결정과 마지막 수락까지 소유**한다. 하위 에이전트는 분리 가능한 코드 검토·테스트만 위임할 수 있고, 동일 Windows 호스트 배포·운영 DB·Gateway 변경은 **반드시 한 주체가 순차 처리**한다. 기존 미추적 파일·다른 checkout/worktree/작업자와 충돌하지 않는다. 이번 실행 범위는 #636/#644의 **증거가 없는 후속 작업**만이다; 별개 UI/항공권/과거 문서 PR #567/#607/#630을 새 개발 큐로 끌어오지 않는다.

### A. 진단/기준선 (먼저, 쓰기 없는 조사)

- [ ] `main`, [#646](https://github.com/6Soo/cost/pull/646) 최신 diff/CI, 작업 중 PR·현재 운영 고정 SHA/task/process/Gateway PID·route·SourceRefresh·공유 writer lock을 확인해 이미 반영된 것은 건너뛴다.
- [ ] 승인된 **읽기 전용** 운영 DB와 권한으로 자율 작업자 상태/일별 지표, `autonomous_ai_review` 실제 설정, 모델 실행기·실행 가능 여부, `blocked/pending/ai_dead/awaiting_agent` 등을 확인. 개인정보/원문/비밀값은 보고서에 복사하지 않는다.
- [ ] Gateway `ledger-gateway-status.json` 및 route 파일의 실제 변경/읽기, OTA/항공 검색 로그·스냅샷·SQLite WAL의 쓰기를 프로세스별로 구분한다. 개발 테스트 C: SSD I/O 제외. **기존 운영 상태에서 유휴 15분** Windows 성능 카운터/USN(가능하면 ProcMon) baseline을 파일별 write/rename 횟수·바이트·디스크 활성 지표·시간/배포 SHA와 함께 저장.
- [ ] #643의 60초 sweep·busy retry 및 #646의 30초 heartbeat가 유휴 D: I/O를 서로 증가시키는지 확인한다. 실제 작업 변화가 없는데 매번 DB/지표 파일을 쓰는지 **측정**하고 적정 감시 cadence를 판단한다.

### B. 자율 지출정리: 구현과 실제 무인 운영 수락

- [ ] #643/#647 현재 구현을 보존하고 호스트 연결 OpenCode 실행기·무료 모델/쿨다운·민감 정보 전송 제한·권한/opt-in 게이트를 검증한다. 기존 승인/정본 계약에서 허용되는 경우에만 호스트의 **명시적 게이트**를 활성화한다. 권한 또는 새 정책 승인이 필요하면 임의 우회하지 말고 해당 게이트만 차단 사유를 기록한다.
- [ ] 운영 변경 없는 격리/합성 경로에서 `업로드/변화 감지→P1→실제 연결 P2→유효 응답 preview/apply→durable 상태→내 확인 필요 P3 분리`를 하나의 E2E로 증명. 중복 업로드, 스냅샷 신선도, 재시작·모델 실행 실패/사용량 제한·dead-letter/재시도, 동시 작성/서버 후보(비활성) 중복 방지, 수동·환불·원본 충돌·금융 기록 보호를 포함.
- [ ] 호스트에서 안전하게 허용되는 최소 **실제 무인 트리거/로그·화면 읽기** 수락을 확보. 금융 실거래 대량 재분류/재기장/환불 확정·Google 쓰기를 수락 시험으로 수행하지 않는다. 진짜 신규 실거래가 관측되지 않으면 합성 E2E/호스트 프로세스 활성화를 완료 근거로만 기록하고 실거래 수락은 **UNVERIFIED**로 둔다.
- [ ] 원인 묶음은 현재 **탐지/기록만 한다**는 점을 확인. [정본](autonomous-expense-cleanup-20261105.md)에 따라 코드 결함을 별도 안전 작업으로 전환하는 최소 루프를 구현: `원인 묶음→재현/유사 사례 검색→범위 보존 regression test→격리 수정·PR/CI→(권한·보호 게이트 충족 시) 배포→관련 거래 재평가`. 모델 판단만으로 운영 소스 임의 패치·금융 정책 변경·DB 대량 교정 금지. 자동 코드 수정에 필요한 GitHub/에이전트/호스트 권한이 없으면 **코드 PR 및 검증까지 진행하고 적용 차단만 정확히 기록**한다.
- [ ] 지출정리 UI에서 자동 진행/자료 대기/안전 보호/사용자만 결정 가능/내부 비용 기록·Google 반영 구분을 확인. ‘내 확인 필요 N’에 전체 금융 보호 미결을 허위로 포함하거나 숨기지 않으며 목록·집계/필터·페이지네이션이 일치해야 한다.
- [ ] 사용자 최초 발견 오류 건수, 자동 P1/P2 처리, 진짜 P3, AI 실행 성공/실패/재시도, 근거 부족 보호, 시간 p50/p95를 **실제로 측정 가능하도록** 검사. 7일 지표는 관측된 기간만 보고하고 가상 감소율을 만들지 않는다.

### C. Gateway·HDD: #646 정리와 안전한 운영 전환

- [ ] #646를 최신 `main`과 대조해 rebase/충돌/CI/성능·안전 회귀를 해결하고, 검증 후 병합한다. **기존 서비스의 Gateway PID는 앱 SHA 배포만으로 갱신되지 않을 수 있음**을 검증한다.
- [ ] 배포 중 **긴 업로드·대기/재개·route generation·pause·drain 0 연결·stale/손상 status·PermissionError/OS 잠금·Gateway 죽음·후보 실패·롤백**을 합성 Windows 테스트로 검증. status heartbeat를 30초로 늘리면서 stale 판단 시간을 크게 늘린 것이 실제 오탐/안전성 후퇴인지 분석한다. 연결 수·세대는 변경 시 즉시 발행, 실패 시 배포 **fail-closed**, 금융 POST 재전송 금지.
- [ ] 필요하다면 Gateway 프로세스만 안전하게 교체하는 **별도의 인증된 설치/전환 절차**를 구현·리허설한다. Cloudflare/Tunnel·8790/8751/8752·단일 writer 및 작업 스케줄러 정체성을 검증하고, 허가되지 않은 직접 kill/restart로 운영 502를 만들지 않는다.
- [ ] 코드 배포 후보 및 Gateway 교체를 순차 진행: SHA/release blob/CI/보호13표 baseline→ready/인증 API→drain→공식 배포→task/process/PID·healthz/readyz·단일 listener·보호13표/Google 읽기 전용 사후 확인. 실패하면 검증된 기존 릴리스 유지/복구하며 실패를 PASS로 보고하지 않는다.
- [ ] **변경 후 동일한 유휴 15분** 측정을 수행, gateway 정기 status write 감소 목표 ≥90%를 검증한다. 이는 **HDD 전체 I/O·소음 90% 감소라는 뜻이 아님**. route 읽기·로그·OTA/항공 검색 스냅샷·WAL 등 다른 쓰기 경로는 분리한 실측으로 보고한다.
- [ ] #646가 OTA 정상 check 로그는 줄여도 **변경 없는 OTA/항공 색인의 스냅샷 통째 재쓰기 방지**까지 구현했는지 검사한다. 미구현이면 원본/세대·캐시 유효성·취소/환불·비결정적 JSON을 재현하고 필요한 최소 수정만 수행. 단순 파일 mtime만으로 같다고 판단하거나 상태/감사 로그를 삭제하지 않는다.

### D. 끝단 통합 수락과 문서 최신화

- [ ] **두 기능을 함께 실행한 합성/운영 안전성**: P1/P2 worker와 Gateway/snapshot 개편이 동시에 작동해도 중복 실행·불필요한 HDD 쓰기·자료 신선도 누락·기존 업로드/분류 누락이 발생하지 않아야 한다. 긴 요청 중 정상/실패 배포와 롤백을 포함.
- [ ] 관련 영향 QA/Windows 실제 테스트/CI 및 인증 PC·모바일 지출정리 UI 검증. 허가되지 않은 금융/Google 업무 쓰기, 원본/수동·환불·권한·감사·13개 보호 테이블 변경 0. 기존 baseline 실패는 새 결함과 구별하되 테스트 skip/권한 약화로 숨기지 않는다.
- [ ] PR 생성/검증/병합 및 운영 변경의 **실제 증거**를 [운영 기록](../operations.md), [최신 인계](../session_handoff.md), 양대 상세 명세의 **현재 상태 표**에 반영. 같은 사실을 새로운 복제 문서 여러 개에 추가하지 않는다.
- [ ] 완료 보고는 ELI10으로 **영역별 DONE/PARTIAL/BLOCKED**, PR/병합 SHA·운영 SHA·실제 에이전트 호출 증거·기능별 자동 해결/P3 건수·I/O 전후 횟수·남은 사용자 판단과 정확한 권한/검증 제약을 제시한다.

## 2. 중단·승인·재개 계약

- **승인 없이 가능한 일:** 읽기 조사, 비운영 합성 테스트, 기존 승인 계약 내 코드/테스트·문서 수정, GitHub PR 및 CI, 이전에 허용된 공식 보호 게이트를 충족하는 비파괴 코드 배포. 권한이 실제 없으면 우회하지 않는다.
- **명시 승인 필요:** 새로운 금융/분류 정책, 고객 원본 수정·대량 재분류/재기장·스키마/복원, Google Sheets 자동 쓰기(현 정책상 금지), 위험한 Gateway 강제 재시작·다운타임 허용, 보안·배포 게이트 우회, 새로운 유료 모델/API/비밀키. **승인되지 않은 변경만 BLOCKED로 남기고 나머지 독립 작업은 끝까지 수행**한다.
- **정지 조건:** active writer/호스트 신원 불확실, gateway route/status 불일치, drain timeout, 보호 13표 불변 실패, CI/브라우저 핵심 검사 실패, AI 응답 무결성·원본 버전 불일치. 기존 서비스·데이터를 우선 보존한 후 복구/명시적 중단 사유만 보고한다.
- 주 에이전트가 단독으로 전체 완료 여부를 판정하되, 문서/PR 작성만으로 `COMPLETE` 판정할 수 없다. 작업 도중 컨텍스트 제한·접속 중단이 있으면 인계에 현재 검증된 SHA/검사/미결 1~3개와 다음 안전한 실행 명령만 남겨 다른 에이전트가 **중복 없이** 이어받게 한다.

## 3. 완료 판정 요약

**CLEANUP COMPLETE:** 운영 호스트의 실제 실행 프로세스/모델·권한·지속 트리거 + 합성 P1→실제 연결 P2→복구·P3 예외만 표시 + 운영 인증 읽기 수락이 증명되었고, 코드 결함 발생 시 재현/PR·검증/허용 배포·재평가가 연결되어야 한다. 일시 모델 장애는 보호 보류·재시도되며 성공으로 위장하지 않는다.

**I/O COMPLETE:** #646 계열의 변경이 실제 Gateway 프로세스와 코드에 안전 적용됐고 15분 전후 유휴 I/O·Gateway status 감소율이 실측됐으며 route/업로드/무중단 전환/보호13표 등 운영 안전성이 확인되어야 한다. 측정 불가 항목·스냅샷 잔여 작업은 미완료로 정확히 구분한다.

**통합 COMPLETE:** 두 작업이 동시에 실행돼도 중복 I/O·금융 훼손·서비스 접속 중단 없이 운영되고, 두 영역의 수락 증거/운영 SHA/복구 절차가 기록되어야 한다.
