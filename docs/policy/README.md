# 영역별 판정 규칙 안내

현행 판정 우선순위는 [판정 규칙집](../DECISION_POLICY.md) §2·§3을 먼저 따른다. 이 폴더는 거래에 필요한 **상세 규칙과 한정된 예외**를 ID별로 검색하는 곳이다. 같은 사실을 여러 파일에 다시 적지 않고, 적용하는 영역의 규칙 ID를 가리킨다.

## 처리 단계별 찾아가기

| 단계·질문 | 읽을 규칙 파일 | 대표 ID |
| --- | --- | --- |
| 카드·메일·포털 자료를 믿고 쓸 수 있는가? | [수집·원본](source.md) | SRC-001, SRC-013, SRC-045 |

각 파일에는 현재 규칙만 남기고 주제별 제목을 붙였다. **규칙 ID·결정 유형(일반/사용자 예외/보호)·현재 본문·조건과 예외·사례**는 유지한다.

## 적용과 변경 원칙

1. 사용자의 실제 수동 결정과 범위가 정해진 예외를 먼저 확인한다. 최신 사용자 명시 결정 → 규칙집 → 코드의 권위 관계는 [규칙집 §2](../DECISION_POLICY.md)를 따른다.
2. 이 파일들의 제목은 찾기 위한 분류이며, **주제별 나열 순서가 판정 우선순위를 새로 만들지 않는다**. 충돌할 때는 공통 규칙과 각 ID에 적힌 예외·보호를 확인한다.
3. 기존 규칙을 수정할 때는 ID를 그대로 쓰고, 변경 전 문구·변경 근거를 Git 이력과 검수 기록에 남긴다. 새 규칙만 해당 영역의 다음 번호를 부여한다. 한두 건의 개별 교정을 범용 규칙으로 만들지 않는다.
4. 금융 원본·금액·부호·환불 짝·수동 교정·Google 최종 장부에 대한 보호는 문서 정리만으로 변경되지 않는다.
5. [코드·규칙 차이](CODE_GAPS.md)는 역사적 진단도 포함하므로 실제 수정 전 현재 코드와 재현 시험으로 확인한다.

## 과거 규칙과 출처 확인

2026-11-18 정리 이전의 **규칙별 출처·대체된 옛 규칙·당시 코드 비교**는 [고정 커밋의 원문](https://github.com/6Soo/cost/tree/c0c45c7fa9cdb291d198d5c3e9667801abb6721d/docs/policy)에서 동일한 ID로 찾는다. 정리 시점의 Git 저장 내용은 삭제하지 않았으며 새 문서는 과거 규칙을 현재 정책처럼 인용하지 않는다.

규칙 개정 과정은 [규칙집 §7](../DECISION_POLICY.md), 실제 구현·검증/배포 상태는 [현재 작업판](../agents/BOARD.md)과 [운영 기록](../operations.md)을 따른다.
