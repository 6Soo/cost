# M4 COST 전체 UI 설계 — Plush UI

> 상태: **설계 초안 작성**. 2026-11-16 사용자가 Plush UI 기반 전체 UI 설계를 요청했다. 구현·패키지 설치·운영 배포·Rust 전환 승인은 포함하지 않는다.
> 실행 정본은 [SPEC §11.2](../SPEC.md), 판정 정본은 [규칙집](../DECISION_POLICY.md)이다. 이 문서는 M4 화면의 상세 설계이며 판정 규칙을 새로 정의하지 않는다.

## 1. 확정 사항과 설계 방향

- 사용자 참조: Dominik Martin의 [Plush 데모](https://plush-ui.pages.dev/), [공개 소스](https://github.com/dominikmartn/plush-ui).
- 사용자 답변: **PC 장부 업무 중심, 모바일에서는 조회·영수증 등록을 편하게 한다.**
- 시각 기본안: Plush의 밝은 표면·초록색 선택·둥근 조작부·탄성 모션을 유지한다. 거래 목록은 비교하기 쉬운 표로 구성한다. 설명 당시 제시한 선택지 1·2의 차이가 불명확하다는 답변에 이를 설명했고, PC 중심 답변에 맞춰 이 기본안을 채택했다. 사용자가 1번을 명시 선택한 것으로 기록하지 않는다.
- 현재 단계는 M3 진행, M4 계획이다. 이번 요청으로 **M4 설계**를 구체화하며 M3 운영 전환이나 M4 구현을 시작하지 않는다.
- 기존 Claude Design 동기화 방침은 유지한다. 이 문서는 Claude Design에서 작업을 실행하거나 `/design-sync` 연결을 검증했다는 뜻이 아니다.

사용자에게 보일 변화: 서로 다른 모양의 화면을 하나의 앱으로 묶고, 장부·거래·영수증 사이를 이동해도 위치와 선택 맥락을 유지한다. 처리 결과와 실패 원인이 명확하게 보이며, 장식 때문에 업무 정보가 줄어들지 않는다.

## 2. 원본 조사 근거와 이식 범위

조사 기준은 upstream 커밋 `125a22ce151b719077637da38ffe9ec06a1a08c5`다. 구현 때 이 버전의 소스·라이선스·의존성을 보존하고, 최신 버전 자동 추종은 하지 않는다.

| 구분 | 확인한 사실 | COST 설계 |

## 3. 정보구조와 주소

[기존 정보구조 §5](../history/specs-20261110/uiux-full-audit-redesign-20261110.md)의 주 메뉴를 이어받는다. 그 문서의 과거 판정 대기·사용자 분기 검수 표현과 옛 영수증 복사 종결 흐름은 현 SPEC·규칙집·최신 영수증 명세로 대체한다.

| 주 메뉴 | 하위 화면 | 기존 주소 / 역할 |
| --- | --- | --- |
| 홈 | 정산 현황, 최근 여행, 자동화 실행 상태, 결과 바로가기 | `/`; owner |
| 여행 | 여행 목록, 여행 장부, 분기 기타비용 | `/trips`, `/board?tab=…`; 권한 있는 여행만 |
| 거래 | 카드, OTA 예약, 환불, 항공권 | `/cards/all`, `/ota`, `/board?tab=refunds`, `/flight-passengers`; 기존 권한 유지 |
| 영수증 | 파일 등록, 모델 선택, 작업·결과, 선택 반영 | `/receipts`; 기존 권한 유지 |
| 관리 | 계정·권한, 기본 정보, Google 장부 연결, AI 분기 검수 결과 | `/access/*`, `/google-ledger`, `/review`; owner |

- 여행 장부 안: `지출 / 수입 / 참가자·보험 / 항공권 / 예약 연결`. 국내여행·기능 설정에 따른 현재 표시 조건을 유지한다.
- `/participants/insurance-match`, `/reserve-links`, `/export`, `/expense/new`, `/income/new`, `/rules`의 기능을 빠뜨리지 않는다. 여행/거래 맥락의 보조 화면으로 연결한다.
- 전체 URL·query·필터 호환표를 구현 첫 단계에서 만든다. 주소를 열면 로그인과 권한 검증을 거쳐 동일 대상·탭이 열린다. 없는 여행은 404다.
- viewer에게 허용된 여행 화면만 제공한다. owner 메뉴를 숨기는 것과 별도로 API에서 대상별 권한을 검사한다. 새 직원 역할이나 권한 확대는 만들지 않는다.
- 상태·정렬·필터·선택 거래는 URL로 복원할 수 있게 한다. 파일·개인정보·모델 응답은 URL에 넣지 않는다. 뒤로 가기는 목록의 스크롤·필터·초점을 복원한다.

## 4. 앱 셸과 반응형 배치

### 4.1 PC

- 1024px 이상: 232px 사이드바 + 최소 너비 0의 본문. 본문 좌우 여백 24px, 큰 화면에서는 32px.
- 사이드바: 브랜드 한 번 → 주 메뉴 → 최근/진행 여행 바로가기 최대 8개 + 현재 분기 → 관리·테마·계정. 긴 여행명은 줄바꿈하거나 전체 이름을 열 수 있게 한다.
- 상단: 현재 위치, 여행 전환기(여행 맥락일 때), 관련 실행 상태. 본문에 고유한 h1을 한 번 표시한다. 불필요한 제목 반복을 제거한다.
- 장부는 넓게 사용한다. 폼·계정 설정은 읽기 쉬운 800px 안쪽으로 제한한다. 모든 페이지를 같은 최대 너비에 가두지 않는다.

### 4.2 태블릿·모바일

- 768–1023px: 고정 사이드바를 접고 상단 탐색과 메뉴 서랍. 장부 도구막대를 두 줄까지 배치한다.
- 767px 이하: owner 하단 탐색 `홈 / 여행 / 거래 / 영수증 / 더보기`; viewer는 허용 여행과 상단 탐색만 제공한다. 현재 작업의 하단 버튼은 탐색·안전영역과 겹치지 않는다.
- 모바일 장부 기본은 날짜·내용·금액·항목의 요약 행. 눌러 상세로 이동하고, 열 비교가 필요하면 별도의 표 보기에서 표 영역만 가로 스크롤한다. 문서 전체는 가로로 넘치지 않는다.
- 모바일 영수증은 원본/결과 전환 + 원본 작은 미리보기, 선택 건수와 반영 버튼은 고정 하단 영역에 배치한다. 사진 확대는 전체 화면에서 제공한다.
- 모바일에서 기존 수정·복사 기능을 제거하거나 권한을 바꾸지 않는다. 다만 고밀도 대량 편집을 위한 별도 새 기능은 만들지 않는다.
- 수락 폭: 320, 390, 640, 720, 1024, 1440, 1920px. 200% 확대·긴 한국어 여행명·세 자리 이상 건수도 시험한다.

## 5. 시각 토큰

값은 **설계 제안**이다. 구현에서 렌더링·모든 상태·테마 조합을 검증해야 한다. 공용 의미 토큰 `--cost-*`를 정본으로 삼고 `--plush-*`에 연결한다. 화면별 임의 hex 추가를 금지한다.

| 의미 토큰 | 라이트 | 다크 제안 | 용도 |
| --- | --- | --- | --- |
| background | `#fbfbfa` | `#181a18` | 앱 배경 |
| panel | `#f3f3f1` | `#222521` | 묶음·보조 영역 |
| surface | `#ffffff` | `#292d28` | 입력·표·서랍 |
| text | `#141414` | `#f5f5f2` | 본문·금액 |
| text-secondary | `#6e6e72` | `#b6bab4` | 보조 설명 |
| border-control | `#858581` | `#92998e` | 입력 경계; 실제 배경 대비 3:1 검증 |
| action / on-action | `#161616 / #ffffff` | `#f5f5f2 / #181a18` | 주 행동 |
| selection | `#16c26b → #b8e62e` | 같은 선택색 + 어두운 글자 | 선택·진행 강조 |
| success-text | `#17643b` | `#80dda5` | 성공 문구 |
| danger-text | `#b42318` | `#ffb4ab` | 오류·파괴적 동작 |
| focus | `#141414` | `#f5f5f2` | 두께 2px, 바깥 간격 3px |

- 원본의 희미한 `#a3a3a6` 글자는 흰 배경 대비 약 2.52:1이다. COST의 의미 있는 본문·안내에는 사용하지 않는다.
- 기본 주 행동은 원본처럼 검정(다크에서는 밝은색)이다. 초록 그라데이션은 선택·진행·완료 피드백에 쓴다. 초록 배경의 글자는 어두운색으로 한다.
- 본문 Pretendard Variable 16px/1.5, 표 14px/1.45, 보조 13px/1.5, h1 28px/1.25, 요약 금액 28px/1.2. 모바일 입력은 16px 이상. 금액은 우측 정렬·tabular-nums, 통화와 부호를 보존한다.
- 간격 4/8/12/16/24/32px. PC 행 높이 기본 48px, 긴 내용은 자동 확장. 터치 가능한 버튼·입력은 44px 이상. 표 안 작은 아이콘도 클릭 영역은 44px를 확보한다.
- 반경: 큰 요약 패널 28px, 표 컨테이너 20px, 입력·목록 12–16px, 버튼·탭 999px. 표의 모든 셀을 둥글게 만들지 않는다.
- 그림자: 원본의 얕은 그림자를 선택된 탭·떠 있는 서랍·대화상자에 집중한다. 다크에서는 경계와 표면 차이도 함께 사용한다.
- 아이콘은 단일 세트·단일 선 굵기로 통일한다. 의미가 있는 버튼은 이름을 제공하며 색이나 아이콘만으로 상태를 전달하지 않는다.

정적 대비 계산 예: `#141414 / #ffffff` 18.42:1, `#6e6e72 / #f3f3f1` 4.57:1, 선택 그라데이션 양끝 위 어두운 글자 7.86:1·12.63:1, 다크 보조 글자/패널 7.88:1. 이는 일부 색쌍 계산이며 전체 UI 대비 통과 선언이 아니다.

## 6. 공통 컴포넌트와 모션

| COST 컴포넌트 | 기반 | 책임 |
| --- | --- | --- |
| ActionButton, SelectionControl | Plush button/checkbox/switch/radio-group/toggle-group | disabled·실행 중·실패·완료 상태, 중복 전송 방지 |
| ContextTabs, FilterBar | tabs/select/calendar/input | URL 동기화, 필터 초기화, 적용 범위 표시 |
| AppShell, TripSwitcher | COST 추가 + Plush 버튼·선택 | 역할별 탐색, 맥락 복원, 건너뛰기 링크 |
| LedgerTable, MobileTransactionList | COST 추가 | 정렬·페이지·열 구성·조회 합계, 원본 금액 표시 |
| TransactionDrawer | COST 추가 + Radix dialog 기반 | 원본·판정 근거·교정 이력, 닫은 뒤 초점 복원 |
| ReceiptWorkspace | COST 추가 + Plush 입력·선택·진행 | 영속 작업 조회, 원본/결과 비교, revision·선택 반영 |
| JobStatus, InlineNotice | progress/progress-ring/badge/sonner | 실제 작업 상태와 오류, 반복 알림 억제 |
| FormField, EmptyState, ErrorState | input + COST 추가 | 가시 라벨·오류 위치·복구 행동 |

모션 규칙:

- 포인터 누름은 작은 압축, 스위치·탭은 원본의 스프링 감각을 유지한다. 스프링 곡선과 지속시간은 항상 짝으로 조절한다.
- 원본 tempo 0.7에서 스프링 정착은 약 732–895ms다. 이를 단순히 “모든 모션 200ms”로 바꾸지 않는다. 입력·선택 상태는 즉시 갱신하고 시각 효과만 뒤따르게 한다.
- 색·불투명도 전환 120–200ms, 서랍·대화상자 이동 목표 200–300ms. 목록 정렬·페이지 변경에 행별 순차 등장이나 금액 count-up을 사용하지 않는다.
- 금액은 서버의 정확한 값을 즉시 표시한다. 모션 도중 중간 금액을 실제 값처럼 보여 주지 않는다.
- 진행률은 서버가 분모와 완료 수를 제공할 때만 백분율/링으로 표시한다. 완료 시각·분모를 모르면 `처리 중`과 실제 단계만 표시한다. 데모의 자동 반복 연출을 업무 화면에 넣지 않는다.
- 완료 피드백은 같은 작업 revision당 한 번. 재접속·폴링마다 토스트·완료 모션을 반복하지 않는다. 중요한 실패는 토스트 외에 해당 영역에 남긴다.
- `prefers-reduced-motion`에서는 위치·크기·탄성을 제거하고 필요한 상태 변화만 유지한다. 비활성 탭의 모션·폴링을 줄여도 서버 작업은 계속한다.
- CSS anchor positioning·`linear()` 등 미지원 환경에서는 정적 선택 표시/기본 easing으로 기능을 보존한다. 지원 범위는 구현 시 실제 브라우저로 확인한다.

## 7. 화면별 상세 동선

### 7.1 홈 — 정산 현황

상단은 현재 분기·최근 갱신 시각, 그 아래 여행별 손익 요약과 최근 여행을 둔다. 자동화 상태는 수집·판정·AI 분기 검수의 실제 실행 상태와 마지막 성공을 보여 준다. 장애가 있으면 관련 작업으로 이동하는 복구 행동을 제공한다.

`확인할 거래 N건`, 사용자 분류 대기함, 매일 승인할 목록은 만들지 않는다. AI 검수 결과는 완료 보고와 붙여넣기 결과로 연결한다. 직원·가이드 정산 집계는 아직 정의되지 않았으므로 카드나 메뉴를 미리 만들지 않는다.

### 7.2 여행 목록과 여행 장부

- 여행 목록: 진행 중/마감/이전/보관/분기 기타비용, 검색, 수입·지출·차액. 여행 생성은 Google 탭이라는 기존 출처를 유지한다. `여행 만들기` 버튼을 새로 만들지 않는다.
- 장부: 여행 전환 → 손익 요약 → 업무 탭 → 필터 → 표. 주 행동은 `Google 장부용 복사`, 내보내기는 보조 행동, 여행 관리는 더보기로 묶는다.
- 표 기본 열: 날짜 / 가맹점·내용 / 항목 / 금액 / 근거 요약. 결제수단·이용기간 등 기존 업무 열은 열 설정이나 상세에서 접근 가능하게 한다. 저장된 개인 열 설정은 권한 범위 안에서만 복원한다.
- 정렬·필터 결과의 합계는 `조회 합계`, 전체는 `전체 합계`로 구분한다. 페이지에 보이는 행을 전체로 가장하지 않는다. 검색으로 선택 행이 가려져도 선택 범위를 명확히 표시한다.
- 행을 열면 상세에서 원문·판정·근거·이력을 본다. 사용자의 기존 교정 기능은 유지하되 기본 화면에 건별 승인/확정 버튼을 추가하지 않는다.
- 마감 분기는 읽기 전용 조건을 그대로 적용하고 사유를 짧게 표시한다. 닫힌 기간을 UI 편의로 재개방하지 않는다.
- 복사 전후의 형식·집합·건수·합계·붙여넣기 순서를 서버 산출물 기준으로 유지한다. 복사 성공과 Google 반영 완료는 구분한다.

### 7.3 거래 허브

카드/OTA/환불/항공권의 상위 탭과 공통 필터 형식을 통일한다. 카드 업로드·수집 현황은 상단 보조 패널에서 열고 목록 공간을 유지한다. OTA 추가 조회는 펼침 상태와 활성 필터 수를 표시한다.

원결제·부분환불·전체환불은 서버가 제공한 관계로 보여 준다. 화면에서 부호를 바꾸거나 상계값을 원문 금액처럼 대체하지 않는다. 카드→여행 장부와 장부→원거래 링크가 같은 거래를 가리킨다. 연결 없음은 실제 사실 조회 조건이며 사용자 처리 대기 상태로 바꾸지 않는다.

### 7.4 영수증 — 원본과 결과 비교

정본은 [영수증 처리 변경](receipt-paseo-workflow-20261116.md)이다. 별도 구현 세션의 API·영속 계약을 이어받으며 이번 설계에서 변경하지 않는다.

```text
영수증             [파일 등록]                       작업 목록
┌─────────────────────────┬───────────────────────────────────────┐
│ 원본 목록 · 선택 사진    │ 실제 작업 상태 · 선택 모델 · 저장 시각  │
│                         │                                       │
│ 사진 확대 / 이동         │ 상호  [합성 상점 A             ]       │
│                         │ 날짜  [2026-11-03              ]       │
│ PDF 페이지·실물 영역     │ 금액  [12,000]  통화 [KRW]             │
│                         │ 여행  [합성 여행 A ▾]  항목 [식비 ▾]   │
│                         │ [✓] 이 내역 선택     수정 저장 상태    │
└─────────────────────────┴───────────────────────────────────────┘
원본 저장됨 · 다른 화면에서도 처리 계속            [선택 1건 반영]
```

- 파일 등록 후 provider 탐색, 모델의 `이 모델로 처리`가 실제 실행이다. 방향키·목록 복원·provider 선택으로 실행하지 않는다. 미지원·승인 미확인 모델은 이유와 함께 선택 불가다.
- 작업 목록은 서버 영속 상태를 표시한다. 다른 화면 이동·탭 종료 후 복귀해도 작업·결과·교정을 복원한다. 브라우저 저장소를 유일한 복구 수단으로 쓰지 않는다.
- 원본 패널은 PC에서 약 45%, 결과는 55%, 구분선으로 조절 가능하게 한다. 작은 폭에서는 세로 배치/원본·결과 전환으로 바꾼다. 드래그 외 버튼/키보드 조절도 제공한다.
- 결과 선택과 입력 수정은 별도 상태다. 반영 직전 최신 revision·반영 이력을 서버에서 검증한다. 충돌 시 입력을 버리지 않고 최신 결과와 차이를 표시한다.
- 선택 묶음은 명세대로 원자적·멱등 반영. 응답 유실 뒤 재시도에서도 중복 등록하지 않는다. 완료는 실제 장부 행과 연결한다. 화면 선택 건수만 줄여 성공으로 표시하지 않는다.
- 일부 사진 실패는 해당 사진에서 사유·재시도를 제공한다. 다른 모델 자동 대체나 반복 자동 전송은 하지 않는다. 인증 인계가 필요한 경우에만 해당 동작을 요청한다.
- 영수증 결과의 사용자 검수는 명시 승인된 예외이며, 카드·분기 판정을 사용자에게 넘기는 화면으로 일반화하지 않는다.

### 7.5 관리·보조 화면

- 계정·권한은 허용 대상과 실제 저장 결과를 표시한다. viewer에게 권한 없는 자료·요약 수치도 내려주지 않는다.
- Google 연결·비교·복사는 현재 기능을 보존한다. 자동 최종 장부 쓰기나 새 외부 효과를 추가하지 않는다.
- AI 분기 검수는 기간·실행 상태·결과·교정 집계·결과 산출물을 보여 준다. 사용자가 거래를 승인하는 화면을 만들지 않는다. 새 모델 실행 버튼/과금 경로는 현재 계약이 있을 때만 연결한다.
- 수입·참가자 대조, 보험 대조, 수기 입력, 예약 연결, 내보내기는 동일 공용 폼·오류·표 컴포넌트를 사용한다.
- 오류·빈 상태는 제목 하나와 실제 이유, 가능한 다음 행동을 제공한다. 빈 데이터/권한 없음/연결 실패/아직 조회하지 않음은 서로 다른 상태다.

## 8. 구현 구조와 서버 계약

### 8.1 구조 제안

새 React/TypeScript 프런트는 정적 자산으로 배포하고 같은 origin의 인증 JSON API를 사용한다. Plush 데모가 Next.js라는 이유로 COST에 Next.js 서버를 추가하지 않는다. Rust API를 최종 대상으로 하며, 전환 중 승인된 기존 Python 서비스를 API 어댑터로 호출할 수 있다. 프런트가 어느 코어가 작성자인지 결정하지 않는다.

```text
frontend/src/
  app/                 셸·경로·권한·테마
  components/plush/    고정 upstream에서 가져온 컴포넌트
  components/cost/     공용 표·서랍·폼·작업 상태
  features/            home·trips·ledger·transactions·receipts·admin
  api/                 서버 계약·요청·오류 변환
  styles/              의미 토큰·Plush 매핑·테마·모션
```

이는 제안 경로이며 현재 레포에 이 구조가 존재하거나 구현됐다는 뜻이 아니다. 컴포넌트 갤러리에 light/dark, 입력·선택·오류·긴 문구·모션 감소 예시를 모아 Claude Design 동기화의 기준으로 삼는다.

### 8.2 API 구현 전에 확정할 계약

| 대상 | 필요한 계약 | 보호/검증 |
| --- | --- | --- |
| 세션·권한 | 역할, 허용 여행, 가능한 동작 | 서버에서 모든 조회·쓰기에 검증 |
| 여행·장부 | 안정 ID, revision, 통화·부호, 정확한 합계, 정렬·페이지 | 금액은 정밀도를 보존하는 문자열/정수 계약; JS 부동소수점 합산 금지 |
| 거래·근거 | 원거래↔예약·환불·판정·이력 참조 | 근거 원문은 인증 경로로만 조회 |
| 사용자 교정 | 변경값, 대상 revision, 감사 이력 | 기존 수동 교정 우선·마감 보호 유지 |
| 작업 | 실제 상태, 단계, 갱신 시각, 가능하면 분모·완료 수 | UI가 완료/진행률을 추측하지 않음 |
| 영수증 | 기존 영속 API의 배치·사진·결과·revision·멱등 키 | 최신 명세/구현 계약을 재사용, 별도 큐 금지 |
| 복사·내보내기 | 서버가 만든 집합·형식·건수·합계·산출 시점 | 화면에 로드된 일부 행으로 전체 파일을 만들지 않음 |

구체 endpoint 이름과 JSON 스키마는 구현 직전 현재 API를 대조해 정한다. 이 표는 이미 존재하는 API 목록이 아니다. UI는 HTML을 파싱해 업무 데이터를 얻거나 기존 Python 함수를 브라우저에 복제하지 않는다.

같은 origin 인증·현재 세션·CSRF 보호를 유지하고 원문을 외부 분석/모니터링 서비스로 보내지 않는다. 로그아웃/계정 전환 시 민감한 메모리 캐시를 비운다. 개발 fixtures와 캡처에는 완전 합성 자료만 사용한다.

## 9. 이행 순서와 완료 조건

M4 구현이 요청되면 다음 순서로 진행한다. M3의 안전한 작성자 전환과 별도 진행 중인 영수증 구현을 이번 문서로 대체하지 않는다.

| ID | 묶음 | 완료 조건 |
| --- | --- | --- |
| UI-0 | 계약·기능 지도 | 모든 기존 경로·권한·폼·쿼리·산출물을 대조하고 API 빈틈 표시 |
| UI-1 | 토큰·공용 컴포넌트 | Plush 버전·라이선스 고정, 두 테마·한국어·초점·모션 감소 갤러리 |
| UI-2 | 셸·장부 대표 화면 | 합성 자료로 탐색·필터·표·상세·뒤로 가기·모바일을 수락 |
| UI-3 | 장부·여행·산출물 | 서버 합계와 표시·복사·내보내기 일치, 조회/교정 권한·마감 보존 |
| UI-4 | 영수증 | 원본/결과·복귀·충돌·선택 묶음 반영을 기존 영속 구현과 연결 |
| UI-5 | 거래·관리·보조 화면 | 누락 기능 0, URL 호환·viewer·오류 화면 수락 |

- 개발 중 old/new 경로는 명시적으로 분리하고 새 UI는 합성/허용 사본에 연결한다. 운영 포트 8751·8752·8790을 미리보기에 쓰지 않는다.
- 화면 단위로 전환하되 업무 데이터 작성 경로는 하나다. React 도입을 위해 두 코어에 동시에 쓰거나 신규 DB 이관을 수행하지 않는다.
- 되돌림은 해당 경로의 렌더러/정적 자산 버전을 이전으로 바꾸는 절차로 설계한다. 새 UI에서 정상 반영한 업무 데이터를 삭제해 되돌리지 않는다.
- 임의의 개발 기간·성능 향상을 약속하지 않는다. UI-0에서 API 공백과 실제 데이터 크기를 측정한 뒤 구현 범위를 산정한다.

P-06의 라벨 검사는 가시 라벨·접근 가능한 이름의 일치를 뜻한다. 실제 스크린리더 실청취·실기기 검증은 자동 DOM 검사와 구분해 기록한다.

검사는 변경 기능의 표적 검사와 저장소 영향 검사로 수행한다. 0건·건너뜀을 통과로 기록하지 않는다. 브라우저 검증은 ego-browser, 운영 배포는 기존 배포 절차를 사용한다.

## 11. 현재 완료·미실행·다음 작업

- 완료: 원본 특정, 공개 소스/의존성/라이선스/라이트 전용 확인, 사용자 환경 답변 반영, 정보구조·토큰·화면·모션·서버 계약·이행·수락 기준 설계.
- 일부 색쌍은 정적 대비를 계산했다. 전체 테마·컴포넌트·브라우저 수락 통과를 주장하지 않는다.
- 이번 산출물은 문서다. React 코드·패키지·데이터·판정 규칙은 변경하지 않았고, 앱 검사·새 미리보기·배포는 실행하지 않는다.
- 필수 미답 질문 없음. 글꼴·반경·모션 세부값은 위 기본안으로 구현 시 검증·조정할 수 있다.
- 다음 구현 요청이 오면 UI-0부터 시작한다. Claude Design 사용 환경·API 공백·실제 upstream 호환성은 그때 기술 확인하며, 현재 설계 완료를 막는 사용자 질문으로 돌리지 않는다.

설계 보조 검색은 `ui-ux-pro-max`를 사용했다. 전체 디자인 추천의 Enterprise Gateway/OLED 결과는 회계 앱과 참조 이미지에 맞지 않아 채택하지 않았다. 재검색한 `data tables`의 표 넘침·묶음 선택 지침은 참고했고, 시각 토큰은 확인한 Plush 소스와 COST 수락 기준에서 도출했다.
