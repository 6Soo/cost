[User] 당신은 아키텍처 검토 모델이다. 아래 현재 파이프라인 구조를 읽고, "구글 스프레드시트 기반 비용 파이프라인을 DB+웹앱으로 전환"하는 제안에 대해 기술적 아키텍처 관점에서 검토하라.

## 현재 파이프라인 구조

### 핵심两 축
1. **비용분류 파이프라인** (`ledger/`, Python): 카드 4장 + 수기장부 → SQLite 분류·대사 → 매출확인자료
2. **Apps Script 엔진** (`apps-script/`, GAS): 카드 RAW → Google Sheets 장부 자동전기

### 현재 기술 스택
- **입력**: 카드사 RAW CSV(4곳), 수기장부 CSV, OTA 데이터, Gmail 영수증
- **처리**: Python 스크립트 체인 (8단계 순차: build_v13 → fix_v14 → patch_v14 → build_workbook → gen_rev × 2 → consolidate)
- **저장소**: SQLite DB + Google Sheets 원장 (단일 시트, 여행탭 41개)
- **출력**: Excel 워크북 (36시트, 1,833행, ~320M원)
- **자동전기**: Apps Script → Google Sheets 직접 기록

### SQLite 스키마 (도메인 분리 모델 v2, 테이블 15개+)
- 원천 계층: source_documents, source_records, direct_source_records
- 결제 계층: payment_methods, payment_transactions, transaction_sources, cancellations
- 배분 계층: allocation_plans, allocations, allocation_targets
- 예약/여행: reservations, trips
- 판정/근거: decisions, evidence
- 장부: journal_entries, journal_line_items
- 검증: review_snapshots, baselines

### 현재 파이프라인 실행 (8단계)
```
cd ledger
python3 build_v13_trip.py       # CSV + 수기 → classified_v13
python3 fix_v14.py              # v13 + cardindex → classified_v14
python3 patch_v14.py            # 수기 마스터 재주입
cd data
python3 build_workbook_v76.py   # → Excel 워크북
python3 gen_april_rev.py        # → 4월 매출확인자료
python3 gen_mayjun_rev.py       # → 5-6월 매출확인자료
python3 consolidate_2q.py       # → 2분기 통합
```

### 현재 문제
- Google Sheets를 "원장"으로 쓰되 처리는 오프라인 Python
- Apps Script가 별도로 Sheets에 자동전기
- 수기장부와 자동분류가 분리
- 워크북 버전이 76까지 감 (build_workbook_v64~v76)

## 검토 대상 제안
"비용 파이프라인을 수기+자동화 통합 관리하는 웹앱으로 전환"

## 아키텍처 관점 검토 포인트
1. **MSA vs 모놀리식**: 현재 Python 스크립트 체인을 웹 서비스로 바꿀 때 적절한 아키텍처는?
2. **데이터 레이어**: SQLite → PostgreSQL? 아니면 SQLite 유지 + 웹 프론트만?
3. ** Apps Script 대체**: 자동전기를 어떻게 통합? 웹앱이 Google Sheets를 대체하는가?
4. **배포**: Vercel? self-hosted? 1인 운영 환경에서 적절한 선택은?
5. **점진적 전환**: Big Bang 전환 vs 기존 파이프라인 병렬 운영 → 점진적 마이그레이션?
6. **비용**: 인프라 운영 비용 (서버, DB, 배포) vs 현재 무상(Google Sheets + 로컬 Python)

기술적 현실성을 기반으로 구체적인 아키텍처 제안과 전환 경로를 제시하라.
현재 저장소의 인계·비용분류 규칙을 확인한 뒤, 운영 규모(1인·회계 원장·Google 연동)를 기준으로 전환안을 검토하겠습니다.
