# 모든 Codex 작업용 무손실 중단·데스크톱 이전 프롬프트

아래 블록을 각 Codex 작업의 새 메시지로 그대로 붙여 넣는다.

```text
현재 노트북의 CPU와 RAM이 포화되어 데스크톱 환경으로 작업을 이전한다.
이 지시는 이 작업의 최우선 현재 지시다.

1. 즉시 새로운 실질 작업을 중단하라. 새 브라우저 탭, 다중 자동 브라우징, 서브에이전트,
   장시간 테스트, OCR/LLM 대량 호출을 시작하지 마라.
2. 네가 이 작업에서 직접 시작한 실행 프로세스·브라우저 탭·서브에이전트만 안전하게 종료하라.
   사용자 또는 다른 작업이 시작한 프로세스·탭·파일은 건드리지 마라.
3. 저장소에 AGENTS.md가 있으면 그 시작 순서에 따라 필수 문서를 끝까지 읽어라.
   기존 사용자 결정과 저장소 정본을 임의로 재해석하거나 축약하지 마라.
4. 현재 실제 상태를 무손실 핸드오프로 남겨라. 최소한 다음 내용을 포함하라.
   - 작업의 목표와 적용 중인 사용자 지시
   - 완료·부분완료·미완료 항목
   - 사용자가 이미 확정한 판단과 아직 필요한 판단
   - 실행 중이거나 중단한 브라우징·외부 연결·자동화 상태
   - 생성·수정·미추적 파일과 절대경로
   - Git 브랜치, HEAD 커밋, 원격 동기화 여부, git status
   - 실제 실행한 테스트와 결과, 실행하지 못한 테스트 및 이유
   - 재개 시 첫 5개 실행 순서
   - 첨부파일처럼 Git에 넣을 수 없는 자료의 경로·파일명·가능하면 SHA-256
5. 저장소가 있으면 프로젝트의 기존 핸드오프 문서와 LOG 최신 블록에 위 상태를 기록하라.
   기존 기록을 지우거나 덮어쓰지 말고 새 블록으로 추가하라.
6. 변경사항을 보존해야 다른 PC에서 이어갈 수 있다. 다음 안전조건을 지켜라.
   - 사용자 파일, 다른 작업의 변경, 비밀정보, 인증정보, 원격 첨부 폴더,
     생성 산출물은 임의로 stage하지 마라.
   - 현재 작업 범위의 코드·테스트·문서만 전용 codex/ 브랜치에 stage·commit하라.
   - 파괴적 Git 명령(reset --hard, checkout --, clean 등)을 사용하지 마라.
   - 원격 push가 허용되고 안전하면 push하고 브랜치명·커밋 SHA를 보고하라.
   - push할 수 없으면 그 이유와 데스크톱에서 옮겨야 할 정확한 파일 목록을 보고하라.
7. 사용자가 명시하지 않은 워크북·CSV·보고서 등 최종 산출물을 새로 만들지 마라.
8. 아카이빙은 기록 보존 수단이지 전역 기억이 아니다. 새 데스크톱 작업이 반드시 읽어야 할
   핸드오프 파일의 경로와 시작 프롬프트를 마지막 답변에 적어라.
9. 위 보존 절차가 끝나면 더 진행하지 말고 다음 형식으로 10줄 이내 보고하라.
   - 상태: 보존 완료 / 부분 보존 / 차단
   - 브랜치:
   - 커밋:
   - 원격 push:
   - 핸드오프 파일:
   - 사용자 판단 대기:
   - 중단한 실행:
   - 데스크톱 첫 실행:

cost 프로젝트라면 추가로 다음을 적용하라.
- docs/CODEX_DESKTOP_MIGRATION_HANDOFF_2026-07-26.md를 최우선 인계서로 채택하라.
- 카드 이벤트 무손실, OTA N:M 교집합 충돌차단, 2025년 이전 제외,
  Agoda 선순위, 예약 1건마다 SQLite 즉시저장을 유지하라.
- 사용자 명시 전 워크북·CSV를 생성하지 마라.
```
