# 분기 검수

- 목적: 한 분기의 판정을 AI 검수자가 다시 보고 교정해, 사용자가 건별 판단 없이 Google 지출표에 붙여넣을 수 있는 장부와 검수 보고를 만든다.
- 실행 주체: 프론티어 모델 — Fable 5.2 high 에이전트(대체: 그때의 최상위 Claude 모델). 근거는 [통합 명세 §8](../SPEC.md#8-분기-검수와-교정-환류), 규칙집 PROC-068.
- 주기: 분기마다 한 번.
- 개정 이력: 2026-11-13 · 사용자가 하던 판단과 교정을 AI 검수자에게 위임, "먼저 볼 50건" 사용자용 목록 폐지 · 소유자 결정 "내가 볼 50건이 있는 것 자체가 현재 프로젝트 방향에 맞지 않는다".

## 누가 무엇을 하나

| 주체 | 하는 일 |
| --- | --- |
| AI 검수자 | 검수 자료 생성, 표본·전수 판정, 교정, 규칙집 개정, 검수 보고 |
| 사용자 | 결과를 받아 보고 Google 지출표에 붙여넣기. 로그인·인증 인계. 규칙이 없거나 규칙끼리 모순일 때의 정책 결정(질문 단위) |

사용자에게 건별 검토 목록을 주지 않는다. Google 장부에 자동으로 쓰지 않는다.

## 입력 — 검수 자료 만들기

운영 서버를 재시작하거나 Google 장부에 쓰지 않고 파일을 만든다. 출력 폴더에는 고객 자료가 있으므로 Git 밖의 비공개 경로를 쓴다.

```powershell
python tools/quarter_review/pack.py --host-root D:/WebLedgerHost --year 2026 --quarter 3 --out D:/WebLedgerHost/data/backups/quarter-review-2026Q3/<날짜>/ --basis-note '<이번 실행의 기준>'
```

| 파일 | 누가 쓰나 | 내용 |
| --- | --- | --- |
| `review-list.csv` | 검수자 입력 | 사유가 있는 행 전체. 순위는 오류 확정이 아니라 볼 순서다. 수동 교정은 합계에 포함하고 목록에서는 제외한다 |
| `review-pack.xlsx` | 사용자 결과 | 여행별 손익 → 분기 기타비용 → 판정 주체. 건별 목록 시트는 없다 |
| `trips.csv`, `quarter-other.csv`, `sources.csv` | 양쪽 | 위 시트와 같은 내용 |
| `notes.md` | 양쪽 | 조회 시각·수입 미확인 원인·합계 기준과 한계 10줄 |

XLSX는 기존 openpyxl 설치가 필요하며 새 의존성은 추가하지 않는다.

## 단계

1. **검수 자료를 만든다.** 성공 기준: 판정 없는 정상 거래 수와 사유별 건수가 `notes.md`에 나온다.
2. **사유별 표본을 본다.** 사유(AI 판정, 최근 자동 변경, 추론 귀속, 포괄 항목)마다 20건씩 카드 원행, 예약 메일·포털 근거, 여행 기간, 규칙집으로 맞는지 판정한다. 성공 기준: 사유별 표본 정답률.
3. **원인 단위로 묶는다.** 같은 원인의 오판이 여러 건이면 규칙 문제다. 규칙집을 고치고(같은 ID 개정, 옛 내용 보존) 다시 판정할 대상을 정한다. 한두 건짜리 오판은 건별 교정 대상으로 둔다.
4. **전수 범위를 정한다.** 정답률이 낮은 사유·가맹점·패턴은 끝까지 본다. 정답률이 높은 묶음은 표본으로 승인하고 전수를 생략할 수 있으며 그 판단과 근거를 보고에 적는다.
5. **교정한다.** 기존 정식 경로로만 한다: 서버 인증 API의 교정 경로(열린 분기 한정, 요청당 50건 이하) 또는 미리보기·`--apply`·digest·신선 백업 게이트·감사 원복을 갖춘 유지보수 도구. 운영 DB에 직접 쓰지 않는다. 반영 전에 변경 전 값을 비공개 폴더에 저장한다. 출처는 AI 검수(모델 이름)로 적고 사용자 결정 표기(`user_decision`)를 쓰지 않는다. 서버를 멈춰야 하는 반영은 배포 담당 세션에 정확한 명령·예상 건수·백업 증거 경로를 넘긴다.
6. **사용자 결정 필요를 추린다.** 규칙이 없거나 규칙끼리 모순이거나 사업 판단이 필요한 것만, 건별이 아니라 질문 단위로 예시를 붙인다. 0건이 가장 좋다.
7. **다시 생성한다.** 새 날짜 하위 폴더로 검수 자료를 다시 만들어 이전 자료를 보존하고 전후 수치를 비교한다.
8. **보고한다.** `docs/agents/artifacts/ai-quarter-review-<연도>Q<분기>.md`에 사유별 표본 정답률, 원인별 묶음과 처리, 교정 건수(여행 귀속·항목·이용기간별), 개정한 규칙 ID, 사용자 결정 필요 질문, 검수 전후 수치를 식별값·금액 없이 적는다.
9. **사용자가 붙여넣는다.** 검수가 끝난 장부를 기존 장부 복사 기능으로 Google 지출표에 붙여넣는다. 검수용 CSV는 Google 지출표 자체의 양식이 아니다.

## 실패했을 때

- 교정 경로가 보호 사유로 거부하면 우회하지 않는다. 수동 교정·환불 짝·초과 환불·원본 충돌·닫힌 분기 보호는 그대로 두고, 필요한 경우 유지보수 도구 반영을 배포 담당 세션에 넘기거나 사용자 결정 필요 질문으로 올린다.
- 검수자 모델을 쓸 수 없으면 그때의 최상위 Claude 모델로 대체하고 보고에 모델을 적는다. 고객 원문을 무료 모델에 넘기지 않는다.

## 하지 않는 것

- 수동 교정(실제 사용자 결정)을 덮지 않는다.
- 카드 원문·금액·부호·ID, 메일 원문, 영수증 원본을 바꾸지 않는다.
- Google 최종 장부에 쓰지 않는다.
- Git·PR·보고에 원문·금액·이름을 넣지 않는다.
- 자료를 만들었다는 사실만으로 검수·Google 붙여넣기·교정 환류가 끝났다고 보지 않는다.

## 범위와 한계

범위는 여행 시작일의 분기와 저장된 분기 기타비용 귀속이다. 2026년 6월 30일 출발 여행은 3분기다. 선결제도 그 여행에 포함하며, 환불은 원금액을 보존한 음수 행으로 함께 합산한다. 다른 분기 여행, 원본 충돌·중복·금액 오류는 합계에서 제외한다. 예약 근거까지 읽는 화면과 같은 이용일 기준을 오프라인에서 재현할 수 없어 이 사유는 점수·건수에서 제외한다. 이용일 경고는 장부 화면 기준이다. 카드 합계는 수동 교정을 우선한 저장 판정 기준이며 화면의 취소·환불 묶음 표시와 다를 수 있다. 수입 미확인 여행의 수입·차액과 전체 합계의 수입·차액은 빈칸이다. 사유별 건수는 한 행에 여러 사유가 있을 수 있다. 수동 판정 의심 사례와 닫힌 분기 귀속 의심 사례는 [규칙집 §6.3](../DECISION_POLICY.md#63-분기-검수-때-볼-것)의 기존 기록을 검수자가 별도로 확인한다.

- 대체된 옛 절차(2026-11-13 이전): 사용자가 `review-pack.xlsx`의 "먼저 볼 50건" 시트부터 열어 사유를 보고 장부 화면에서 직접 교정한 뒤 고친 건수와 걸린 시간을 기록했다.

## Google 붙여넣기 묶음 만들기

검수·교정이 끝난 분기 장부를 Google 매출자료 양식_rev의 지출 7열로 파일화한다. 이 명령은 SQLite를 `mode=ro`로 읽고 Google이나 운영 DB에 쓰지 않는다. 출력 폴더는 저장소 바깥의 비공개 경로여야 한다.

```powershell
python tools/quarter_review/paste_pack.py --host-root D:/WebLedgerHost --year 2026 --quarter 3 --out D:/WebLedgerHost/data/backups/quarter-review-2026Q3/paste-pack-<시각>/
```

여행마다 `trip-NNN.tsv`, 분기 기타비용 `quarter-<연도>Q<분기>-other.tsv`, `summary.json`을 만든다. `summary.json`의 여행별 지출 합계는 저장 장부 합계와 각각 일치해야 한다. 불일치는 프로세스 종료 코드 1이며, 생성된 요약에 불일치 수가 남는다. 보류 사유별 건수와 보류 0 달성 여부도 기록한다. 거래 ID와 보류 행의 상세는 출력 요약이나 콘솔에 싣지 않는다.

숙박비·항공료의 미확인 이용기간은 DATE-109에 따라 공란으로 두고 다음 분기 검수에서 근거가 들어오면 채운다. 예약번호 공란은 DATE-032에 따라 추정값을 만들지 않는 경우 허용하며 저장된 값은 그대로 출력한다. 기존 `app/google_tsv.py`도 기간·예약번호를 필수 열로 보지 않는다. 공식 열 순서와 의미는 [공식 양식_rev B:H 조항](../history/specs-20261110/google-ledger.md#src-docs-google-workbook-layout-md--공식-기준-매출자료-양식_rev의-bh-연속-7열-구조)을 따른다. 항목·증빙유형·금액이 없거나 유효하지 않으면 보류한다.
