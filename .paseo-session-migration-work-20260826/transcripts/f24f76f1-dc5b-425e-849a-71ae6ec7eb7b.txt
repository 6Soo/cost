[User] Agoda 예약 DOM 수집 워커다. 반드시 현재 workspace의 Paseo IAB browser_* 도구만 사용한다. Edge/Chrome/CDP/UIA/shell 브라우저/Agoda API 또는 네트워크 직접 호출은 금지한다. 이 workspace의 브라우저 탭 하나만 사용하고 다른 agent와 탭을 공유하지 않는다.
고객센터 관련: 목록과 상세에 있는 "아고다 고객센터에 연락하기"·도움말·지원·문의 컨트롤은 기본 렌더링이므로 절대 클릭·hover·fill하지 않는다. 실제 패널은 제목/대화 영역과 정확한 문구 "요청 사항을 선택하거나 직접 입력해 주세요"가 함께 보이는 경우뿐이며, 보이면 즉시 CUSTOMER_CENTER_PANEL_VISIBLE로 fail-closed한다.
browser_click은 사용하지 않는다. generic snapshot ref/전체 DOM 버튼 index/위치 range를 선택에 쓰지 않는다. 예약 상세 진입은 예약 ID가 먼저 확인된 동일 카드의 data-element-name="blp-booking-item-button-edit"이고 aria-label에 같은 ID가 포함된 요소만 browser_evaluate로 클릭한다. ID·요소 검증 실패 시 클릭하지 않는다.
탭/페이지 이동은 browser_navigate 또는 정확한 role/name의 비지원 navigation control을 browser_evaluate로만 수행한다. new_tab timeout이면 browser_list_tabs를 한 번만 하고 zero/불명확이면 PASEO_BROWSER_UNAVAILABLE 또는 NAVIGATION_STATE_UNKNOWN으로 종료하며 재시도하지 않는다.
파일·DB·JSON/output에는 쓰지 말고 최종 응답은 JSON 하나만 반환한다. JSON 필드: lane, tab, pages, shard, status, list_count, scanned_count, captured_count, duplicate_count, failure_codes, timings, records. records에는 booking_id, kind(hotel/flight/other), detail_route, hotel_or_route, check_in, check_out, reservation_status, payment_state_text, total_amount_text, currency, card_last4, evidence_method="DOM", customer_center_panel_seen=false를 넣는다.
예약 ID의 안정적 SHA-256 문자열 해시를 3으로 나눈 나머지가 shard와 일치하는 예약만 상세 캡처한다. 다른 shard는 목록만 스캔한다. 중복은 booking_id 기준이다. 타임아웃은 무한 재시도하지 않는다.

전용 범위: tab=완료된 예약, pages=7, shard=1/3, lane=C07. 범위 밖 페이지/예약은 처리하지 않는다. 페이지 상태가 기대와 다르면 PAGE_STATE_MISMATCH로 중단한다. 실제 상세에서 예약 ID가 기대값과 다르면 DETAIL_BOOKING_ID_MISMATCH로 중단한다. 상세 필드를 DOM/ARIA에서 읽고 고객센터 패널 여부를 재검사한 뒤 JSON만 반환한다. 추가 agent/terminal/browser 생성 금지.
Paseo IAB 브라우저 제어 스킬을 적용해 전용 탭 하나에서만 목록 상태·페이지 범위·예약 카드·상세 DOM을 검증하겠습니다. 파일, 터미널, 추가 agent/browser는 사용하지 않습니다.
