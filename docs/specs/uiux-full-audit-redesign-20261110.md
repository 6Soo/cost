## 0. 구현 모델이 먼저 읽을 규칙

1. **PR 순서대로 구현한다** (§9). 각 PR은 독립 배포 가능해야 하며 앞 PR의 수락 기준이 녹색일 때 다음 PR을 시작한다.
2. **바꾸지 않는 것** (§11 보호 경계): POST/API 경로·요청 형식·CSRF·owner/viewer 판정·금융 계산·Google 쓰기 금지·업로드 파이프라인·live sync 영역 id(`live-rows`, `live-nav`)·행 편집 패널 내부 폼(`_panel_html`)의 필드와 제출 동작.
3. **화면 이동은 하되 기능은 지우지 않는다.** "삭제"로 표시된 것은 *중복 진입점·중복 문구·폐지 상태 UI*다. 기능 자체를 없애는 항목은 §5.3 표에 명시된 것뿐이다.
4. **기존 GET 주소는 모두 계속 열린다.** 주소를 바꾸면 303 리다이렉트를 남긴다 (§5.4 표).
5. 새 색·크기·간격 값을 직접 쓰지 않는다. §7 토큰만 쓴다. 토큰이 없으면 `tokens.css`에 역할 이름으로 추가한다.
6. 문구는 §8 용어 사전만 쓴다. 금지어 목록(§8.2)은 렌더링 결과에 나타나면 불합격이다.
7. 의도한 문구·구조 변경으로 깨진 테스트는 **기대값을 이 명세의 새 값으로 갱신**한다. 단 금융·권한·CSRF·원본 보호 테스트의 기대값은 바꾸지 않는다. 그런 테스트가 깨지면 구현이 틀린 것이다.
8. 각 PR은 AGENTS.md의 흐름(`DISCOVER → IMPLEMENT → TARGETED TEST → REVIEW → COMMIT`, `python tools/run_quality_checks.py --base origin/main --run`)을 따른다.
9. 판단이 필요한 곳은 §12의 기본값으로 진행하고 PR 본문에 "기본값 D-n 적용"이라고 적는다. 사용자에게 다시 묻지 않는다.

## 2. 제품 핵심 이해 (재설계의 기준)

COST는 여행사 운영자 1인(owner)과 열람자(viewer)가 쓰는 **여행 단위 정산 장부**다. 핵심 객체와 일은 다음과 같다.

| 객체 | 사용자가 하는 일 | 현재 위치 |
| --- | --- | --- |
| **여행** (Google 시트 탭에서만 생성) | 지출을 모으고, 수입·참가자·보험을 대조하고, 지출을 Google 장부에 붙여 넣고, 마감하고, XLSX로 낸다 | `/board?tab=` (장부), `/trips` (관리) |
| **분기 기타비용** | 여행에 속하지 않는 비용의 종결 귀속처 | 사이드바 `n분기 기타비용`, 이전 여행 서랍 |
| **카드 거래** | 파일 업로드 → 자동 귀속(P1/P2) → 조회·교정 | `/cards/all` |
| **OTA 예약** | 메일 수집 → 카드 결제와 M:N 연결 → 여행 연결 | `/ota` |
| **환불** | 원결제·취소 쌍 확인 | `/board?tab=refunds` |
| **영수증** | 사진/PDF 등록 → 분석 또는 직접 입력 → 장부용 복사 | `/receipts` |
| **항공권 예약** | 예약번호·여행 ID로 탑승객 연결 확인 | `/flight-passengers`, 여행 장부 하단 |
| **계정·권한** | 직원 계정·열람 범위 | `/access/admin` |

사용자의 주 작업 흐름은 하나다: **"자료를 올린다 → 여행별로 맞는지 본다 → Google에 붙여 넣는다 → 마감한다."** 현재 화면은 이 흐름이 아니라 데이터 원천(카드/OTA/영수증) 기준으로 흩어져 있고, 여행 장부 안에서도 단계가 6개의 동등한 버튼과 4개의 접힌 패널로 흩어져 있다. 재설계는 **여행 정산 흐름을 화면의 뼈대로** 삼고, 원천 자료 화면은 "거래" 하나로 묶는다.

이미 확정된 사용자 결정(변경 금지): P3 작업함·`내 확인 필요` 폐지, 카드 귀속은 실제 여행 또는 분기 기타비용, 미배정·확인필요·처리필요·미분류·보류 상태 UI 금지, Google 최종 장부 자동 쓰기 금지, 수동 테마는 해/달 아이콘 하나, 카드 업로드·수집 현황은 카드 화면 안, 여행 목록에 금액 배지 미표시(`ledger_design.py:259-261` 주석의 혼동 방지 결정).

## 3. 진단 요약

### 3.1 체계적 문제 5가지

1. **셸이 세 벌이다.** (a) 장부가 직접 그리는 내비(`ledger_design._nav_html`), (b) `site_shell.wrap_document`가 감싸는 독립 페이지, (c) 자체 `<style>`과 JS가 나중에 끼워 넣는 "여행별 비용으로 돌아가기" 막대(`site_shell.js:96-102`)를 가진 도구 페이지. 그 결과 제목 위치·미리보기 배너 위치·본문 폭(영수증은 가운데 섬, OTA는 전체 폭)·뒤로가기 유무가 화면마다 다르고, 뒤로가기 막대가 로드 후 삽입되어 레이아웃이 밀린다.
2. **사이드바가 과적재다.** 주 메뉴 5개 + 여행 검색 + 여행 목록 + 3·4분기 기타비용 + `환불` 섹션 + `이전 여행` 분기 서랍 + `보관` 서랍 + 하단 `전체 여행 보기`(= `여행 관리`와 같은 곳). 현재 위치 표시도 세션 저장값으로 칠해져 다른 화면에서 엉뚱한 항목이 선택된다.
3. **여행 장부에 주 행동이 없다.** `마감 / 여행 관리 / 예약·참가자 / 보험가입내역 / 여행 검토 / 수기 지출 추가`가 같은 무게로 놓이고, 같은 기능이 버튼(`예약·참가자`)과 접힌 패널(`예약·참가자 여행 연결`)로 두 번 나온다. 이 화면의 최종 산출물인 `지출내용 복사`는 맨 아래에 있다.
4. **디자인 토큰이 두 벌이고 Python 문자열에 색이 박혀 있다.** `--shell-*`(`site_shell.css:4`)와 `--bg/--grn`(`ledger_design.css:66-88`)이 공존하고, 다크 값이 서로 다르다(선택 배경 `#1C7A52` vs `#1E3A5F`). Python 페이지 STYLE에 hex 리터럴 약 250개(항공권 43, OTA 결제 39, 장부 38, 영수증 33, OTA 목록 28, 여행 항공 26). 글자 크기 23종, 모서리 15종, 미디어 쿼리 조건 20종 이상.
5. **폐지된 상태어가 화면에 남아 있다.** 사용자 결정으로 없앤 `보류`, `분류대기`, `미배정`이 여행 검토 패널·출력 화면·OTA 필터에 보인다.

- 날짜 표기: 같은 해이면 `MM-DD`, 다른 해가 섞이면 `YY-MM-DD`. `title`에 전체 날짜.
- 금액 열 오른쪽 정렬, `tabular-nums`. 음수는 `−` 기호(U+2212)와 글자 `취소`/`환불` 칩 병기.
- 행 상세: 지금의 인라인 확장(행 아래 끼워 넣기)을 오른쪽 서랍 `<dialog class="drawer">`로 바꾼다. 안의 내용은 `panel_part`가 주는 HTML 그대로. `showModal()`, 닫기 버튼 `aria-label="거래 상세 닫기"`, `Esc`, 닫으면 해당 행으로 포커스 복귀, URL `row=` 파라미터 동기화는 현재 동작 유지.
- 모바일 행(§7.7 `list-row`): 1줄 `거래처`(왼쪽, 말줄임) + `금액`(오른쪽); 2줄 `날짜 · 항목 · 이용일`(13px, 보조색). 가운데 정렬 금지. 행 전체가 버튼(`min-height:56px`).

- 빈 상태: 무엇이 비었는지 + 다음 행동. 카드 0건: "이 기간의 카드 거래가 없습니다." + `카드 업로드` / `기간 초기화`. OTA 0건: "조회된 OTA 예약이 없습니다." + `검색 초기화`(검색어가 있을 때) — 원인 추정 문구("수집 자료 연결 상태를 확인해 주세요")는 근거가 있을 때만. 환불 0건: "환불·취소 거래가 없습니다."

카드 탭:
- `수집 현황`은 펼침 버튼(`aria-expanded`, 아래 화살표 `⌄`가 열리면 180° 회전). 현재 오른쪽 화살표 `›` 사용 금지.
- 업로드 패널 닫기 버튼 문구 `닫기`, 밑줄 없음. 파일 선택은 §7.7 `file-drop`(네이티브 `<input type=file>`을 라벨 버튼으로 감싸고 드래그·드롭 영역 제공, 선택 파일 목록 표시). "선택된 파일 없음" 중복 문구 1개로.
- 업로드 결과: 파일별 한 줄 `synthetic-cards.csv · 처리 완료`(현재 `분류 검사 통과`). API 응답에 건수 필드가 있으면 `거래 12건 저장 · 중복 0건`을 덧붙이고, 없으면 붙이지 않는다(새 집계 금지). `이 화면에서 처리 결과 보기` → `처리 결과 보기`.
- 표 헤더 `배정` → `귀속`. 귀속 보조 표기 `코드 추론` → 칩 `자동`(`title="규칙 기반 자동 귀속"`), 수동 교정은 `수동`. 상세에서 근거 전문을 보여 준다.
- 행 전체가 상세 열기 버튼이 되도록 가맹점 셀의 버튼(현재 높이 18px)을 셀 전체로 확장(`::after{inset:0}` 패턴). 상세에 `이 여행 장부에서 보기` 링크(`/board?tab={귀속 tab}&row=card-{id}`), 귀속이 분기 기타비용이면 그 탭으로.
- 상세는 정의 목록 2열(데스크톱), 1열(모바일).

OTA 예약 탭:
- 자체 셸·뒤로가기 막대 제거, 공통 머리·필터 막대 사용.

환불 탭: 현재 내용 유지, 셸·필터 막대·KPI 표기(원결제/환불/순액)를 §7.7 `kpi`로. `카드 환불 0쌍` → `환불 쌍 0개`.

### 7.3 간격·모서리·그림자·모션·브레이크포인트

- 간격 `--s-1:4px --s-2:8px --s-3:12px --s-4:16px --s-5:24px --s-6:32px --s-7:48px`. 묶음 안 간격 ×2 이상을 묶음 사이 간격으로.
- 모서리 3개만: `--r-sm:6px`(칩·작은 버튼), `--r-md:8px`(버튼·입력), `--r-lg:12px`(카드·패널·서랍), 알약 `999px`. 패딩이 있는 중첩 면은 바깥 = 안 + 패딩(24px 초과면 각자 토큰).
- 그림자: `--sh-1: 0 1px 2px rgb(15 23 42 / .06)`(카드), `--sh-pop: 0 8px 24px rgb(15 23 42 / .14), 0 2px 6px rgb(15 23 42 / .08)`(메뉴·서랍), 다크는 불투명도 2배. 그림자 아래 `border:1px solid transparent`(강제 색 모드).
- 모션: 상태 전환 `150ms ease-out`, `opacity`/`background-color`/`transform`만 이름 지정(`transition: all` 금지). 펼침 화살표 회전 150ms. 서랍 입장 `transform: translateX(16px)→0` + opacity 200ms, 퇴장 150ms. 모두 `@media (prefers-reduced-motion: no-preference)` 안. 누름 `scale(.96)` 150ms(비활성 제외).
- 브레이크포인트 **2개만**: `--bp-desktop: 1024px`(사이드바 ↔ 상단 바+하단 탭), `--bp-wide: 1440px`(본문 패딩 확대). 컴포넌트 내부 적응은 `@container`. 현재의 760/600/560/480/390/375/680/899/1099/1100 조건은 이 둘로 합친다.
- `100vh` → `100dvh`(`ledger_board.py:1231, 2107`). 고정 `height`가 글을 담으면 `min-height`.
- 터치 대상: 모바일 최소 44×44, 데스크톱 최소 32×32(밀집 표의 행 안 버튼), 그 외 40.

### 7.4 아이콘

`ui_icons.icon()` 한 라이브러리. 크기 16(표·칩)/18(메뉴·버튼)/20(상단 바). `currentColor`. 장식 아이콘 `aria-hidden="true"`. 의미: 펼침 = 아래 화살표(`chevron-down`, 열리면 회전), 이동 = 오른쪽 화살표(`chevron-right`, 링크에만), 뒤로 = `chevron-left`. 한 컨트롤에 화살표 두 개 금지. `여행 관리`·`OTA 내역`이 같은 `list` 아이콘을 쓰는 문제: 여행=`plane` 또는 `map`, 거래=`credit-card`, 영수증=`receipt`, 홈=`home`, 관리=`settings`(없으면 `users`). 없는 아이콘은 `ui_icons.ICONS`에 Lucide 경로로 추가.

### 7.5 포커스·키보드

- 포커스 링: `:focus-visible{outline:2px solid var(--c-focus); outline-offset:2px}` 전역 1곳. `outline:none`은 대체 링이 있는 곳에서만(`ledger_design.css:104, 442`, `card_flow.py:3293`, `flight_passenger_page.py:63` 재점검 — 대체 없으면 삭제).
- 현재 사이드바 검색 입력 포커스는 `outline:none + box-shadow`(측정) → 전역 규칙으로 통일.
- `본문으로 건너뛰기` 링크: 셸의 첫 포커스 요소, `href="#main"`.
- 모바일 메뉴/서랍이 닫혀 있을 때 그 안 링크가 탭 순서에 들어가지 않게 `inert` 또는 `hidden`(미검증 항목 확인 겸).

## 부록 B. 감사 중 관찰한 비UI 사항 (이 명세 범위 밖, 기록만)

- 합성 자료에서 2026-09-12·2026-11-02·2026-11-04 카드 거래가 2027-08 여행(유일한 여행)에 `코드 추론`으로 귀속됐다. "실제 여행 후보가 있으면 최선 후보에 배정" 규칙의 결과일 수 있으나, 1년 가까이 떨어진 날짜의 귀속이 의도인지 금융 명세 소유자가 확인할 가치가 있다. 운영 자료로는 확인하지 않았다.
- `/review`는 미리보기에서 `/cards/all`로 이동했다(실제 자료 검토 미설정). 운영 동작은 미검증.
