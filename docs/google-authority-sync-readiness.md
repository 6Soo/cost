# Google 정본 동기화 준비 체크리스트 (비활성)

> **구현 전 검토 문서**입니다. 2026-10-11 기록을 바탕으로 하며 현재 Google 정본 연동이나 예약 작업이 실제 활성화되었다는 뜻이 아닙니다. 최신 목표 및 작업 순서는 [COST V3 START HERE](COST_V3_START_HERE.md) 및 [Google 업무 명세](target-workflow-google-authority.md)에서 확인합니다.


> 상태: **준비 문서. 스케줄러는 등록하지 않았고 운영 설정도 바꾸지 않았다.**
> 대상 구현: `app/google_authority.py`, `tools/google_authority_sync.py` (PR #71, #73).
> 기준 시각은 Asia/Seoul이다.

## 1. 현재 동작 (저장소 기준)

- `tools/google_authority_sync.py --snapshot <공개 스냅샷 경로> --rows <비공개 행 경로>`로 1회 실행한다. 경로는 항상 명시한다. 기본 경로는 없다.
- 두 워크북을 xlsx로 읽기만 한다. Google에는 쓰지 않는다.
- 공개 스냅샷에는 합계·검증 상태·행 변경 건수만 있다. 행 값(이름·예약번호 등)은 비공개 행 파일에만 있다.
- 실패 시 이전 정상 값을 유지하고 `stale`로 표시한다. 빈 결과로 덮어쓰지 않는다.

## 3. 기존 작업과의 충돌 확인 (필수)

- `tools/refresh_review_source.py --watch`는 기본 30초 간격으로 **같은 메인 워크북**을 내려받는다. 검토용 흐름이며 정본 읽기와 목적이 다르다.
- 운영에서 이 `--watch`가 상시 실행 중인지 저장소 문서로 확인되지 않았다. 등록 전 운영 PC에서 프로세스와 작업 스케줄러 목록을 확인한다.
- 두 흐름이 같은 원본을 동시에 읽는 것 자체는 쓰기가 아니지만, 요청 수를 줄이기 위해 하나로 합치거나 간격을 분리하는 결정이 필요하다.

## 4. 저장 위치와 권한

- 공개 스냅샷과 비공개 행 파일은 **저장소 밖**에 둔다. 예: `D:\WebLedgerHost\data\google-authority\`. 저장소 안이나 임시 공개 폴더에 두지 않는다.
- 비공개 행 파일은 고객 개인정보와 재무 행을 포함한다. 접근 권한을 운영자 계정으로 제한하고, 백업에 포함할지 별도로 정한다.
- 공개 스냅샷에는 개인정보가 없다는 것을 테스트(`test_public_snapshot_has_no_row_contents_but_private_file_does`)로 확인한다.

## 5. 승인 전 확인 항목

1. 운영 PC의 작업 스케줄러에 기존 `--watch` 또는 다른 Google 접근 작업이 있는지
2. 실행 계정이 두 워크북에 읽기 권한을 가지는지 (`SOURCE_ACCESS_DENIED` 재현 여부)
3. 로컬 PC가 꺼져 있을 때의 공백 시간 표시 방식 (명세 Q7의 미결)
4. 백업 대상에 비공개 행 파일을 넣을지
5. 실패 알림 채널 (현재는 표준 출력 상태 코드만 있다)

## 6. 활성화 절차 (승인 후에만)

1. 구현된 CLI의 `sync.lock`과 `sync-state.json` 경로 및 실행 계정의 파일 권한을 확인한다. 합성 잠금·장애 테스트는 구현되어 있다.
2. 격리된 임시 경로에 스케줄러를 **비활성 상태로** 등록하고 수동 1회 실행으로 확인한다.
3. 사용자 승인을 받은 뒤 활성화한다. 활성화 전 공개 스냅샷과 비공개 행 파일을 백업한다.
4. 활성화 후 첫 정각 실행 결과를 `synced_at`과 오류 코드로 확인한다.

## 7. Render 전환 메모 (검토만, 미실행)

- 현재 코드는 Windows 경로와 `openpyxl`만 쓴다. Linux 이식성은 실행 전에 확인이 필요하다.
- 비공개 행 파일을 Render 디스크에 두면 개인정보가 국외 서버에 저장된다. 호스팅 지역·보관 기간·백업을 먼저 정한다 (명세 Q8).
- Google 읽기 권한은 서비스 계정 또는 OAuth 중 하나로 정해야 한다. 현재 익명 xlsx 내보내기에 의존하며, 공개 범위 확인이 필요하다.

## 8. 이번 단계에서 하지 않은 것

- 운영 SQLite·OTA DB 쓰기

## 9. 2026-10-11 Google 원본 공유 설정 실측 및 인증형 읽기 준비

- 연결된 Google Drive 권한 메타데이터에서 **메인·보관 모두 anyone/reader**가 확인됐다. `allowFileDiscovery=false`이므로 검색 공개를 뜻하지는 않지만, 링크를 아는 사람이 읽을 수 있는 공유 방식이다. 원본에 회계·개인정보가 포함될 수 있어 운영 보안 승인이 필요하다. **공유 설정은 변경하지 않았다.**
- 기존 기본 `tools/google_authority_sync.py` 실행은 인증 없는 Google XLSX export를 사용한다. 두 문서의 공유를 제한하면 기존 방식은 실패할 수 있다. 공유 권한을 바꾸기 전에 대체 인증이 실제로 동작하는지 검증해야 한다.
- 개발 브랜치에는 `--google-auth adc` 선택형 읽기가 추가됐다. `google-auth`의 Application Default Credentials와 Google Drive **읽기 전용** scope를 사용하며, 허용된 두 원본에만 Drive export를 요청한다. 비허용 URL과 외부 리다이렉트는 차단하고 인증 실패 시 공개 링크로 폴백하지 않는다. 기본값 `public`은 호환을 위한 현재 동작이며 운영 안전 승인으로 해석하지 않는다.
- 코드에는 비밀키·토큰이 없다. 운영 계정의 ADC/서비스 계정 접근권한 부여, 실제 인증 XLSX 응답, token 만료/재발급, 비공개 전환 이후 재시도는 **미검증 HOLD**다. 실제 자료·인증정보를 GitHub나 외부 AI로 전송하지 않는다.
- 후속 Windows 실제 저장소에서 인증 내보내기·정본 동기화·스케줄 상태의 표적 검사를 실행했다. ADC 초기화 실패도 기존 정상 행을 보존하면서 즉시 stale로 전환한다. 복구 불가 토큰 갱신 실패는 `GOOGLE_AUTH_REFRESH_REQUIRED`, 일시적인 갱신 장애는 `SOURCE_UNREACHABLE`로 구분한다. 응답 정리 오류는 인증 오류를 덮거나 원문 오류를 노출하지 않는다. Google 실계정 검증은 여전히 HOLD다.
- API 계약은 [Google Drive files.export 문서](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/export)와 대조했다. 이 API는 내보내기 크기를 10 MB로 제한하며 읽기 전용 Drive scope를 허용한다. 원본이 API 한도를 넘는 경우에도 공개 링크로 우회하지 않는다.
- [Google Drive 오류 문서](https://developers.google.com/workspace/drive/api/guides/handle-errors)에 따라 403의 `rateLimitExceeded`·`userRateLimitExceeded`는 권한 거절과 구분해 일시 장애로 표시하고 기존 지연 재시도를 따른다. 오류 본문은 최대 16 KB까지만 판독하며, 알려지지 않은 사유나 권한 거절이 섞이면 접근 거절을 유지한다. 본문과 토큰은 출력하지 않는다.
- 전환 순서: 승인된 비운영 인증 자격 준비 → 두 원본에 명시적 읽기 권한 부여 → 격리에서 `--google-auth adc` 정상 읽기 확인 → 운영 동기화 설정·복구 계획 승인 → Google 공유를 제한 → 인증된 읽기 및 stale 표시 검증. 각각 별도 권한 승인이 필요하다.
