# 로드맵 — 후속 개별 프로젝트

1~4단계 자동화가 안정화된 뒤 진행. 세 과제 모두 오픈 API가 없고,
실질 해법이 **이메일 파싱**으로 수렴하므로 **이메일 인제스천 계층 하나**로 통합 설계한다.

## 공통 계층: 이메일 = 사실상의 API

| 소스 | 계정/프로토콜 | 추출 대상 |
|---|---|---|
| 카드사 이용명세 | (카드사별) 이메일 발송분 | 사용내역(가능한 카드사 한정) |
| 트립닷컴/아고다/부킹 예약확정 | 예약 시 수신 메일 | **실사용일(체크인/탑승)**, 호텔/항공사명, 금액 |
| 네이버페이/카카오페이 결제알림 | **hanmail(Daum) IMAP** | 결제일, 금액, 항목 |

Gmail은 Gmail API, hanmail은 IMAP으로 접근. Apps Script(GmailApp) 또는 별도 파서.

## P1. 카드 수집 자동화 (우선순위 낮음)
- 법인카드는 마이데이터 대상 아님, 오픈 API 없음 → 수동 다운로드 유지가 현실적.
- 일부 카드사만 이용명세를 이메일로 발송 → 해당분만 파싱 검토.
- **결론: 당장은 하지 않음.** 붙여넣기 형식 표준화로 충분.

## P2. 트립닷컴/아고다/부킹 실사용일 매핑 (임팩트 큼)
- "결제 2월 → 실사용 6·7·10월" 문제를 사이트 스크래핑이 아니라
  **예약확정 메일 파싱**으로 해결: 메일에 체크인/탑승일·시설명·금액이 모두 존재.
- 파싱 결과로 RAW의 트립닷컴/아고다/부킹 보류 건을 **실사용일**에 맞춰 장부 전기.

## P3. 페이 결제내역 (카드 3820) 매핑
- hanmail IMAP → 네이버페이/카카오페이 결제알림 메일 필터 → 금액·일자·항목 추출.
- 3820 카드의 "페이 큰 금액(항공권 결제료)" 보류 건과 매칭해 계정과목 확정.
