# OTA 카드 매칭 P2 실패 원인 상세 보고 — 정책 예시와 검수 기준

> 2026-11-18 소유자 결정: **A안**. 실제 카드 청구가 금융상 정상인 경우 OTA 예약 연결이 실패해도 내부 비용 기록을 허용한다. 다만 P2 조사 후 연결 실패의 **이유를 아주 상세하게** 기록한다. 정책 정본은 [판정 규칙집 §3.0·§3.9](../../DECISION_POLICY.md)과 [LINK-044](../../policy/link.md), [REC-020](../../policy/record.md), [PROC-010](../../policy/process.md)이다.
>
> 아래 예시는 **모두 합성 사례**다. 고객 거래 원문이나 실제 AI 실행 기록이 아니다. 수집되지 않은 자료를 수집한 것으로 꾸미지 않는다.

## 1. 실무 보고의 필수 구분

| 구분 | 의미 | 적으면 안 되는 것 |
| --- | --- | --- |
| **P2 조사 완료·미매칭** | 지정 근거를 실제로 읽고 대조했으나 연결할 충분한 근거가 없거나 명시 충돌이 있다 | 매칭 완료, 예약번호 확정, 환급 완료 |
| **P2 실행/조회 실패·조사 미완료** | 모델 호출·인증·시간초과·자료 읽기·stale 등으로 검토 범위를 완료하지 못했다 | 'AI가 거래를 검토했지만 해당 결제가 없다', 'AI 조사 완료' |
| **카드 정상 비용 기록** | 별도 P1 금융 안전 조건을 충족한 실제 카드 원행을 내부 장부에 기록했다 | OTA 예약 연결 완료, Google 쓰기 완료 |
| **금융 보호 차단** | 원본 오류·중복·미해결 취소/환불·수동 점유·잠금 등으로 쓰기를 보호한다 | OTA 미매칭만을 금융 오류로 변경 |

**상세 보고 작성 단위:** OTA 결제 사건별. 후보가 여러 개면 후보별 결과를 별도로 기재한다. 같은 카드 원행이 M:N 관계 여러 개에 쓰여도 금액은 원행 한 번만 집계한다.

## 2. 예시 A — P2가 조사했으나 검증된 OTA 결제 카드 연결을 찾지 못함

**합성 입력:** 2026-11-10에 OTA 예약 청구 200,000원(KRW)이 완료됐다는 검증된 메일이 있다. 카드 검색 범위에서 같은 날 200,000원 카드 원행은 발견됐으나 가맹점은 **예약 공급자와 무관한 독립 전자제품 판매점이며 PG가 아님이 검증**됐다. OTA 공급자 표기의 199,000원 카드 원행도 별개로 발견됐다. 이 가상 결과에서 어느 카드와도 OTA 결제의 정확 연결 조건이 충족되지 않는다.

### 2.1 검토 사실과 실행 상태

- **대상 사건:** OTA 실제 청구 관측 1개. 예약번호 전체 대신 비공개 사건 참조 및 원본 digest를 기록한다.
- **상품/지급 사실:** 청구 완료 메일은 확인됨. 이용기간은 이 예시의 결제 매칭 판단과 별도로 관리.
- **대조한 자료:** 인증 결제 메일·포털 청구 명세·해당 조회 범위의 카드 원행·기존 수동 점유를 각각 읽었는지, 사용한 자료 기준일·조회 시작/끝·원천 digest·검색 실패 내역을 적는다. 실제 확인하지 않은 것은 '미조회'로 구분한다.
- **P2 실행 증거:** 실운영에서는 provider/model/run_id, 요청 digest, 원본 revision, 근거 조회 상태, 결과 검증을 별도 비공개 감사에 기록해야 한다. 이 예시에는 실제 실행 증거가 없으므로 테스트/템플릿으로만 사용한다.
- **적용 규칙:** LINK-002(가맹점·통화·금액), DATE-023(동일일 조건), LINK-018(PG 특례), LINK-003(M:N), LINK-044(미매칭 상세 보고), REC-020(카드 기록 분리).

### 2.2 후보별 근거 비교 — 합성

| 카드 후보 | 날짜 | 통화/금액 | 카드 가맹점·공급자 대조 | 결과와 정확한 원인 |
| --- | --- | --- | --- | --- |
| 카드 원행 A | 2026-11-10 | KRW 200,000 | 독립 전자제품 판매점, 비PG로 **확인** | **MISMATCH**. 날짜·정확 금액은 맞지만 명시된 무관 사업자 충돌. LINK-002·LINK-018에 따라 자동 연결 불가 |
| 카드 원행 B | 2026-11-10 | KRW 199,000 | OTA 공급자 표기 일치 | **MISMATCH**. 원문 금액이 1,000원 다름. 승인된 차액 예외 증거가 없으므로 같은 금액으로 취급 불가 |
| 추가 카드 후보 | 확인된 검색 범위에서 없음 | 미확인 | 검색 범위 밖 카드/미수집 파일 존재 여부는 미확인 | **UNKNOWN**. 검색 결과 0건은 세상에 카드 결제가 없다는 증거가 아님 |

이 예시에서는 후보 2개가 **각각 다른 이유**로 배제된다. '후보가 2개이므로 M:N 실패'라고 표현하지 않는다. M:N 조건을 만족하는 edge가 있다면 모두 보존해야 하며, 이 예시의 두 후보는 그 조건을 충족하지 못한다.

### 2.3 구체적인 실패 설명의 예시 문장

> 해당 OTA 결제는 원문 청구액 200,000원(KRW), 청구일 2026-11-10이다. 검토한 카드 조회 범위에서 후보 A는 200,000원·동일일이었으나 카드 가맹점이 다른 독립 소매업체이며 PG가 아님이 확인돼 공급자 충돌로 배제했다. 후보 B는 동일 공급자·동일일이지만 실제 카드 원문 199,000원으로 1,000원 차이가 났다. 이 차이를 입증할 수 있는 승인된 할인/차액 근거는 제공되지 않았다. 따라서 현재까지 대조한 두 후보 중 검증된 OTA↔카드 edge는 0개다. 수집 범위 밖 거래의 존재 여부까지 부정하지는 않으며, 다른 카드 파일·결제 식별자·청구 정정 메일이 추가되면 같은 금융/원본 보호를 적용해 다시 비교할 수 있다.

**결론 및 처리:** `OTA_CARD_RELATION=UNVERIFIED`(설명용 상태명, 신규 API/DB 필드 제안이 아님). 단순 미매칭으로 카드를 기록 차단하지 않는다. 원행 A·B 각각의 **실제 정상 비용 여부**는 독립적인 금융 안전 검사로 판단하여 필요하면 개별 카드 지출로 내부 기록한다. **원행 A나 B를 OTA 200,000원 예약의 매칭 카드·예약번호로 표시하지 않는다.** Google 최종 장부 자동 쓰기 없음.

## 3. 예시 B — 실제 P2 실행이 실패해 원인 판단까지 못한 경우

**합성 입력:** OTA 미매칭 사건을 P2가 분석하려 했으나 승인된 메일 원문 조회가 권한 오류로 실패했다. 모델은 관련 원문을 읽지 못했다.

- **실패 지점:** 메일/근거 조회 중 권한 오류. 어떤 원문을 읽지 못했는지 비공개 근거 참조와 범위를 기록
- **검토 상태:** `P2_REVIEW_INCOMPLETE`(설명용 상태명); **P2 조사를 완료했다는 증거 없음**
- **매칭 결론:** `OTA_CARD_RELATION=UNVERIFIED` 유지. '같은 예약의 실제 카드 결제가 없다'고 쓸 수 없음
- **후속:** 인증 정상화·원문 접근·실제 P2 실행 성공 후 재대조. 재시도 횟수·최종 오류·실행자/요청 digest를 비공개로 기록
- **카드 기록:** 별도의 정상 카드 원행은 OTA 매칭 조사 미완료만으로 자동 기록 차단하지 않지만 원본 충돌·중복·환불 등 금융 검사를 통과해야 함

## 4. 회귀 검수 체크리스트 (구현 시)

- [ ] P1에서 OTA 카드 관계 미매칭이면 **항목 분류가 완료된 사건도** P2 대조에 진입
- [ ] 검증된 1:1·M:N 관계는 그대로 유지하며 후보 수만으로 실패 처리하지 않음
- [ ] 후보 0/1/복수, 증거 미제공, 명시 공급자 비PG 충돌, 정확금액 불일치, 환불/중복/수동 점유를 각각 다른 원인으로 설명
- [ ] 사용한 데이터의 조회 성공·미조회·오류 및 조회 범위를 분리
- [ ] P2 조사 완료 미매칭과 P2 호출/조회 실패를 별도 상태로 기록하고 실운영 run 증거를 검증
- [ ] 정상 카드 지출 기록은 OTA 링크 실패만으로 막지 않되 기존 금융 보호는 유지
- [ ] 미매칭 사건으로 개별 예약번호·실제 환급·Google 반영을 자동 확정하지 않음
- [ ] 출력에는 개인정보 원문·전체 카드번호·예약번호 전체가 없고 보호된 상세 근거 참조만 있음

**검수 상태:** 이번 문서는 요구·사례·검수 계획이며 해당 코드나 금융 데이터를 변경하지 않았다. P2 실행기 및 현재 운영 결과를 검증하거나 동등성 테스트를 완료한 문서가 아니다.
