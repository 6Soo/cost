# 이메일(Gmail) 연동 설계 — `kkokkohero6@gmail.com`

이미 hanmail → Gmail(`kkokkohero6@gmail.com`) 수집이 구성돼 있고 결제 메일이 다수 쌓여 있다.
이를 되살려 **로드맵 P2(OTA 실사용일)·P3(페이 내역)** 를 지금 붙인다.

## 핵심: Gmail도 Apps Script로 (샌드박스 아님)

- 이 자동화 환경은 구글 접근이 차단됨 → **GmailApp/SpreadsheetApp(Apps Script)** 로만 접근.
- GmailApp은 **스크립트를 실행하는 계정의 메일함**을 읽는다.
  → 결제 메일이 있는 `kkokkohero6@gmail.com` 에서 실행해야 그 메일함을 읽을 수 있음.

### 계정 배치 (권장)
**`kkokkohero6@gmail.com` 한 계정에서 전체 자동화 실행.**
- GmailApp: 결제 메일 파싱 (같은 계정 메일함).
- SpreadsheetApp.openById: 5개 시트 접근.
  - 시트를 `kkokkohero6` 가 **소유**하면 → 추가 공유 0회(이상적).
  - 아니면 5개가 든 **드라이브 폴더 1개만** `kkokkohero6` 에 편집자로 공유(1회로 상속).
> "메일 계정 ≠ 시트 소유 계정" 이면 위 폴더 공유 1회가 유일한 손질.

## 되살리기 체크리스트
1. hanmail → Gmail 자동전달(또는 Gmail의 "다른 계정 메일 가져오기") **재활성화**.
2. Gmail 필터로 결제/예약 메일에 라벨 **`결제데이터`** 자동 부여.
3. Apps Script를 `kkokkohero6` 계정에 배치 + **시간 기반 트리거**(예: 6시간마다) 등록.

## 수집 파이프라인
```
Gmail(label:결제데이터 -label:처리완료)
  → 발신자별 파서로 구조화
  → '메일수집' 스테이징 시트에 append
  → 메시지에 '처리완료' 라벨 부여 (멱등/증분)
```

### 구조화 레코드 (스테이징 시트 열)
| 열 | 내용 |
|---|---|
| source | naverpay / kakaopay / agoda / booking / tripcom / card ... |
| paidDate | 결제일 |
| useDate | **실사용일**(OTA 체크인/탑승). 없으면 공란 |
| merchant | 시설/항공사/가맹점명 |
| item | 항목 요약(항공권/숙박 등) |
| amount | 금액(원) |
| messageId | Gmail 메시지 ID(중복 방지 키) |

## 장부와의 매칭 (보류 건 해소)
- **OTA 보류건**(RAW의 트립/아고다/부킹): 스테이징의 `amount`(+가맹점)로 매칭 →
  `useDate`(실사용일)를 찾아 **그 날짜로 장부 전기** → "결제≠사용" 문제 해결.
- **3320 페이 보류건**: 스테이징의 `amount`(+결제일 근접)로 매칭 →
  `item`으로 계정과목/여행 귀속 확정.

## 지금 필요한 것 (파서 작성용)
발신자별 본문 형식이 달라 정규식을 맞춰야 함. 각 유형 **예시 메일 1통씩**:
- 네이버페이 / 카카오페이 결제알림
- 트립닷컴 / 아고다 / 부킹닷컴 예약확정
- (있다면) 카드사 승인/이용 알림

각각 **발신자 주소 + 제목 + 본문 텍스트**만 있으면 파서를 바로 짠다.
