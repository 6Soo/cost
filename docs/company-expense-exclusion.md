# 회사 경비 제외

카드 검토 화면에서 거래를 고르고 `이 건은 회사 경비 아님`을 제안합니다. 제외할 거래를 확인한 뒤 `회사 경비 제외 확인`을 누르고 별도 확인에 동의해야 적용됩니다. 소유자만 변경할 수 있습니다.

원본 거래와 기존 분류 결정은 유지합니다. 제외된 거래는 장부 기록 준비 목록과 Google TSV에서 빠집니다. 화면의 제외 목록에서 되돌릴 수 있으며, 이후에 확정한 분류도 덮어쓰지 않습니다. 요청 번호와 상태 버전으로 재시도·중복 적용·오래된 되돌리기를 보호하고, 적용과 되돌리기를 변경 이력에 기록합니다.

이미 장부에 기록했거나 사용자 확정이 있는 거래의 신규 제외, 환불 묶음, 중복·충돌·보류 거래는 이 경로로 변경하지 않습니다. 이 범위의 정책은 별도로 확인해야 합니다. Google에 이미 붙여넣은 행을 자동으로 삭제하거나 수정하지 않습니다.

`transaction_company_exclusions` 표는 별도 명령 없이 `app.db.Store`를 만들 때 자동으로 생성됩니다. `Store.open()`과 `Pipeline(connection)`도 이 경로를 사용합니다. 웹에서는 선택된 장부 연결로 첫 `CardFlow`를 만드는 요청이 생성 시점이며, 카드 목록 조회와 규칙 검토도 이 경로를 사용할 수 있습니다. 서버 시작만으로 생성된다고 가정하거나, 쓰기 버튼을 누르기 전에는 DB 변경이 없다고 가정하면 안 됩니다.

스키마 생성은 저장점 안에서 실행합니다. 도중 실패하면 이번에 만든 표와 인덱스를 모두 되돌리고, 호출자가 진행 중이던 트랜잭션을 자동으로 커밋하지 않습니다. 기존 표와 자료는 보존하며 반복 실행은 같은 스키마를 유지합니다. 격리 SQLite에서 기존 자료 보존, 실패 롤백, 호출자 롤백, 첫 `CardFlow` 생성 시점을 검증합니다. 기존 DB 파일을 이전 버전으로 복원하는 운영 롤백은 별도 복구 사본이 필요합니다.

이번 실행에서는 임시 DB만 변경했으며 운영 DB에는 적용하지 않았습니다. 운영 적용 전에는 자동 스키마 생성까지 포함한 DB 변경 승인과 복구 사본 검증이 필요합니다. 승인 전에는 새 코드를 운영 DB에 연결하지 않습니다.

표적 검증 파일은 `tests/card_pipeline/test_company_expenses.py`와 `webapp/tests/test_company_exclusion_http.py`입니다. 원본 보존, 적용과 되돌리기, 재시도, 상태 충돌, 감사 기록 실패의 롤백 및 390px·1440px 화면을 다룹니다.
