# 여행 지출표 ↔ Google 지출 장부 금액 그룹 M:N 대조 UI (2026-10-30)

- 상태: **COMPLETE_DEPLOYED / PR386·387, 운영509392e1·실제 로그인 화면 수락 완료**. 현재 실행은 [열린 PR 구현 실행](open-pr-development-execution-20261030.md)과 현재 상태의 최신 기록을 따른다.
- 우선순위: P1, PC 전용 가시화
- 정본: Google 여행별 지출 영역. COST는 읽기 전용 대조·표시만 하며 Google 쓰기 금지.
- 관련 문서: `docs/specs/google-ledger.md`, `docs/specs/finance.md`, `docs/specs/lean-card-ota-core-20261030.md`.
- 제품 결정: **동일한 실제 여행 ID + 동일한 지출 금액이면 매칭 관계를 생성한다.** 날짜·가맹점명·축약/별칭·메모는 매칭 키에 사용하지 않는다. 동일 금액의 반복 거래는 각각 유효한 별도 거래로 보존하며 1:1 강제 배정하지 않는다.

## 1. 목적과 범위

사용자가 COST의 여행별 **지출내용**을 Google 스프레드시트의 같은 여행 **지출내용**과 비교할 때, PC 화면의 각 COST 지출행에 Google 장부 기록 여부를 직관적으로 표시한다. 수입내용과 지출내용은 혼합하지 않는다. 여행 정본 매핑이 검증된 실제 여행에만 비교하며 분기 기타비용이나 여행 미배정은 다른 여행으로 추정해 비교하지 않는다. 기존 Google 읽기·캐시·권한·여행 매핑을 재사용하고 새 수집/동기화 엔진을 만들지 않는다.

## 2. 판정: 키, 다중 관계, 건수

1. 각 COST 지출 원행과 Google 지출 원행을 **실제 trip_id + 금액**으로 그룹화한다. 금액은 정수 원화 기준으로 정확히 일치시킨다. 외화/원화 환산액이 혼재하면 검증된 동일 통화·회계금액이 없을 때 비교 불가로 둔다. 환불/취소는 부호를 유지해 정상 지출과 섞지 않는다.
2. 같은 키에 COST `m`건, Google `n`건이 있다면 **모든 `m × n` 쌍을 후보 관계**로 조회할 수 있어야 한다. 가맹점명·거래일·장부 기입일·메모 차이로 후보를 제거하거나 순위를 매기지 않는다.
3. **초록 체크(그룹 건수 일치):** `m > 0 && m === n`이고 두 원천 스냅샷이 정상·최신이며 여행 매핑이 유효한 경우. 그룹의 모든 COST 행에 표시. 이는 '여행+금액 그룹의 건수가 같다'는 의미이지 **개별 결제↔특정 Google 행의 신원이 증명되었다는 뜻이 아니다**.
4. **노란 부분 일치:** `m > 0 && n > 0 && m !== n`. 그룹의 모든 COST 행에 노란 표시 및 `COST m건 / Google n건 / 차이 |m-n|건`. 일부 거래만 임의로 초록 처리하거나 임의의 1:1 확정을 만들지 않는다.
5. **미기록:** `m > 0 && n === 0`. 해당 그룹의 COST 행은 체크 없음/미기록으로 표시.
6. **비교 불가:** Google 조회 실패, 권한/여행 매핑 오류, 파싱 실패, 구형 스냅샷, 통화·금액 불확정, 비교 대상 영역 불명확 등. 0건으로 취급하거나 초록 체크하지 않고 이유와 마지막 성공 조회 시각을 표시.
7. Google에만 있는 금액 그룹(`m=0,n>0`)도 그룹 요약의 'Google에만 있음' 건수로 제공. 웹 지출 원행을 허위 생성하지 않는다.
8. Google 지출행은 기존 정본 구조의 실제 지출 범위만 포함하고 수입·합계·소계·빈 행·수식 요약·중복 인덱스 행은 제외. COST에서도 같은 원천 거래를 카드/OTA/영수증 증빙으로 중복 표시한 경우 원래 지출 1건으로 집계한다. 실제 별도 반복 결제는 **절대 중복 제거하지 않는다**.

### 예시

| 동일 여행·금액 | COST m | Google n | 후보 관계 | COST 행 표시 |
|---|---:|---:|---:|---|
| 50,000원 | 3 | 3 | 9 | 초록 체크 · 3/3 |
| 50,000원 | 5 | 2 | 10 | 노란 부분 일치 · 5/2 |
| 50,000원 | 2 | 0 | 0 | 미기록 · 2/0 |
| 50,000원 | 0 | 2 | 0 | Google에만 있음 · 0/2 |

## 3. UI 계약

- **여행별 지출내용 표**에 `Google 장부` 상태 열을 추가한다. CSS 미디어 쿼리 `@media (min-width: 900px)`에서만 표시하며 899px 이하는 열·상태 상세 트리거 모두 숨긴다. User-Agent/OS 판정 금지. 화면 폭은 CSS viewport 기준.
- 초록 아이콘 + `장부 건수 일치`, 노란 아이콘 + `부분 일치`, 회색 `미기록`, 중립 `비교 불가` 상태. 색상만으로 의미 전달 금지; aria-label/title/텍스트 제공.
- 행 상태 클릭 시 같은 여행·금액 그룹의 COST m건과 Google n건을 **양쪽 원본 식별자를 보존해** 표시. `m×n` 전체 관계는 개념상 모두 성립하지만 DOM에 모든 쌍을 생성할 필요 없이 그룹 내 양측 목록으로 효율적으로 제시. 가맹점명·날짜는 비교 참고로만 표시.
- 최신 사용자 보완: [정렬·보험 후속](ledger-sort-insurance-followup-20261030.md)에 따라 상단 요약·하단 상시 목록/반복 안내를 제거하고 상태 클릭 때만 상세 창을 연다. 기본 PC 정렬은 건수 일치·부분 일치·미기록 순이며 각 단계 안에서는 첫 Google 행 번호순이다. 원천 오류는 상태 툴팁에 유지한다.
- 모바일 기존 지출 UI·복사 표·정렬·필터는 그대로 유지. Google 데이터 자동 수정 금지.
- 초록 체크는 **복사/붙여넣기 완료의 증명도 아니고 개별 원행의 식별 확정도 아님**. 기존 복사 목록에서 자동 제외·자동 삭제·자동 완료 처리하지 않는다. 별도 명시적 사용자 동작 없이는 복사 대상 변경 금지.

## 4. 계산·성능·안전

- 기존 Google snapshot/read-only authority API와 COST 지출 projection을 재사용. 그룹별 count 및 원행 ref만 인덱싱하여 `O(m+n)` 수준으로 상태 산정. 후보 관계는 필요한 상세 화면에서만 열람; `m×n` 물리적 DB 레코드나 감사 이벤트 대량 생성 금지.
- 그룹 키는 서버에서 실제 여행 매핑을 검증한 `trip_id`와 정확한 signed amount. 동일 금액·동일 여행이라도 **원본 행 ID/거래 ID는 각각 독립 유지**. 장부 행 이동/스냅샷 교체 시 다시 계산하며 이전 체크를 확정 상태로 캐시하지 않는다.
- 사용자 권한 범위 내 여행/Google 원본만 열람. API 응답에 다른 여행 거래나 비공개 시트 정보 노출 금지.
- 데이터 불일치 발견 시 표시만 한다. COST 지출, Google 시트, OTA/카드 매칭, 수동 귀속, 원본 지문, 환불 상태를 수정하지 않는다.

## 5. 구현 작업

1. **GEMN-01** 기존 여행 지출 projection·Google 정본 스냅샷·여행 매핑·Google 지출행 파서 조사. 수입과 지출 구분, Google 전용 이체 지출, 카드/영수증 증빙 중복을 명시적으로 확인.
2. **GEMN-02** 순수 함수 `reconcile_expense_amount_groups` 등으로 `trip_id + signed_amount` 그룹 계산과 상태 반환. 기존 분류/OTA 엔진에 매칭 로직 중복 삽입 금지.
3. **GEMN-03** 서버에서 기존 여행 지출 렌더링에 그룹 상태 projection 주입. Google 오류/오래된 캐시/매핑 불명확을 '0건'과 구분.
4. **GEMN-04** 900px PC 전용 열·그룹 상세·건수 차이 표시. 접근성·다크/라이트·데스크탑 좁은 창 테스트.
5. **GEMN-05** 합성 테스트 및 운영 읽기 전용 수락. 실자료 변경/Google 쓰기 없이 상태와 화면을 검증.

## 6. 필수 회귀 테스트

- 1:1, 3:3, 5:2, 2:0, 0:2; 3:3에서 정확히 9개의 논리적 후보 관계.
- 같은 금액의 유효한 반복 결제 모두 보존; 같은 원본의 중복 projection만 제거.
- 가맹점명 전혀 다름·축약·날짜 크게 다름에도 동일 여행·금액이면 동일 그룹.
- 여행 다름/금액 1원 차이/환불 부호 다름/통화 미확정이면 그룹 분리 또는 비교 불가.
- 수입 행·합계행·이체 지출·영수증 증빙·환불을 정확히 구분.
- Google 캐시 오류·미매핑·시트 변경 시 거짓 초록 체크 0건.
- 899px 숨김 / 900px 표시, 모바일 기존 UI와 Google B:H 복사 결과 불변.
- 조회/테스트 전후 Google 쓰기 0, 카드/OTA/참가자/분류/원본 금융 DB 변경 0.
