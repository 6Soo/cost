## 착수 전 결정과 독립 작업

운영비 기준은 무료 선행 시험·유료 전환 별도 승인으로 확정됐다. 공급자 후보의 실제 자원 확보와 운영 전환은 실행 단계에서 확인한다. Google 로그인과 직원 신청 후 소유자 승인은 확정됐으며, 실제 Gemini 무료 지원 모델·OAuth 자격 증명·예약 API는 연결 단계에서 확인한다. 결정 등록부의 확정 사항은 재질문하지 않는다. 초기 미착수 설명은 별도 작업자의 Phase 1~5 착수 지시 이후 현행 구현 상태가 아니다. 구현을 재개하는 작업자는 현재 결과와 구현 검토의 수정 묶음에서 이어가며 Phase 1부터 다시 만들지 않는다. 설계·검토 세션의 `계속`을 코드 구현이나 미정 정책 승인으로 바꾸지 않는다. 운영 계정·키·외부 배포를 임의 생성하지 않는다.

첫 단계 입력은 관련 `webapp` 조회·저장 코드, 기존 카드 정규화 인터페이스, UI 명세 4절, 구현·검증 계약의 담당 시나리오다. 완료 보고에는 바꾼 파일·동작·합성 검증 결과·남은 선택만 적는다. 새로운 계획 문서를 계속 생산하는 것으로 구현 완료를 대체하지 않는다.

## 사용자 확정 사항

- 웹앱이 기준 장부다. 구글 스프레드시트와 양방향 동기화하지 않는다.
- 사용자 한 명만 입력·수정한다. 로그인한 직원·가이드는 담당 여행만 조회하며 포트폴리오는 분리된 예시 데이터를 사용한다.
- PC가 꺼져도 웹앱·DB·카드 업로드·기존 규칙 실행은 상시 서버에서 계속된다. Muse 연결 불가 시 Gemini는 서버에서 호출한다.
- 수입은 기본적으로 입금 한 건마다 한 행이며 사용자가 분할한 입금은 배분별 행이다. 원천은 한 건으로 보존하고 원금·배분·고객별 요약을 중복 합산하지 않는다. 동명이인을 합치지 않는다.
- 사용자는 행 단위로 수정하고 저장한다.
- 왼쪽 세로 탭의 초기 이름은 날짜와 행선지 형식이며 표시 이름 전체를 자유롭게 바꿀 수 있다.
- 화면은 수입 위, 지출 아래다.
- 선택 탭의 현재 저장된 장부를 한 xlsx 파일의 여러 시트로 출력한다. 미저장 변경은 저장 후 출력하거나 돌아가게 하며, 전체 대사를 다시 실행하지 않는다.
- 수입은 직접 입력과 은행 입금 파일 업로드를 함께 지원한다. 중복 가져오기는 입금 사건을 늘리지 않고 직접 입력과 원천 연결 시에도 이중 합산하지 않는다.
- 직원·가이드의 담당 여행은 예약 시스템의 명시 가이드 배정을 연동한다. 제목의 닉네임이나 공유 링크 보유로 권한을 부여하지 않는다. 여행 종료 후에도 유효 담당자는 조회할 수 있으며 담당 해제·계정 비활성화 시 종료한다.
- xlsx 생성·출력 작업 조회·파일 다운로드는 owner만 허용한다. viewer에게는 화면 조회만 제공한다.
- viewer에게 고객 이름·닉네임·예약번호·해당 여행 증빙을 보여 주되 내부 메모·수정 이력·AI 대화와 원본 카드·은행 파일 전체는 서버에서도 반환하지 않는다.
- 현금·계좌이체 수기 지출을 추가하고 날짜·금액을 편집할 수 있다. 변경 이력을 보존하고 카드 금액 수정 경로와 분리한다.
- 모바일에서도 PC와 같은 입력·업로드·규칙 대화·출력을 지원한다. 모바일 화면이라는 이유로 역할별 권한을 바꾸지 않는다. 각 Phase에서 해당 기능의 작은 화면 동작도 검증한다.
- 카드 파일을 앱에 올린다.
- 카드 원천의 날짜·금액·부호·안정 식별자는 읽기 전용이다.
- 사용자가 수정할 수 있는 값은 여행 배정, 항목, 내용, 메모다.
- 자동분류된 여행 탭 행을 나중에 수정할 때도 `예외 사항`과 `규칙 변경`을 구분해 묻는다.
- 기존 파이프라인의 후보 결과까지 포함해, 대상이 선택된 행은 사용자 승인 없이 해당 여행 탭에 자동 삽입한다.
- 기본 장부에는 자동분류·후보 상태 배지·색상·열을 표시하지 않는다. DB와 행 상세에는 상태·근거를 보존한다.
- 분류에 실패한 행만 `분류대기` 탭에 보존한다.
- 사용자는 분류대기 행의 드롭다운으로 목적지 탭을 선택한다.
- 그 선택은 학습 사례와 변경 사건으로 저장한다. 모델 재훈련이라고 표현하지 않는다.
- 수정 후 규칙 변경을 선택하면 Muse는 상황별 1~5개 질문을 만들고 답변이 충분하면 멈춘다. 기본 조건은 정규화 가맹점·카드 종류·거래 방향이며 금액·기간은 필요할 때 추가한다.
- 기존 자동 배치는 승인 없이 진행한다. 사용자가 새로 만드는 규칙은 미리보기 후 기존 행과 미래 입력의 적용 범위를 각각 선택해 확정한다. Muse에게 직접 장부를 쓰는 권한은 없다.
- 사용자 수동 배정은 이후 규칙이 덮어쓰지 못하는 고정값이다.

Phase 0 명세, Phase 1 합성 화면, Phase 2 저장, Phase 3 카드, Phase 4 수입, Phase 5 출력, Phase 6 규칙 대화, Phase 7 권한, Phase 8 이관, Phase 9 운영 준비 순서다. 현재 코드의 수정 재개 위치·완료 판정은 `docs/WEB_LEDGER_IMPLEMENTATION_REVIEW.md` 6~7절을 우선 대조한다. 각 단계의 완료 증거와 실제 사용자 확인 여부를 남기며 후속 구현 지시가 허용한 진행 범위를 적용한다. 상세 계약의 W 번호는 기능 분할 번호이며 별도 실행 순서가 아니다.

## 핵심 동작 계약

### 카드 업로드

- 파일 전체 SHA-256과 파일 행의 안정 키를 저장한다.
- 원본 파일과 원본 셀 값은 절대 수정하지 않는다.
- 필수 열이 없는 행은 `가져오기 오류`로 보존한다.
- 기존 파이프라인이 선택한 후보 대상도 화면 배치에 사용한다. 내부 `auto_classified`와 원래 `proposed`·`held` 상태는 별도로 보존한다.
- 대상이 없거나 기존 선택 규칙 적용 후에도 목적지가 불명확한 행만 `분류대기`로 보낸다. 후보라는 이유만으로 보류하지 않는다.
- 화면의 `display_tab_id`는 검증된 회계 allocation과 구분한다. 후보의 화면 배치가 회계 확정이나 외부 전기 권한을 만들지 않는다.
- 같은 원천 파일과 행 키를 다시 올리면 중복 행을 만들지 않는다.
- 금액·날짜가 다른 같은 키는 충돌로 남긴다.

### 분류대기 탭

- 자동 분류에 실패한 미배정 행을 조회하고 검색·필터한다.
- 드롭다운은 권위 여행 탭과 `여행_미배정`을 제공한다.
- 이동은 복사가 아니라 화면 배정 변경 사건이다. 기존 payment ID를 유지하고 회계 allocation으로 자동 승격하지 않는다.
- 이동 뒤 원래 사건과 목적지 링크를 이력에 남긴다.

### 규칙 질문과 Muse

- 질문은 이번 행만 적용할지, 같은 조건에도 적용할지 확인한다.
- 정규화 가맹점·카드 종류·거래 방향은 확정된 기본 분류 조건이다. 거래 중복 판정 키로 사용하지 않는다.
- 금액·기간·항목 조건은 사용자가 추가로 선택한다.
- 기존 여행 탭과 분류대기를 포함한 영향 행을 미리 보여 주고 `apply_existing`과 `apply_future`를 독립적으로 선택한다. 미리보기의 영향 행 수·합계는 서버가 계산한다.
- 기존만 선택하면 선택한 행 revision에만 적용한다. 미래만 선택하면 새로 들어오는 거래부터 적용한다. 재업로드한 기존 거래는 새 거래가 아니다. 둘 다 선택하면 두 범위에 적용하며 둘 다 선택하지 않으면 초안만 저장한다.
- 특정 여행을 대상으로 한 규칙은 여행 ID·연도·적용 범위를 포함한다. 가맹점이 같다는 이유만으로 미래 거래를 과거 여행에 계속 보내지 않는다.
- 질문은 상황별 1~5개로 한정하고 이미 답한 내용을 반복하지 않는다. 정해진 다섯 문항을 매번 요구하지 않는다.
- `예외 사항`과 `규칙 변경`을 구분한다.
- 기본 모델 ID는 `opencode/muse-spark-1.3-contributor-free`다. 대화 보조에는 사용자가 명시적으로 요청한 Gemini fallback을 허용하며 전환 사실을 표시한다. 구현자 모델 자체는 바꾸지 않는다.
- 카드 원문 고객명·예약번호·메일 본문과 비밀값을 Muse에 보내지 않는다. 필요한 문맥은 가명·정규화·집계값으로 줄인다.
- Muse 응답은 규칙 초안 JSON으로 검증하고 장부 쓰기 권한을 주지 않는다.
- Muse가 실패하면 설정된 Gemini로 대화를 이어 간다. 둘 다 불가하면 AI 규칙 초안 생성만 대기하며 이번 행 저장과 이미 확정된 규칙 실행은 계속한다.
- Muse 연결이 명시된 실패 조건이면 사용자가 설정한 Gemini API key와 model ID로 한 번만 fallback한다. fallback은 규칙 대화 보조에만 적용하며 구현자 모델이나 비용 파이프라인을 바꾸지 않는다.
- fallback 사실, 실제 provider·model·사유 코드를 화면과 감사 기록에 남긴다. 다른 모델로 조용히 바꾸지 않는다.
- Muse와 Gemini 사이의 문맥은 provider 내부 ID가 아니라 앱의 conversation_id, 규칙 버전, 질문·답변, handoff summary로 이어 간다. 모델 가중치나 숨은 상태가 이전된다고 주장하지 않는다.
- owner의 AI 연결 설정에서 Gemini 키 등록·교체·삭제를 제공한다. 키는 웹앱 서버 비밀 저장소 또는 배포 환경 변수로 관리한다. 사용자 PC에만 저장하지 않는다. 브라우저 저장 공간·소스 저장소·로그에는 남기지 않는다.
- 같은 턴의 늦은 Muse 응답이 Gemini 응답을 덮어쓰지 않도록 attempt_id와 응답 채택 상태를 확인한다.
- Gemini는 `free_only` 정책으로 등록한 키의 설정과 무료 한도를 따른다. 무료 지원 모델과 프로젝트 등급을 확인하고, 연결 성공만으로 무료라고 판정하지 않는다. 한도 소진 시 대화만 대기하며 유료 전환·충전·다른 키로 우회하지 않는다. API 키만으로 공급자의 외부 결제 설정까지 통제한다고 주장하지 않는다.

### 편집과 감사

- 카드 거래일, 금액, 부호, 안정 원천 키는 수정 API 자체를 만들지 않는다.
- 카드 행의 수정 가능 필드는 여행 배정, 항목, 내용, 메모다. 직접 입력 수입은 날짜·금액 편집과 이력을 지원하며 은행 수입은 원천 고정·별도 정정 기록 계약을 적용한다.
- `expected_revision`과 `client_request_id`를 모든 저장에 요구한다.
- 삭제는 물리 삭제가 아니라 void 사건이다.
- 사용자가 직접 배정한 행은 수동 고정으로 규칙보다 우선한다.

- 실제 원본 DB·워크북·Google Drive 자료 덮어쓰기
- 외부 전기, 게시, 메일 발송, 배포
- 기존 정규화 엔진과 다른 새 식별자 체계 만들기
- 결제일·가맹점명·근사 금액만으로 여행을 확정하기
- 음수 취소·환불을 양수 구매로 바꾸기
- 규칙 대화만으로 자동 적용하기
- 조회자에게 쓰기 API를 노출하기
- 미정인 공개 범위를 임의로 확정하거나 운영 원본을 공개 배포하기

## 수용 테스트

- 카드 파일을 올리면 기존 규칙으로 분류된 행은 여행 탭에 들어가고, 실패한 행만 분류대기 탭에 들어간다.
- 미확정 후보도 대상이 선택되면 여행 탭에 바로 나타난다. 기본 표에는 후보·자동분류 표시가 없으며 행 상세에는 기존 상태와 근거가 남는다.
- 후보의 화면 배치로 release_eligible 또는 회계 확정 상태가 바뀌지 않는다.
- 파싱 오류 행은 별도 탭에 남고 원본 행 위치를 볼 수 있다.
- 같은 파일을 다시 올려도 행이 늘지 않는다.
- 분류대기 행을 드롭다운으로 이동하면 이력이 생긴다. 사용자가 규칙 변경을 선택한 경우에 학습 사례를 만들며 예외 사항·메모만 변경에는 규칙 대화를 강제하지 않는다.
- 규칙 질문을 건너뛰어도 행 이동은 저장된다.
- 규칙 미리보기 확인 전 다른 행이 바뀌지 않는다.
- 기존만·미래만·둘 다·둘 다 아님의 적용 범위가 구분된다. 미리보기 이후 수정된 행은 충돌로 처리하며 과거 미리보기로 덮어쓰지 않는다.
- 수동 고정 행은 새 규칙으로 바뀌지 않는다.
- 카드 날짜·금액을 바꾸는 요청은 거부된다.
- 선택한 탭만 `매출자료 양식_rev` 형식의 새 xlsx로 출력된다.
- xlsx의 행별 금액·부호와 앱의 값, A·B·회사수익인식 합계가 일치한다.
- 출력 실패 때 기존 출력이 변하지 않는다.
- 조회자는 담당 여행의 허용된 화면 조회만 가능하며 쓰기와 모든 xlsx 출력·다운로드 API는 서버에서 거부된다.
- 모든 조회 API는 담당 여행 범위를 적용하며, 다른 여행 ID와 전체 고객 합계 요청으로 우회할 수 없다.
- PC가 꺼진 상태에서 장부 저장·카드 업로드·Gemini 대화를 확인한다. 제공자 전환 전후 확정 규칙과 질문 답변이 보존된다.

## 결과 보고

구현 전에는 담당 작업에 필요한 미답변 정책만 확인한다. 위에서 확정한 자동 배치·상태 숨김·규칙 적용 범위·Google 로그인·계정 연결 승인을 재질문하지 않는다. 구현 후에는 변경 파일, 데이터 마이그레이션, 실제 모델 ID, 합성 테스트 결과, 미검증 원천, 외부 효과 실행 여부를 보고한다. 배포 공급자·비용·운영 전환은 별도 선택이며 Google 로그인 확정과 혼동하지 않는다. 보고 형식과 재개 위치는 구현 검토 7절을 따른다.
