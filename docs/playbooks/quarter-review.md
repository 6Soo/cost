# 분기 검수 자료 만들기

운영 서버를 재시작하거나 Google 장부에 쓰지 않고 검수용 파일을 만든다. 출력 폴더에는 고객 자료가 있으므로 Git 밖의 비공개 경로를 쓴다.

```powershell
python tools/quarter_review/pack.py --host-root D:/WebLedgerHost --year 2026 --quarter 3 --out D:/WebLedgerHost/data/backups/quarter-review-2026Q3/
```

1. 출력 폴더의 `notes.md`를 먼저 연다. 조회 시각, 수입을 읽지 못한 여행, 집계 범위와 한계를 확인한다.
2. `trips.csv`에서 여행별 수입·지출·차액을 본다. 수입이 확인되지 않으면 수입과 차액은 빈칸이다. 합계의 수입·차액도 일부 여행이 빈칸이면 빈칸이다.
3. `review-list.csv`를 위에서부터 보며 기존 장부 화면에서 판정을 교정한다. 순위는 오류 확정이 아니라 먼저 볼 순서다. 수동 교정은 합계에 포함하고 이 목록에서는 제외한다.
4. `quarter-other.csv`의 항목별 건수·합계와 `sources.csv`의 판정 주체별 건수·판정 없는 정상 거래 수를 확인한다. `review-pack.xlsx`가 있으면 같은 네 표를 한 파일로 볼 수 있다.
5. 교정 후 같은 명령을 다시 실행한다. 이 명령은 출력 파일을 갱신하므로 검수 중 적은 메모는 별도 파일에 보관한다. Google 지출표에는 기존 장부의 복사 기능을 이용해 사용자가 붙여넣는다. 검수용 CSV는 Google 지출표 자체의 양식이 아니다.
6. 고친 건수와 걸린 시간을 기록한다. 같은 원인의 교정을 묶어 [통합 명세 §8](../SPEC.md#8-분기-검수와-교정-환류)과 [규칙집 §7](../DECISION_POLICY.md#7-고치는-법)에 따라 규칙으로 환류한다. 고객 식별값은 규칙 사례에 넣지 않는다.

범위는 여행 시작일의 분기와 저장된 분기 기타비용 귀속이다. 2026년 6월 30일 출발 여행은 3분기다. 선결제도 그 여행에 포함하며, 환불은 원금액을 보존한 음수 행으로 함께 합산한다. 다른 분기 여행, 원본 충돌·중복·금액 오류는 합계에서 제외한다. 저장된 화면 행만 사용한 이용일 미확인은 실시간 화면의 메모리 근거와 다를 수 있다. 수동 판정 의심 사례와 닫힌 분기 귀속 의심 사례는 [규칙집 §6.3](../DECISION_POLICY.md#63-분기-검수-때-볼-것)의 기존 기록을 별도로 확인한다.

이번 2026년 3분기 최초 실행은 준비 비용 귀속 폐지 반영 전 수치다. 최초 실행에는 `--basis-note '이번 실행은 준비 비용 귀속 폐지 반영 전 수치입니다. 반영 후 다시 생성하세요.'`를 덧붙여 안내에 남긴다. 반영 후에는 이 옵션을 빼거나 새 기준을 적어 다시 생성한다. 자료를 만들었다는 사실만으로 실제 사용자 검수·Google 붙여넣기·교정 환류가 끝났다고 보지 않는다.
