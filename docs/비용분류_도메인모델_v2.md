# 비용분류 도메인 모델 v2

## 목적

`classified_v14.csv` 한 행에 결제 원천, 취소, 예약, 여행 귀속, 계정과목, 증빙,
신뢰도와 장부 상태가 함께 들어가면서 규칙 간 우선순위 충돌이 커졌다.
v2는 원천 사실과 판단을 분리해 각 축을 독립적으로 수정·검증할 수 있게 한다.

기존 v14/v76 파이프라인은 당분간 정본으로 유지한다. v2가 기존 건수·금액을
재현하고 분류 차이가 모두 설명될 때만 산출 경로를 전환한다.

## 도메인 경계

```text
source_document / source_record
                │
                ▼
payment_transaction ── transaction_relation
                │
                ├──── payment_booking_link ─── booking
                │                                │
                ▼                                ▼
classification_decision              booking_target_link
                │                                │
                └──── allocation_plan / cost_allocation ─────┘
                                  │
                                  ▼
                            journal_entry
```

### 원천

- `source_documents`, `source_records`
- 파일 해시와 원문 JSON을 불변으로 보존한다.
- 파서나 분류 규칙이 바뀌어도 입력을 재현할 수 있다.

### 결제

- `payment_methods`, `payment_transactions`
- 카드사가 제공한 날짜·가맹점·금액·승인번호만 저장한다.
- 여행, 계정과목, 신뢰도, 설명은 결제 테이블에 넣지 않는다.
- 취소·환불은 `transaction_relations`로 원거래와 연결한다.

### 예약·여행

- `bookings`, `payment_booking_links`, `trips`
- 결제와 예약은 다대다 관계다.
- 예약번호, 체크인·탑승 기간과 결제금액은 서로 다른 원천에서 올 수 있다.

### 배분 대상

- `allocation_targets`
- 여행만 대상이 아니다. `trip`, `overhead`, `leader`, `unassigned`,
  `clearing`을 같은 인터페이스로 표현한다.
- 기존 `bucket`은 이 테이블로 이관하지만 결제 사실에는 포함하지 않는다.

### 분류판정과 근거

- `classification_decisions`, `evidence`, `decision_evidence`
- 귀속, 비용성격, 계정, 세무판정을 서로 다른 `dimension`으로 저장한다.
- 판정은 덮어쓰지 않고 이전 판정을 `superseded`로 연결한다.
- 기존 v14 값은 정확성을 재보증하지 않으므로 `legacy` 상태로 이관한다.

### 비용 배분과 장부

- `allocation_plans`가 한 결제의 배분 버전을 관리하고, `cost_allocations`가
  그 plan 안에서 결제금액을 하나 이상의 대상·예약으로 나눈다.
- 활성 배분 합계는 반드시 결제금액과 일치해야 한다.
- `journal_entries`는 확정 배분을 소비하는 최종 출력이며 원천과 분리한다.

## 현재 이관 범위

`ledger/domain/ledger_db.py`는 다음 작업만 수행한다.

1. SQLite 스키마 초기화
2. `classified_v14.csv` 원문 스냅샷 보존
3. 결제 사실, 예약, 취소관계, 배분대상, 독립 판정으로 분해
4. 결제 건수·합계와 배분 건수·합계 검증
5. 분류 품질 검토 큐 출력

검토 리포트에서 `unassigned_*`는 현재 배분 대상이 실제로 `여행_미배정`인 전체이고,
`engine_isolated_*`는 v13 엔진이 생성한 `MISC-*` 집합이다. 후자는 생성 이후
취소환불 등 다른 대상으로 이동할 수 있어 두 수치는 같지 않을 수 있다.

현재 워크북 생성기는 v2 DB를 읽지 않는다. 산출물 전환은 다음 단계다.

## 실행

저장소 루트에서:

```bash
python3 ledger/domain/ledger_db.py import-legacy
python3 ledger/domain/ledger_db.py validate
python3 ledger/domain/ledger_db.py review-report
python3 -m unittest discover -s ledger/tests -p 'test_*.py'
```

기본 DB는 `ledger/data/ledger_v2.db`이며 Git에 포함하지 않는다.
다른 경로를 사용하려면 서브명령 앞에 `--db`를 지정한다.

```bash
python3 ledger/domain/ledger_db.py --db /tmp/ledger.db import-legacy
```

## 전환 게이트

다음 조건을 모두 충족하기 전에는 기존 산출 경로를 교체하지 않는다.

1. 원천 결제 건수와 정규화 결제 건수가 일치한다.
2. 결제 총액과 활성 배분 총액이 일치한다.
3. 모든 결제별 `결제금액 = 배분합계`가 성립한다.
4. 취소·환불의 원거래 미연결 건이 검토되었다.
5. 한 예약이 여러 배분 대상에 연결된 충돌이 검토되었다.
6. `상` 신뢰도이면서 근거가 `추정·유사·불명`인 판정이 해소되었다.
7. 기존 워크북과 여행별·계정별 차이가 전부 설명된다.
