# 카드 업로드 지연·연결 실패 수정

현재 사용자 요청: 작은 XLSX 업로드가 오래 걸리고 연결 실패로 표시되는 문제 해결.

- 목적/종료 조건: 긴 분류·OTA 갱신을 HTTP 응답 수명과 분리하고, 저장 여부와 검증 결과를 구분한다. 표적 보호 검사와 고정 SHA 운영 배포를 확인한다.
- 직접 영향: `/api/imports`의 명시적 `X-Upload-Async: 1` 요청과 카드 파일 추가 UI. 기존 동기 API를 유지한다. 새 스키마·서비스·과금은 없다.
- 원인: 파일 저장 후 분류·OTA 갱신·자동 기록·전수 검증을 한 요청에서 수행했다. 중간에 응답되지 않으면 화면은 저장된 파일도 연결 실패로 표시했다. 첨부 건의 특정 프록시 타임아웃 로그는 확보하지 않았으므로 단정하지 않는다.
- 구현: 검증·원본 접수·내구 큐 저장 후 202를 반환하고 기존 처리 순서를 단일 작성자 잠금 아래에서 이어간다. 인증된 소유자만 임의 토큰의 상태/결과를 조회한다. 상태 조회는 금융 DB를 읽지 않는다. 진행 단계·경과 시간·연결 재시도·저장된 파일 링크를 제공한다. 처리 중 새로고침은 DB 없는 업로드 UI를 응답한다. 새로고침 상태는 브라우저에 보존하며 서버 재시작 시 저장 파일 링크로 안내한다. 내구 분류 재개는 기존 활성화된 worker를 따른다.
- 성능: 사용하지 않던 중간 `state()` 조립 2회를 제거한다. 최종 화면·전수 검증은 유지한다. 총 분류/OTA 실행 시간이 사라진다는 의미가 아니며 운영 개선 배수는 미측정이다.
- 보호: 중복 파일의 원본/거래 재사용, 수동 교정, 환불 검증, OTA 갱신 전후 두 기록 경계, 원자 기록과 기존 실패 복구 큐를 유지한다. GET 상태 조회와 UI shell은 쓰기/원문 파싱이 없다. Google 최종 장부 쓰기는 없다.
- 검증: 느린 분류를 Event로 멈춘 HTTP 테스트에서 POST 202·진행 GET·새로고침 HTML이 작업 완료 전에 반환되는지 확인한다. 기존 금융/중복/환불/수동 배정 보호와 전수 대조 검사, 합성 UI 새로고침·완료·접수 후 오류·모바일 검사를 수행한다. 운영 배포 결과는 operations/session_handoff의 이번 항목을 따른다.
