# M5 클라우드 제공자 선택 자료 — 2026-11-17

제공자를 고르기 위한 조사 문서다. **제공자 확정·계정 생성·유료 계약·이전은 하지 않았다.** 조사 범위는 공개 법령·상품 자료와 지정된 설계·성능 계측 코드다. 고객 원문과 운영 DB는 열지 않았다. 아래의 ‘확인’은 공개 문서 확인이며 실제 계정의 설정·계약·서버 성능 검증을 뜻하지 않는다.

작성 기준: 2026-11-17, 작업 폴더 `C:/AX/cost-m5m6-20261117`, 열람 당시 HEAD `2df7e0ba`. 이번 산출물은 이 문서 하나이며 커밋하지 않는다. 제공자별 확정 견적이 없는 항목은 그대로 표시했다.

## 1. 무엇을 어디에서 실행하는가

클라우드의 작은 서버 한 대가 화면, API, 장부 DB, 원문 파일, 코드 판정(P1), 작업 대기열을 맡는다. 사무실 PC는 로그인해야 가져올 수 있는 자료 수집과 AI 판정(P2)을 맡는다. PC가 꺼져도 화면·업로드·P1은 작동하고 P2와 로그인 수집만 기다린다.

PC가 클라우드로 HTTPS 요청을 보내 일을 받아 온다. 클라우드가 PC에 접속할 터널이나 PC의 공개 주소는 필요 없다. 이 방식은 아래 모든 VM 후보에서 구성할 수 있다는 **설계 판단**이다. 후보별 실연결은 시험하지 않았다. 서버의 HTTPS 접속점은 필요하지만, PC의 인바운드 포트를 열 필요는 없다.

옮길 짐은 실행 파일, SQLite DB 파일, 원문 폴더다. 원문 폴더 대신 S3 호환 저장소를 선택할 수도 있다. DB는 VM의 영속 디스크에 두고 오브젝트 저장소를 실행 중인 SQLite 디스크로 쓰지 않는다. 매일 DB와 원문을 PC로 내려받아 백업한다. DB는 실행 중 파일을 무작정 복사하지 않고 일관된 백업본을 생성해야 한다. PC가 꺼진 날의 백업은 누락을 드러내고 복구 후 따라잡아야 한다.

GPU, 클라우드 상주 AI 모델, Kubernetes, 제공자 전용 서버리스 런타임은 현재 규모 산정의 전제가 아니다. 운영체제·CPU가 다르면 같은 프로그램의 해당 대상 빌드가 필요하다. Windows용 exe를 Linux나 ARM VM에 그대로 복사해 실행할 수 있다는 뜻은 아니다.

근거: [SPEC §11.3·§13·§14](../../SPEC.md), [M5 착수 설계 §2](../../design/m5m6-kickoff-20261117.md), [판정 규칙집](../../DECISION_POLICY.md). D11의 원문은 규칙집이 아니라 SPEC 부록 A에 있다. 제공자 비종속 개발과 제공자 확정·실제 이전은 서로 다른 게이트다.

## 2. SPEC §14 #10 — 개인정보 법률 요건

### 2.1 먼저 조항 번호를 바로잡는다

조사 지시문의 ‘제28조의8 국외 이전 중지 명령’ 표기는 정정이 필요하다. **제28조의8은 ‘개인정보의 국외 이전’, 제28조의9는 ‘개인정보의 국외 이전 중지 명령’**이다. 국가법령정보센터에서 확인한 본문은 시행 2026-09-11, 법률 제21445호다. [국가법령정보센터 해당 조문](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1020398611)

제28조의8 제1항은 국외 제공의 범위에 **“조회되는 경우를 포함한다”**고 명시한다. 같은 항 제1호의 허용 근거는 **“국외 이전에 관한 별도의 동의”**다. 같은 항 제3호는 정보주체와의 계약 체결·이행에 필요한 위탁·보관에 대해 처리방침 공개 또는 정해진 방식의 개별 알림을 둔다. 모든 국외 이전에 동의만 가능한 것도, 처리방침만 고치면 모두 가능한 것도 아니다. [제28조의8 제1항](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1020398611)

### 2.2 국내 저장에도 필요한 위탁 계약과 공개

제26조 제1항은 처리 위탁을 **“문서로 하여야 한다”**고 정한다. 제2항은 수탁자 범위에 **“다시 위탁받은 제3자를 포함”**한다. 보관·호스팅 위탁에도 목적 외 처리 금지, 보호조치 등을 계약에 담고, 업무 내용과 수탁자·재수탁자를 쉽게 확인하도록 공개해야 한다. 제4항의 관리·감독, 제5항의 위탁 범위 초과 이용 금지, 제6항의 재위탁 시 위탁자 동의도 적용된다. 여기서 제6항 동의의 주체는 고객 개인이 아니라 위탁자다. [국가법령정보센터 제26조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398923)

**일반적인 클라우드 저장 위탁 자체에 고객의 별도 동의를 일률적으로 요구하는 조항은 아니다.** 제26조 제3항은 홍보·판매 권유 업무 위탁에 별도 알림을 요구한다. 저장 업체가 자기 목적으로 데이터를 이용한다면 통상적인 위탁과 다른 검토가 필요하다. [제26조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398923)

계약에는 목적·범위, 재위탁 제한, 접근 제한, 점검, 위반 책임을 구체화한다. 위탁 내용·수탁자 공개는 원칙적으로 홈페이지에 계속 게재한다. 위탁 계약을 체결해도 기존 수집·이용의 적법 근거가 새로 생기는 것은 아니다. 이름과 예약·거래 정보의 수집 목적, 보유기간, 직원 권한은 기존 정책과 함께 확인해야 한다. [시행령 제28조](https://www.law.go.kr/lsLinkProc.do?chrClsCd=010202&datClsCd=010102&gubun=admRul&joNo=002800000&lsId=45570&lsNm=개인정보보호법시행령&mode=10), [법제처 위탁 설명](https://easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=2&cciNo=1&cnpClsNo=2&csmSeq=1257&popMenu=ov)

### 2.3 국내 리전과 국외 리전의 차이

| 실제 처리 형태 | 제공자 선택 전에 확인할 내용 |
| --- | --- |
| 국내 업체·국내 리전, 고객 개인정보의 저장·처리·조회가 국내에 한정 | 제26조 계약·공개·감독과 일반 안전조치. 국내 업체라는 이유만으로 해외 재위탁이 없다고 단정하지 않는다. |
| 해외 업체·한국 리전, 개인정보가 실제로 국내에만 머무름 | 본사 국적만으로 국외 이전이라고 단정하지 않는다. 다만 국내 저장 약정이 해외 조회·지원까지 막는지 별도로 확인한다. |
| 한국 리전에 저장하지만 해외 지원자·재수탁자가 고객 개인정보를 조회·처리 | 제28조의8의 ‘조회 포함’에 비추어 국외 이전 경로로 검토한다. 접근국가·수신자·목적·법적 근거가 필요하다. |
| 국외 VM·버킷·백업 또는 해외 복제 | 저장·위탁 자체가 국외 이전이다. 적법한 이전 근거와 공개/알림/동의 및 보호조치를 갖춘 뒤 이전한다. |

위 표는 법의 이전 정의를 이 아키텍처에 적용한 **해석**이다. 해외 본사의 접근 ‘가능성’과 실제로 허용·예정된 조회 경로를 구분해야 한다. 한국 리전 명칭만으로 국내 한정 처리를 입증할 수 없다. [개인정보보호위원회 국외 이전 설명](https://pipc.go.kr/np/default/page.do?mCode=D060040000)

예를 들어 AWS는 선택 리전의 저장 원칙을 설명하면서, 고객이 시작한 서비스 제공 또는 법적 명령 등에 따른 예외도 설명한다. Google의 DPA §10.1은 서비스별 위치 약정을 전제로 Google·재수탁자 시설이 있는 국가의 처리를 규정한다. 이는 해외 접근이 이번 구성에서 실제 발생한다는 증거가 아니라, **지역 저장 선택과 전체 처리 위치 약정이 다름을 확인하는 계약 근거**다. 국내 업체에도 같은 질문을 해야 한다. [AWS 데이터 프라이버시 FAQ](https://aws.amazon.com/compliance/data-privacy-faq/), [Google DPA §10·§11](https://cloud.google.com/terms/data-processing-addendum)

### 2.4 국외 이전을 선택할 때의 두 주요 경로

제28조의8 제1항은 별도 동의, 법률·조약 등의 특별 규정, 계약 체결·이행에 필요한 위탁·보관, 고시된 인증과 조치, 보호수준 동등성 인정의 다섯 근거를 둔다. COST에 어느 근거가 성립하는지는 아직 확정하지 않았다. ISMS-P 로고만으로 국외 이전 허용 근거가 자동 성립하지 않는다. [개인정보보호위원회 설명](https://pipc.go.kr/np/default/page.do?mCode=D060040000)

실무상 먼저 검토할 경로는 다음 둘이다.

- **별도 동의 경로:** 제28조의8 제2항의 다섯 묶음, 즉 개인정보 항목 / 국가·시기·방법 / 이전받는 자의 명칭·연락처 / 이용 목적·보유 및 이용 기간 / 거부 방법·절차·효과를 사전에 알린다. 제3항의 변경 시 알림·동의 요건도 검토한다.
- **계약 필요 위탁·보관 경로:** 제1항 제3호의 ‘정보주체와의 계약 체결·이행에 필요’ 요건을 먼저 입증하고 위 다섯 묶음을 처리방침에 공개하거나 정해진 방법으로 알린다. 사내 회계의 편의나 낮은 서버 가격만으로 해당 요건이 충족된다고 단정하지 않는다. 참가자·예약자·직원 등 정보주체별 계약 관계도 살핀다.

[제28조의8 제1~3항](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1020398611)

이전 근거와 동의에 따른 이전 내용의 처리방침 공개, 안전성 확보, 고충·분쟁 처리, 이전받는 자와 사전 협의한 보호조치의 계약 반영도 필요하다. 제3국 재이전에도 규정이 준용된다. [개인정보보호위원회 설명](https://pipc.go.kr/np/default/page.do?mCode=D060040000), [시행령 제29조의10](https://www.law.go.kr/LSW/lsInfoP.do?ancYnChk=0&chrClsCd=010202&efYd=20250701&lsiSeq=269291&urlMode=lsInfoP)

제28조의9 제1항은 위법한 이전 또는 보호 수준 부족에 따른 뚜렷한 피해 우려 등에 대해 중지 명령을 허용한다. 같은 조 제2항의 이의 제기는 명령을 받은 날부터 7일 이내다. 사전 고지를 대신하는 조항이 아니다. [제28조의9](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1020398611)

### 2.5 제공자에게 받아야 할 확인서의 범위

VM·디스크·원문 버킷뿐 아니라 스냅숏·백업·지원 첨부파일·로그에 개인정보가 들어갈 수 있다. 선택 후보에게 계약 법인, 저장국가, 원격 접근국가, 재수탁자와 재이전, 백업 위치, 접근 승인·감사, 반환·파기, 사고 통지와 점검 지원을 확인한다. 이를 위탁 계약과 처리방침에 대조해야 §14 #10을 닫을 수 있다. 암호화·최소 권한·HTTPS·비공개 버킷·복원 검사는 이 아키텍처의 보호조치 제안이다. 특정 인증 하나가 COST의 법 준수를 대신하지 않는다.

P2가 로컬 PC에서 실행되더라도 모델 제공자로 보내는 자료 흐름은 별도의 국외 이전 검토 대상일 수 있다. 이번 클라우드 저장 제공자 조사로 기존 P2 경로의 법적 근거까지 확인됐다고 보고하지 않는다.

## 3. 제공자 비교

### 3.1 비용을 읽는 방법

아직 실제 요청량·원문 용량을 측정하지 않았다. 비교용 **가정**은 Linux VM 1대(1~2 vCPU, RAM 2~4GB), 월 730시간, 영속 디스크 약 40GB, 원문 20GB, 별도 백업 보관 약 40GB, 월 인터넷 송신 100GB 이하다. 별도 GPU·관리형 DB·로드밸런서·NAT Gateway·유료 지원·Windows 라이선스는 포함하지 않는다. 부가세는 별도이며 달러를 현재 환율로 환산하지 않았다.

아래 ‘예산 범위’는 확정 견적이나 가격 보장이 아니다. CPU 버스트 제약, 디스크 성능, IP, 저장 버전, 다운로드, 스냅숏, API 요청 비용에 따라 달라진다. 특히 무료 체험·장기 약정·스팟·회수 가능한 무료 VM을 운영 비용의 전제로 삼지 않는다.

### 3.2 매일 백업하는 비용을 빠뜨리지 않는다

총액은 `VM + 영속 디스크 + 공개 IP + 원문 저장 + 백업 저장/스냅숏 + 저장소 API + 인터넷 송신 + 선택한 지원`이다. 무료 제공량은 어느 서비스에 적용되는지 나눠 계산한다. S3 계열 비용에는 저장·요청·전송 등이 따로 있고, Google 저장소도 저장·작업·네트워크를 분리한다. [AWS S3 가격 구조](https://aws.amazon.com/s3/pricing/), [Google Storage 가격 구조](https://cloud.google.com/storage/pricing)

예를 들어 DB 1GB와 원문 20GB를 **매일 전체** 내려받으면 월 약 `21×30=630GB`다. 원문은 첫 20GB만 받고 하루 1GB의 새 파일, DB 1GB를 매일 받는 가정이면 첫 달 약 `20+30×(1+1)=80GB`다. 둘 다 가상 계산이며 실측이 아니다. 원문 증분 백업은 과거 파일을 지우지 않고 무결성 확인과 누락 재시도를 갖춰야 한다. 기준 가정의 월 100GB를 넘으면 표의 예산 범위를 다시 계산한다.

SQLite DB 백업은 VM에서 내려받고 원문은 버킷에서 직접 내려받을 수 있으므로, 양쪽 송신량과 무료 구간을 분리한다. 계수기만으로 오브젝트 API 호출이나 백업 송신이 전부 잡히지는 않는다.

## 4. 경량 요청 계수기 설계 — 이번에는 구현·배포하지 않음

### 4.1 현재 확인된 한계

[`app/request_metrics.py`](../../../app/request_metrics.py)는 정해진 작업·단계의 소요 시간과 행/바이트 등을 모으는 성능 계측이다. `MetricsWindow`는 최근 표본을 제한된 개수만 보관한다. 그 표본 수를 전체 HTTP 요청 수나 월 요청량으로 해석하면 안 된다. [착수 설계 §2.4](../../design/m5m6-kickoff-20261117.md)는 접근 로그가 없음을 명시한다. 이번 조사에서는 코드의 전체 라우팅 경로나 운영 로그까지 추가 검증하지 않았다.

### 4.2 무엇을 셀 것인가

고객 내용 없이 **시간대별·고정 엔드포인트별 집계만** 보관한다. 제안 필드는 다음과 같다.

| 항목 | 기록 방식 |
| --- | --- |
| 시간 | UTC 한 시간 버킷, 화면에서 한국 시간으로 변환 |
| 엔드포인트 | 서버 코드에 정한 고정 ID. 경로의 거래번호·예약번호·사용자 값은 넣지 않음 |
| 메서드·결과 | 허용 목록의 HTTP 메서드와 상태 코드 등급(2xx·3xx·4xx·5xx). 기타는 고정 `other` |
| 요청 수 | 시작 건수와 완료·중단 건수. 예외·인증 실패·404도 빠뜨리지 않음 |
| 바이트 | 실제 읽은 요청 본문 바이트와 실제 내보낸 응답 본문 바이트의 합. 헤더 값은 저장하지 않음 |
| 계측 상태 | 가동 초, 재시작 횟수, 유실 가능 구간·집계 저장 실패 수. 원인 문자열은 기록하지 않음 |

원시 URL, 쿼리, IP, 쿠키, 인증값, 요청/응답 내용, 파일명, 사용자·여행·거래 ID, 해시 지문, 예외 문자열은 수집하지 않는다. 미등록 경로는 원문을 남기지 않고 `unknown` 하나로 묶는다. 외부 스캐너가 임의 경로를 보내도 집계 종류 수가 늘지 않게 제한한다. 재시작 구분 토큰을 쓰더라도 내부 중복 방지에만 쓰고 요청 단위 이력은 만들지 않는다.

### 4.3 붙이는 위치와 저장 방식

HTTP 처리가 실제로 끝나는 공통 경계 한 곳에 새 계수기를 둔다. 서버가 정한 라우트 ID만 받고 예외 경로에서도 한 번만 마감한다. 기존 `request_metrics`의 성능 표본·request ID·유지 개수는 바꾸지 않고 별도 이름공간을 사용한다. Python 전환기와 Rust 서버에도 같은 집계 형식을 적용할 수 있게 한다.

카운트는 메모리에서 짧은 잠금으로 더하고, 60초마다 전용 집계 파일에 누적값을 원자적으로 저장하는 안이다. 회계 DB에 테이블을 추가하지 않는다. 시간 버킷의 누적값을 덮어써 같은 값을 재시작 후 두 번 합산하지 않도록 하며, 프로세스가 여러 개면 각자 저장하고 집계 시 합친다. 비정상 종료 직전 최대 약 60초와 저장 실패 구간은 유실 가능성을 표시한다. ‘기록 없음’을 요청 0건으로 표시하지 않는다. 기록 실패가 고객 요청 실패로 이어지지 않게 한다.

본문 크기는 읽기·쓰기 경계에서 정수만 센다. 계측을 위해 본문을 더 읽거나 복사하거나 버퍼링하지 않는다. 스트리밍·HEAD·204·연결 중단을 구분한다. `Content-Length`만 합산하면 없는 헤더·중단·압축에서 부정확하다. 요청 본문을 일부만 읽고 거절한 경우 실제 네트워크 수신량과 다를 수 있다. 프록시가 정적 파일을 직접 제공하면 애플리케이션 계수기에 잡히지 않으므로 프록시에서도 같은 집계만 얻거나 누락 범위를 명시한다.

TLS·HTTP 헤더·재전송·프록시 압축·직접 버킷 다운로드는 앱 본문 바이트와 다르다. 앱 계측은 업무 요청 규모의 근거로 쓰고 **청구 네트워크 용량과 같다고 보고하지 않는다.** 백업 도구의 총 다운로드 바이트·원문/DB 전체 크기·저장 증가량·오브젝트 API 건수는 내용 없는 별도 집계로 보완한다.

### 4.4 언제, 어떻게 측정할 것인가

**현재 회계 TRIP099 관련 배포 보류가 있으므로 실제 계수기 배포·측정 시작은 감독의 보류 해제에 연동한다.** 이번 문서 작업은 보류 해제 근거가 아니다. 보류 사실은 이번 위임 지시 기준이며 운영 상태를 직접 조회하지 않았다. 착수 설계 첫머리의 과거 ‘보류 없음’보다 이번 지시를 따른다.

보류 해제 후 별도 구현 담당이 합성 요청으로 성공·404·인증 거절·예외·동시성·재시작·스트리밍·중단을 확인하고, 정상 요청 수를 독립 발생 건수와 대조한다. 민감한 URL·헤더·본문을 넣은 합성 입력으로 집계 파일에 그 값이 남지 않는지도 확인한다. 저장 지연·CPU·메모리 증가를 함께 측정한다. 이 검사들은 **제안이며 이번에 실행하지 않았다.**

정상 배포 후 최소 14일, 가능하면 한 달과 업로드·정산이 몰리는 기간을 포함한다. 가동 시간과 누락 구간을 함께 보고하고, 시간대별 건수, 최대 시간대, 본문 바이트, 파일 증가량, 백업 송신량으로 견적을 갱신한다. 14일 건수의 30일 환산은 계절·분기 편향을 표시한다. VM 메모리·CPU·디스크 여유도 함께 봐야 하며 HTTP 건수만으로 VM 크기를 확정하지 않는다.

## 5. 사용자가 고를 수 있는 방향

아래는 선택지의 의미를 설명한 것이며 제공자 선정 결과가 아니다.

| 중요하게 여기는 것 | 검토할 옵션 | 남은 근거 |
| --- | --- | --- |
| 국내 계약·한국어 지원과 개인정보 설명의 단순성 | NCP·kt·NHN·카카오의 국내 구성 | 재수탁·해외 지원 여부, 같은 조건의 민간 견적. 국내 기업도 자동 면제 아님 |
| 널리 쓰이는 VM/S3와 자료·도구의 풍부함 | AWS 서울, GCP 서울. Azure는 VM+원문 폴더 방식 | 저장 외 해외 처리, 정확한 서울 견적, S3 호환 제한 또는 폴더 백업 조건 |
| 작은 고정비와 단순한 운영 | AWS Lightsail, 카카오 소형 VM, OCI A1을 각각 비교 | 버스트 성능, 송신 포함 범위, OCI ARM 빌드·재고. 무료 서버 확보를 전제로 삼지 않음 |
| 국외 저장을 포함해 검토 | 해외 리전 견적은 필요 시 별도 준비 | 현재 국외 저장 가격 비교는 하지 않음. 법적 이전 근거·국가·수신자·고지/동의가 먼저 정리되어야 함 |

지금은 국내 저장 후보군을 좁힐 자료를 제공하는 단계다. 국내 저장과 해외 처리 경로가 계약상 확인되고 요청량이 측정된 뒤, 사용자가 제공자·월 예산·지역 범위를 결정한다. 그 전에는 실제 이전·과금을 실행하지 않는다.

## 6. 미해결 질문과 인계

1. 선택 후보가 고객 개인정보의 국내 저장뿐 아니라 해외 지원자 조회도 제한할 수 있는가? 계약 법인·재수탁자·접근국가·예외를 서면으로 받을 수 있는가?
2. 현재 개인정보 처리방침·위탁 고지·정보주체 계약이 어디까지 포괄하는가? 국외 처리에 제28조의8 제1항 제3호를 적용할 수 있는가, 별도 동의가 필요한가? 이번에는 고객 계약·원문을 열지 않아 미확정이다.
3. 기존 P2 모델 전달의 국외 이전 근거와 이번 저장 위탁 고지가 서로 빠짐없이 연결되는가? 클라우드 이전과 별도로 확인해야 한다.
4. 실제 DB·원문 크기, 일일 증가량, 월 요청 수·동시 접속·송신량은 얼마인가? 현재 데이터 없는 상태를 0으로 간주하지 않는다.
5. 로컬 PC가 꺼져 있는 기간에도 일일 백업 목표를 어떻게 충족할 것인가? 허용 가능한 데이터 손실 시간·복구 시간·백업 보관기간은 무엇인가? 매일 백업만으로 24시간 이내 복구가 입증되지는 않는다.
6. NCP·kt·NHN의 동일 조건 민간 견적과 GCP·Azure의 서울 SKU 견적을 확보해야 한다. 새 계정·과금 없이 공개 견적 또는 소유자가 가진 계약으로 확인할 수 있는가?
7. 최신 인증서의 서비스·리전·만료일 확인이 필요하다. 특히 NCP의 오래된 모바일 기간 표기, NHN 백서의 과거 취득 설명, Azure 상세 인증 조회 미확인을 보완한다.
8. 최종 서버 OS/CPU와 실행 파일 대상은 무엇인가? OCI ARM을 후보에 남기려면 별도 빌드·종속성 검증이 필요하다.

**이번 조사 완료:** 역할·보호·제공자 게이트 확인, 법 조항 검증과 국내/국외 차이, 후보 8개 비교, 계수기 설계 작성. **의도적 미실행:** 코드·운영 DB·설정·런타임 변경, 계수기 배포·실측, 고객 자료 조회, 계정·견적 신청·과금·클라우드 이전, 테스트·빌드·배포, 커밋·push·merge·PR. 문서만 바꿨으므로 운영 검사는 실행하지 않는다.

조사 자체의 차단 사항은 없다. 실제 선택·이전의 외부 의존성은 사용자 제공자 결정, 필요한 법적 근거·계약 확인, 실측과 확정 견적이다. 실제 측정은 TRIP099 배포 보류 해제와 계수기 구현·검증·공식 배포가 선행한다. 감독은 이 문서의 diff·출처·가정과 미확인 항목을 검수해 통합하고, 보류 해제 후 별도 계측 작업을 연결한다. 다른 상태 문서는 이번 단일 파일 작성 범위 때문에 수정하지 않았다.

공개 웹 조사 방식: `ego-browser` 스킬과 설치 사용법을 확인했다. Windows 사용법은 추가 UTF-8 `.mjs` 파일을 요구하지만 이번 위임은 문서 하나만 쓰도록 제한하므로, 추가 파일을 만들지 않는 공개 웹 검색·문서 조회 도구로 조사했다. 로그인·폼 제출·사용자 브라우저 세션 조작은 하지 않았다.
