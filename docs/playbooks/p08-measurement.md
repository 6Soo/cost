# P-08 목록 성능 측정

- 목적: 장부 목록 조회(구 `/board` vs 신 `/api/plush/ledger`)가 P-08 예산(주요 조작 p95 200ms, 네트워크 제외)을 만족하는지 재현 가능하게 판정한다.
- 실행 주체·주기: 프런티어 모델이 스크립트로 실행. 판정 근거 SHA나 장부 조회 코드가 바뀌면 다시 돈다.
- 개정: 2026-11-18 최초 측정(`d2debf38`) · 2026-11-19 새 기준(`d4bdff65`) 재측정·정본화. 코드 최적화는 포함하지 않는다.
- 상세 절차(파라미터 표·명령·실패 처리)는 레포 밖 절차서가 정본이다(아래 "정본").

## 판정 단위

- **L1(동등 산출물):** 두 경로가 **같은 첫 50행**을 내도록 맞춘 단위. 두 경로의 행 ID 집합이 일치(`same_ids=true`)할 때만 측정을 인정한다.
- **L2(참고 전용):** 레거시 `/board` 전체 문서 vs React 50행 페이지. 레거시에는 페이지 개념이 없어 두 경로가 **다른 일**을 한 것이므로 판정에 쓰지 않는다.
- 조건: 합성 자료(고정 시드) · 페이지 50 · 같은 정렬(`date,id` 내림차순) · 워음업 6회·30회·3반복 · in-process(네트워크·브라우저 제외).

## 판단 기준

| 조건 | 판정 |
| --- | --- |
| L1(또는 같은 필터)에서 두 경로 p95 모두 ≤200ms, `same_ids=true` | 통과 |
| 한 경로라도 p95 >200ms | 미달 — 원인을 프로파일로 남긴다 |
| `same_ids=false` | 측정 무효 — 정렬·페이지를 맞추고 다시 돈다 |

P-08 확정 규모는 **1,000행**이다. 5,000행은 참고이며 미달은 차단으로 보지 않되 원인은 남긴다.

## 실행

```powershell
python -I .local-archive/m4-p08-20261118/bench_p08.py --rows 1000 --rows 5000 --runs 30 --warmup 6
```

- 측정 SHA를 결과 옆에 반드시 적는다(스크립트는 HEAD를 결과에 넣지 않는다).
- 네트워크·브라우저·운영 포트(8751/8752/8790)·운영 DB·`D:/WebLedgerHost`를 쓰지 않는다.

## 정본
