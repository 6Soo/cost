# 카드 자동처리 누락 재발 방지 — 2026-11-01

현재 사용자 지시: “해당 문제 자체를 재발안하도록 수정해”. 이전 PR453의 소유자 자동 기록 요청 시 복구만으로는 업로드 중단·프로세스 종료 뒤 사용자 재시도를 없애지 못했다.

## 실행 범위

- 원본 접수 직후 기존 `requests` 테이블의 전용 `card_completion_job` scope에 처리할 거래 ID를 저장한다. 새 스키마는 만들지 않는다. 기본 분류 완료 뒤 기록 전에 종료돼도 이 작업으로 재개한다. 접수 직후 작업 저장 전에 종료되면 기존 미분류 원행에서 다시 찾는다.
- 서버 시작 때 활성화된 단일 작업자가 실행되고, 업로드가 깨우며 평상시30초 간격으로 확인한다. 실제 미분류 정상 구매와 저장된 작업 ID만 대상으로 한다. 과거에 이미 분류 완료된 미기록 내역 전체를 재처리하지 않는다.
- 한 번에 최대50건을 현재 정책으로 분류·기록한다. 요청과 같은 runtime/store 잠금 순서를 지키고 서버/DB 종료 전에 멈춘다. 실패는5초부터 최대300초까지 간격을 늘리고 다른 거래 처리를 계속한다. 정책/권위 자료 때문에 남은 거래는 입력이 바뀌거나300초 뒤 다시 평가한다.
- 분류 완료 뒤 기록 전에 중단된 작업은 저장된 항목·배정·근거를 유지하고 기록만 재개한다. 배정이 실제로 비어 있는 일반 분류만 마지막 추론 단계로 보완하며, 가이드 항공권의 강한 근거와 현재 쓰기 권위 검사는 약한 분류로 대체하지 않는다.
- 분류·미리보기·기록은 같은 게시된 OTA 스냅샷만 사용한다. 잠금 안에서 원문 전체 파싱·네트워크 대사를 실행하지 않는다. 현재 정책의 약한 추론과3820 예외를 유지한다. 현재 범위 밖 거래와 환불 묶음은 자동으로 확장해 기록하지 않는다.
- 수동 결정/override·기기록·중복/원본 충돌·명시 보류/회사 제외·취소/환불 및 원승인번호 환불이 있는 구매를 보호한다. Google 최종 장부/원본/인증/금융 링크 쓰기는 없다.
- GET이 작업을 만들거나 수행하지 않는다. 후속 처리503은 활성 작업자가 있으면 자동 재시도 예약을 표시하고 재업로드를 요구하지 않는다. 작업자 미활성 상태에서는 기존 재시도 안내를 유지한다. 성공하지 않은 요청을 성공으로 응답하지 않는다.

## 활성화와 검증

운영의 `config/card-flow.json`에서 `automatic_card_completion: true`로 명시 활성화한다. 기존 `--no-worker`는 구형 카드 가져오기 작업자용이며 이 별도 활성화를 대신하지 않는다. 설정이 없는 합성 환경은 `WEBLEDGER_CARD_COMPLETION=1`을 사용할 수 있다. 실제 호스트 설정이 환경변수보다 우선한다.

일반 코드 배포는 미활성 상태로 검증하고, 데이터 실행은 원본·수동·링크·기존 장부 보존을 검증한 운영 사본 리허설과 백업/복원 게이트 후 별도 활성화한다. 작업 상태 파일 `data/card-completion-status.json`에는 집계와 오류 종류만 기록한다. 작업 ID와 원문은 외부 보고에 넣지 않는다.

수락 조건: 사용자 요청 없는 복구, 기본 분류 후 중단/재시작 재개, 일시 실패 재시도·범위 제한·중복 없음, 근거 갱신 시 재평가, 보호/원자성/생명주기 검사, 검증 SHA 운영 배포와 실제 자동 실행·보호 상태 확인. 완료 근거는 [현재 상태](../../session_handoff.md)와 [운영 기록](../../operations.md)에 기록한다.
